# 本周范围

- 时间窗口：2026-05-04 ~ 2026-05-10
- 覆盖日报：2026-05-04 至 2026-05-10 各期

# 趋势卡片

- Agent 工程从“能不能调用工具”继续推进到 runtime、权限、记忆、checkpoint、浏览器/桌面接入和安全审计的系统设计。
- 评测正在变成生产基础设施：从 ProgramBench、OBLIQ-Bench、Terminal-Bench 到 ByteByteGo 的 eval recipe，团队开始把 grader、任务数据和失败复现当成工程资产。
- 模型前沿的重点同时落在低激活 MoE、实时语音、多模态医疗与训练效率，说明模型竞争已经从聊天能力扩展到场景化部署能力。
- 企业 RAG 与数据 Agent 的瓶颈更清楚地落在检索召回、业务语义、资产发现、权限和可验证答案，而不是单纯向量库选型。
- AI 商业化进入基础设施阶段：算力合作、用量计费、健康入口、政府合同和组织重组共同说明 AI 已经不只是应用功能，而是企业运行成本和风险结构的一部分。

## 模型发布与系统

### GPT-Realtime-2 把 GPT-5 级推理能力放进实时语音 Agent
- **发布日期**：2026-05-08
- **主题**：模型发布与系统
- **链接**：[OpenAI 实时语音模型发布](https://openai.com/index/advancing-voice-intelligence-with-new-models-in-the-api/)
- **摘要**：GPT-Realtime-2、GPT-Realtime-Translate 与 GPT-Realtime-Whisper 将实时语音、流式转写、翻译和工具调用放进同一条 API 路线。128K context 与 Big Bench Audio 96.6% 的信号说明，语音 Agent 正在从“对话接口”进入可以边听边推理、边调用工具的生产系统。

### EMO 与 ZAYA 系列显示 MoE 竞争正在转向低激活成本
- **发布日期**：2026-05-08
- **主题**：模型发布与系统
- **链接**：[EMO on Hugging Face](https://huggingface.co/blog/allenai/emo)
- **摘要**：Ai2 EMO 用文档级弱监督让专家模块自发形成，ZAYA1-74B / ZAYA1-VL-8B 则继续压低 active parameter。二者共同说明开放模型竞争不再只看总参数，而是看能否在高并发、本地部署和多模态场景里保持更低推理成本。

### OncoAgent 把 Corrective RAG、双层模型和 HITL 放进肿瘤决策支持
- **发布日期**：2026-05-09
- **主题**：模型发布与系统
- **链接**：[OncoAgent on Hugging Face](https://huggingface.co/blog/lablab-ai-amd-developer-hackathon/oncoagent-official-paper)
- **摘要**：OncoAgent 使用 8 节点 LangGraph、四阶段 Corrective RAG、三层 Reflexion safety validator 和强制 HITL gate 做肿瘤临床决策支持。它把本地部署、Zero-PHI、指南级可追溯和模型路由组合起来，是医疗 Agent 从 demo 走向受监管流程的代表信号。

## 架构与工程范式

### Claude Code vs. OpenClaw 把 Agent runtime 差异讲清楚了
- **发布日期**：2026-05-09
- **主题**：架构与工程范式
- **链接**：[ByteByteGo: Claude Code vs. OpenClaw](https://blog.bytebytego.com/p/ep214-claude-code-vs-openclaw-5-design)
- **摘要**：ByteByteGo 从 scope、runtime、extension、memory、routing 五个维度比较 Claude Code 与 OpenClaw。Claude Code 更像短生命周期任务进程，OpenClaw 则是常驻 daemon + gateway + queue，这个对比把 coding agent 的核心差异从模型强弱拉回运行时、队列、记忆边界和插件注册表。

### Firefox 的 agentic security harness 让模型审计进入漏洞生命周期
- **发布日期**：2026-05-08
- **主题**：架构与工程范式
- **链接**：[Mozilla Hacks: hardening Firefox](https://hacks.mozilla.org/2026/05/behind-the-scenes-hardening-firefox/)
- **摘要**：Mozilla 没有把模型报告直接丢给维护者，而是让 harness 生成可复现测试用例，再接入去重、分派、修复和发布流程。Firefox 150 相关工作中有 271 个由模型识别的 bug，说明安全 Agent 的价值来自“可复现 + 可融入流程”，而不是一次性扫描分数。

### vLLM + Mooncake 与 OpenAI MRC 共同把 AI 基础设施推到协议层
- **发布日期**：2026-05-08
- **主题**：架构与工程范式
- **链接**：[Mooncake on arXiv](https://arxiv.org/abs/2407.00079)
- **摘要**：vLLM + Mooncake 把 Agent 前缀缓存命中率推到 92%，OpenAI MRC 则把大规模训练网络的失效恢复做成协议层能力。它们共同说明 AI Infra 的竞争已经进入缓存、网络恢复、prefill/decode 分离和硬件拓扑级优化。

### 企业数据 Agent 的核心难题是资产发现、业务语义和验证闭环
- **发布日期**：2026-05-09
- **主题**：架构与工程范式
- **链接**：[Latent Space: AI News](https://www.latent.space/p/ainews-anthropic-growing-10xyear)
- **摘要**：Databricks Genie 的实践把企业数据 Agent 的瓶颈拆成资产发现、冲突业务语境、无确定性测试和多模型协作。企业 Agent 的真实难点往往不是“模型会不会 SQL”，而是能否找到正确数据、理解组织口径并给出可验证答案。

## 工具链 & 仓库

### ProgramBench 把完整软件重建变成 AI Coding Agent 新考题
- **发布日期**：2026-05-10
- **主题**：工具链与仓库
- **链接**：[ProgramBench 解读](https://lukefan.com/2026/05/10/programbench-ai-software-reconstruction-benchmark/)
- **摘要**：ProgramBench 给模型可执行文件和使用文档，要求它探索行为并重建完整程序。9 个模型在 200 个真实软件、248,853 个测试项上没有一个软件全量通过，说明下一轮 Coding Agent 竞争会集中到长期规划、行为探索、自动测试、记忆和工具链协作。

### CrewAI checkpointing 把长链路 Flow 变成可恢复、可分叉状态
- **发布日期**：2026-05-08
- **主题**：工具链与仓库
- **链接**：[Daily Dose of Data Science](https://blog.dailydoseofds.com/p/a-smarter-claude-model-burns-more)
- **摘要**：CrewAI v1.14 将 Flow 中每个方法都变成可保存 checkpoint，并允许从任意保存状态恢复或分叉。对长链路 Agent 来说，checkpoint 不再只是调试工具，而是人机协作、失败恢复和实验分支管理的基础设施。

### CyberSecQwen-4B 展示安全小模型的可部署路线
- **发布日期**：2026-05-08
- **主题**：工具链与仓库
- **链接**：[CyberSecQwen-4B on Hugging Face](https://huggingface.co/blog/lablab-ai-amd-developer-hackathon/cybersecqwen-4b)
- **摘要**：CyberSecQwen-4B 面向 CWE 分类、CVE-to-CWE 映射和 CTI 问答，并能在 12GB 级 GPU 上本地运行。它给出 LoRA、ROCm、vLLM serving 和 transformers 推理示例，是防御安全小模型从研究基线进入可部署工具链的好样本。

### Spotify Save to Spotify CLI 让 Agent 输出进入用户已有音频分发系统
- **发布日期**：2026-05-07
- **主题**：工具链与仓库
- **链接**：[Spotify Personal Podcasts](https://newsroom.spotify.com/2026-05-07/personal-podcasts-launch/)
- **摘要**：Spotify 的 Save to Spotify beta tool 让桌面 Agent 可以把日程简报、学习路线或课堂笔记生成 Personal Podcast 并保存到用户 Library。它的价值不是单纯生成音频文件，而是让 Agent 输出进入跨设备播放、收藏和分发系统。

## 研究 & 方法论

### Direct Corpus Interaction 重新挑战“默认向量库”的 RAG 范式
- **发布日期**：2026-05-09
- **主题**：研究与方法论
- **链接**：[Latent Space: AI News](https://www.latent.space/p/ainews-anthropic-growing-10xyear)
- **摘要**：Direct Corpus Interaction 主张让模型用 grep、find、bash 等工具直接访问原始语料，而不是把所有内容都塞进 embedding + top-k 管线。它提醒我们，RAG 不一定只有向量检索一种形态，真实系统可能需要向量、稀疏检索、文件系统工具和代码式访问共同工作。

### Benchmark 设计开始关注“任务是否完整”和“软件是否可重建”
- **发布日期**：2026-05-05
- **主题**：研究与方法论
- **链接**：[Meta FAIR Autodata](https://ai.meta.com/research/publications/autodata-automated-data-engineering-for-ai-research/)
- **摘要**：本周的 OBLIQ-Bench、Terminal-Bench 2.1、Harvey LAB 和 ProgramBench 都在把评测从单题准确率推向更真实的任务结构。新的问题是：模型是否知道任务条件不完整，是否能探索黑箱行为，是否能生成测试并持续修正，而不是一次输出一个看似正确的答案。

### Open ASR Leaderboard 把私有测试集引入语音识别评测
- **发布日期**：2026-05-07
- **主题**：研究与方法论
- **链接**：[Open ASR Leaderboard](https://huggingface.co/spaces/hf-audio/open_asr_leaderboard)
- **摘要**：Open ASR Leaderboard 加入私有数据集来降低 benchmark 被过拟合和刷榜的风险。这个动作对所有生成式 AI 评测都有启发：当模型和数据泄漏越来越难区分，评测基础设施本身也必须引入隐藏集、复测机制和任务级解释。
