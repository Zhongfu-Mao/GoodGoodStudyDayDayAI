# 今週の結論

- 今週もっとも明確だった主線は、Agent 設計が prompt engineering から harness、memory、authority、evaluation、recovery へと外へ広がったことだった。
- Claude Mythos / Project Glasswing によって、「gate 付き frontier model」という形が初めて明確に舞台へ上がった。
- open model、OCR tool、post-training framework、structured extraction tool が同時に加速し、AI tool 層が本当に workflow に入ってきた。

*代表画像は [The Anatomy of an Agent Harness](https://blog.dailydoseofds.com/p/the-anatomy-of-an-agent-harness) から選定。4 月第 2 週でもっとも重要だったのは、prompt そのものより、Agent の runtime 構造を具体的に議論し始めたことだった。*

## 1. Agent システムは「runtime 設計」の段階に入った

- **[The Anatomy of an Agent Harness](https://blog.dailydoseofds.com/p/the-anatomy-of-an-agent-harness)**、**[Extreme Harness Engineering](https://www.latent.space/p/harness-eng)**、**[Advisor Strategy in Agents](https://blog.dailydoseofds.com/p/advisor-strategy-in-agents)**、**[Build Agents That Don't Fail in Production](https://blog.dailydoseofds.com/p/build-agents-that-dont-fail-in-production)** を並べると、すでに Agent の主要レイヤーはかなりはっきりしている。
- 今週覚えておくべきなのは、「ある Agent が賢い」という話ではなく、tool call、context assembly、workspace isolation、failure recovery、persistent memory、authority boundary へ問題が分解され始めたことだ。
- これは今後設計すべき対象が prompt だけではなく、runtime、approval、state、eval pipeline に移ることを意味している。

## 2. トップ model は「公開版」と「gate 付き frontier 版」に分かれ始めた

- **[Anthropic @ $30B ARR, Project GlassWing and Claude Mythos Preview](https://www.latent.space/p/ainews-anthropic-30b-arr-project)** は、この週でもっとも重要な model 側の signal だった。Claude Mythos は単なる性能ニュースではなく、トップ lab が「公開する能力」と「限定的にだけ解放する能力」を本気で分け始めたことを示している。
- **[Project Glasswing](https://www.anthropic.com/project/glasswing)** の物語も、model release が cybersecurity、提携先の選別、責任境界と一体化していることを示している。
- 同時に **Muse Spark**、**Gemma 4**、**GLM-5.1 / Qwen 3.6-Plus** の signal があり、frontier も open side も急速に伸びている。ただし release のされ方はますます非対称になっている。

## 3. open model 競争は「点数」から「完全な能力パッケージ」へ移った

- **[Gemma 4: The Best Small Multimodal Open Models](https://www.latent.space/p/ainews-gemma-4-the-best-small-multimodal)** が示すのは、open model の競争軸が parameter 数や単一 leaderboard から、多モーダル、長文脈、structured output、on-device deployment を含む総合力へ移ったことだ。
- **[A Visual Guide to Attention Variants in Modern LLMs](https://magazine.sebastianraschka.com/p/visual-attention-variants)** や **[The Anatomy of Diffusion LLMs](https://blog.dailydoseofds.com/p/the-anatomy-of-diffusion-llms)** は、2026 年の architecture 変化が「もっと大きい」ではなく、「もっと多様な設計空間」になっていることを思い出させる。
- つまりこの週の open side が投げかけた本当の問いは、「次の良い model とは何か。高スコアか、それとも完全な engineering capability package か」という点だった。

## 4. OCR、post-training、evaluation が最初に成熟し始めた tool 層になった

- **[Using OCR models with llama.cpp](https://huggingface.co/blog/ggml-org/using-ocr-models-with-llama-cpp)**、**[How we OCR'ed 30,000 papers using Codex, open OCR models and Jobs](https://huggingface.co/blog/nielsr/ocr-papers-jobs)**、**[Building Harvey-style tabular review from scratch, but better](https://huggingface.co/blog/isaacus/tabular-review)** は、document understanding と structured extraction が最初に大規模導入される能力候補であることを示した。
- 同時に **TRL v1.0**、**Transformers v5**、**Six Key Metrics for AI Agent Evaluation** は、「model が強い」と「それを安定評価・微調整・業務投入できる」は別問題だと明確にした。
- この週の tool 層が model 層より「現場寄り」に見えたのは、それらが現実 workflow にもっとも近いからだった。

## 5. product 入口争いが表面化し始めた

- **Perplexity の Agent pivot**、**Hermes / OpenClaw 比較**、**Claude for Word / office 入口**、**OpenAI superapp ambitions** はすべて、「次の AI operating system 入口はどこか」という同じ問いに向かっている。
- この週にはすでに、office 入口、search 入口、personal harness、agentic IDE という複数方向が同時に見えていた。
- product 観点では、これは一回の leaderboard 変動よりずっと重要だ。ユーザーが「どこで AI を使うか」を決めるからである。

## 今週引き続き追うべきこと

- Harness Engineering が少数の engineering 記事の用語から、業界共通語へ進むか。
- gate 付き frontier model が Anthropic、OpenAI、Meta などの標準 release 方式になるか。
- OCR、local multimodal、structured extraction が第一波の大規模 AI tool 能力になるか。
