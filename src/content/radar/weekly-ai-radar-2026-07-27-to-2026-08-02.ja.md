# 今週の範囲

- 対象期間：2026-07-27 ~ 2026-08-02
- 対象日報：2026-07-27 から 2026-08-02

# トレンドカード

- AI engineering の競争は「結果を生成する」ことから「結果を納品できると証明する」ことへ移った。inference service、code migration、real-device test、benchmark、formal proof、trace sampling は、environment、evidence、stop condition、rollback path を要求する。
- Agent control plane が独立した infrastructure になりつつある。approval、network isolation、idempotent tool、shared state、identity、event log、model-independent harness、browser debugging surface が、安全な recovery と audit を左右する。
- モデル競争は capability、cost、specialization の 3 軸に入った。GPT-5.6 の full-stack efficiency、Kimi K3、DeepSeek V4-Flash、Inkling-Small、specialized cyber model、orchestrator / executor routing は、model selection を system-level scheduling problem に変えている。
- AI は現実の action を動かし始めた。search は calendar、inventory call、ticketing と接続し、robot は継続観察して協働する。finance、court、insurance、academic research でも agent 導入が進み、consent、provenance、human confirmation、reversibility が default constraint になる。
- Knowledge と workflow は installable asset に変わる。book-to-skill、k-skill、ECC、OpenWork、docbank、AI-For-Beginners は、routable knowledge、local fact store、regional service、organizational capability の productization を示している。

## 検証、control plane、production 化

### Inference platform と大規模 migration が version、budget、verification loop を明示する

- **発表日**：2026-07-27 から 2026-07-30
- **テーマ**：LLM serving、code migration、harness optimization、benchmark
- **リンク**：https://netflixtechblog.com/in-house-llm-serving-at-netflix-a5a8e799ea2c
- **要約**：Netflix の vLLM / Triton platform は version coupling、model cache、zero-downtime upgrade、metric fragmentation など production 固有の問題を示した。Anthropic の million-line migration は compiler、test、behavior diff、shared rule を継続的な judge にする。ChatGPT agent loop と ARC-AGI-3 も、結果が model、API、harness、budget の共同設計で決まることを示す。environment version、success condition、cost ceiling、rollback strategy を runtime に組み込む必要がある。

### Trace sampling、real device、frontend quality evaluation が「test pass 後」の evidence を補う

- **発表日**：2026-07-27 から 2026-08-02
- **テーマ**：Behavioral traces、device verification、React quality、human review
- **リンク**：https://github.com/millionco/reactbench
- **要約**：ReactBench は hidden behavior test に加えて performance、effect、accessibility、maintainability を検査する。agent-device は real app 上で inspect-act-verify を実行し、behavioral signal sampling は production trajectory から human review に値する failure を選ぶ。evaluation は単一 pass rate から、product quality、real environment、高信号 failure discovery へ広がっている。

### Permission、network、idempotency、model-independent harness が安全基盤になる

- **発表日**：2026-07-28 から 2026-08-01
- **テーマ**：Approval gates、network isolation、idempotency、portable harness
- **リンク**：https://github.com/different-ai/openwork
- **要約**：OpenWorker、OpenWork、Codex Security CLI、Cyber eval の public-network exposure、agent tool idempotency は同じ基盤を示す。side effect は approval を通し、authorization scope と network profile は検証可能で、retry は安全で、execution evidence は保存できなければならない。vendor policy が変わっても、auditable で replaceable な harness が defense team の選択肢を守る。

## モデル効率、評価、task specialization

### Full-stack efficiency と small-active model が price advantage を engineering coordination に変える

- **発表日**：2026-07-29 から 2026-08-01
- **テーマ**：GPT-5.6、Kimi K3、DeepSeek V4-Flash、Inkling-Small
- **リンク**：https://www.latent.space/p/ainews-gpt-56-price-cut-by-20-80
- **要約**：GPT-5.6 の値下げと serving self-optimization は、cost が model、kernel、cache、scheduler、hardware の協調で決まることを示す。Kimi K3 は open-weight multimodal agent を大規模化し、DeepSeek V4-Flash と Inkling-Small は post-training、distillation、adjustable thinking effort により、小さい active footprint で新しい Pareto frontier を狙う。task success、latency、VRAM、context、review cost を同じ比較表に置く必要がある。

### Specialized model、orchestrator、executor が routing を default architecture にする

- **発表日**：2026-07-29 から 2026-08-02
- **テーマ**：Model specialization、cyber routing、multi-model orchestration
- **リンク**：https://every.to/context-window/fable-as-ceo
- **要約**：MAI-Cyber-1-Flash は routine security task を specialized model で処理し、難題をより強い model に route する。Every は CEO、senior engineer、analyst の比喩で orchestrator / executor の分業を説明した。分業は cost と throughput を改善するが、handoff loss、unreadable shorthand、responsibility drift も増やすため、trace、task contract、人間が読める最終 report は不可欠である。

### Astra、HAWK、automatic optimization が evaluator を discovery と training loop に接続する

- **発表日**：2026-07-30 から 2026-08-02
- **テーマ**：Formal verification、scientific discovery、automated optimization
- **リンク**：https://openai.com/index/ten-advances-in-mathematics
- **要約**：Astra の数学結果は Lean certificate で model discovery と formal verification を接続した。Claude Mythos Preview の cryptanalysis は domain expert review を必要とし、OPRO、TextGrad、GEPA、AutoResearch は evaluator で prompt、trace、code、training experiment を反復改善する。automatic optimization の前提は iteration 数ではなく、stable metric、isolated environment、stop condition、replayable evidence である。

## Toolchain、knowledge asset、GitHub trend

### Knowledge、skill、organizational capability が routable asset に変わる

- **発表日**：2026-07-27 から 2026-08-02
- **テーマ**：Local knowledge、skills、MCP、curriculum
- **リンク**：https://github.com/virgiliojr94/book-to-skill
- **要約**：book-to-skill は長い文書を on-demand skill に分割し、k-skill は韓国の交通、行政、生活 service を地域 data source に接続する。docbank は stable identity と hash で local fact store を維持し、ECC と OpenWork は engineering workflow と organizational capability を harness 間で再利用可能にする。AI-For-Beginners は lab と multilingual maintenance を備えた共通知識基盤を提供する。executable knowledge には source、version、permission、update path が必要である。

### Browser、voice、video、device interface が agent の検証可能な work surface を広げる

- **発表日**：2026-07-28 から 2026-07-31
- **テーマ**：Browser debugging、voice、video understanding、device control
- **リンク**：https://github.com/ChromeDevTools/chrome-devtools-mcp
- **要約**：Chrome DevTools MCP は coding agent に real-browser debugging surface を与え、claude-video は subtitle、scene frame、timestamp で video context を補う。speech-to-speech と voice workflow は発話から実行までの摩擦を下げ、agent-device は mobile / desktop app まで verification を広げる。interface が user environment に近づくほど、recording retention、login state、sensitive-action approval、final confirmation を明示する必要がある。

## 産業採用と governance boundary

### Enterprise adoption は license activation から governance、accountability、measurable outcome へ進む

- **発表日**：2026-07-28 から 2026-08-02
- **テーマ**：Enterprise adoption、research、simulation、work redesign
- **リンク**：https://openai.com/index/unive
- **要約**：Univé は management training、permission inheritance、privacy assessment、human accountability を展開前に置いた。OpenAI の occupational-request research、academic research program、Simile の population simulation も、adoption rate だけでなく task shift、prediction error、professional responsibility、real outcome を測る必要を示す。AI は IT project ではなく、組織内の judgment、review、risk ownership を再配分する。

### Real-world action、robotics、public service が consent と reversibility を要求する

- **発表日**：2026-07-30 から 2026-08-02
- **テーマ**：Search actions、robotics、finance、courts
- **リンク**：https://blog.google/products-and-platforms/products/search/ai-mode-real-world-tips/
- **要約**：Google AI Mode は calendar、inventory call、ticketing に接続し、Gemini Robotics ER 2 は複数 robot が progress を共有して協働する。financial service と UAE court も AI-generated material を導入し始めた。model output が real-world action に入ると、data minimization、state freshness、final confirmation、legal discretion、reversibility を execution layer に実装しなければならない。

### AI Act、scam disruption、security incident が platform responsibility を cross-organization evidence chain にする

- **発表日**：2026-07-30 から 2026-08-02
- **テーマ**：EU AI Act、abuse response、provenance、security governance
- **リンク**：https://openai.com/index/advancing-responsible-ai-across-europe
- **要約**：EU AI Act は transparency、safety evaluation、content provenance、serious-risk management を procurement と launch の条件にする。Cambodia scam network の disruption は WhatsApp と model platform の signal sharing に依存し、Cyber eval の public-network exposure は test environment 自体が incident source になり得ると示した。governance は identity、model version、data flow、network boundary、incident response、external coordination を一貫して扱う必要がある。
