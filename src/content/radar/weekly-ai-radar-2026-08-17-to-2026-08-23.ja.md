# トレンドカード

- Agent harnessはmodel外部の足場から本番control planeへ移る。context assembly、tool exposure、permission、memory、retained reasoning、compaction、人のattentionが一体で性能を決める。
- Inference economicsはtoken単価からexecution chain全体へ移る。model routing、KV cache、continuous batching、memory supply、call count、local storage hierarchyを一緒に測りたい。
- Open modelとopen weightsは広がるが、API、download版、license、実能力は同一とは限らない。multimodal、context、runtime、commercial termsを個別に確認する必要がある。
- Safety boundaryはcontent refusalからreal-world actionへ広がる。training pacing、minor mode、text watermark、sandbox、data minimization、execution log、model revocabilityが同じgovernance課題になった。
- Enterprise adoptionは「多年のtechnical debtを再評価できる」段階へ入った。isolated parallel agent、full test、per-change human approval、editable artifactが一部のlegacy migrationを実行可能にする。

## Agent harness、context、本番control plane

### Harnessの中心課題はtool calling支援からhuman attention配分へ移る

- **公開日**：2026-08-17〜2026-08-23
- **テーマ**：context assembly、permissions、compaction、human attention
- **リンク**：https://www.latent.space/p/attention-interface
- **要約**：4種のharness architecture、Alookの組織調整、Glean routing、TrueForge cost attribution、PostHog self-driving observabilityは、同じmodelでもruntimeが違えば別systemとして振る舞うことを示す。Harness-Benchでは同一modelで52.4〜76.2の差があり、retained reasoningとcompactionもlong task scoreを大きく変える。modelはtool callingやcontext処理を吸収し続けても、identity、permission、trust、readability、human takeoverはsystem layerに残る。

### Observabilityはcode action、user experience、token costを同時に説明する必要がある

- **公開日**：2026-08-19〜2026-08-23
- **テーマ**：LLM trace、product analytics、cost attribution、feedback loop
- **リンク**：https://github.com/PostHog/posthog
- **要約**：TrueForgeは費用をharness、skills、instructions、tools、messagesへ分解し、PostHogはLLM trace、error、log、session replay、product behaviorを同じplatformへ置き、Gleanはretrieval後のcontext qualityとcostでmodelをrouteする。本番agentはtokenだけでなくuser experience、tool result、latency、failure attribution、repair diffを関連付け、agent生成pull requestにはhuman merge gateを残すべきだ。

### Append-only event logとisolated worktreeはagent fleetを運用可能にする

- **公開日**：2026-08-17〜2026-08-22
- **テーマ**：event sourcing、mailbox、worktree、ownership
- **リンク**：https://github.com/apache/maka
- **要約**：Munder Difflinのlocal mailbox、single committer、human gate、Apache MakaのRuntime Event Log、Cursor Originのagent-aware code hostingは、execution stateを会話からqueryable factへ引き上げる。multi-agent systemにはowner、branch、credential、approval、termination、recovery pointが必要で、なければ並列化はconflict、重複作業、追跡不能な変更を同時に増幅する。

## Model、inference、real-world feedback

### Model routingの価値は常に最安modelを選ぶことではなくcontext適合にある

- **公開日**：2026-08-17〜2026-08-22
- **テーマ**：routing、cached context、task cost、open models
- **リンク**：https://www.latent.space/p/glean-model-routing
- **要約**：Gleanはroutingをretrieval後に置き、Daily Doseはcross-model switchがhot KV cacheを失うと説明し、Grok 4.6は少ないagent turnでtask costを下げた。price比較にはcache hit、context rebuild、call count、output length、retryを含める必要がある。open modelはvendor lock-inを下げるが、deployment、routing、eval、operations costを増やし得る。real taskのquality、latency、total costで経路を決めたい。

### Open weightsはsmall modelからlong context、vision、agentic workへ広がる

- **公開日**：2026-08-18〜2026-08-22
- **テーマ**：GLM-5.3、Inkling、Grok 4.6、Qwen3.8、license
- **リンク**：https://z.ai/blog/glm-5.3
- **要約**：GLM-5.3はpost-training拡張でlong-horizon codingとsecurity taskを改善し、Inklingは975B total／41B activeと100万token contextのcustomizable weightsを出し、Grok 4.6は50万tokenと少ないturnでlong taskを強化した。Qwen3.8はAPIとopen-weights版がmultimodal、context、licenseで異なり得ると示す。parameter、active size、reasoning budget、model file、runtime support、commercial termsを分けて記録すべきだ。

### Memory、batching、local storage hierarchyはinference supply chainの一部になる

- **公開日**：2026-08-18〜2026-08-21
- **テーマ**：memory price、continuous batching、Apple Silicon、wafer scale
- **リンク**：https://www.latent.space/p/ainews-memory-prices-up-500-in-12
- **要約**：memory priceが一年で約500%上がった信号、GPU arithmetic intensity、oMLXのRAM+SSD tiered KV cache、MTPLXのexact speculative decoding、Cerebras CS-4のmodular wafer-scale rackは、bottleneckがFLOPsだけでないことを示す。capacity、bandwidth、cache lifecycle、scheduler、I/O、quantization error、real concurrencyがend-to-end throughputとlocal inference economicsを決める。

### Simulationとautomated wet labはmodel trainingを現実feedback loopへ接続する

- **公開日**：2026-08-21〜2026-08-23
- **テーマ**：human simulation、world model、robotic lab、external validation
- **リンク**：https://www.latent.space/p/simile
- **要約**：Simileはinterview、transaction data、RCTでhuman behavior foundation modelを作り、Vivodyneは12のrobotic labと年310万超のtissue experimentでbiology world modelを学習する。前者はuser researchをinference workloadへ変え、後者はAI proposalをreal tissue measurementへ戻す。simulation bias、batch effect、clinical extrapolation、independent replicationはinternal model scoreで代替できない。

## Safety、governance、traceability

### Pacing、watermark、teen modeはsafetyをtrainingとproduct defaultへ前倒しする

- **公開日**：2026-08-19〜2026-08-23
- **テーマ**：training pacing、text watermark、minor safety、provenance
- **リンク**：https://openai.com/index/pacing-model-development-cyber-capabilities/
- **要約**：OpenAIは最大frontier runを保留し、ChatGPT for Teensはage predictionとdefault restrictionを使い、Claude watermarkはsamplingへstatistical signalを入れる。safetyは生成後moderationだけでなく、trainingを続けるか、userをどのexperienceへ入れるか、output provenanceをどう残すかの問題になった。threshold、false-positive handling、human review、appealが必要で、watermarkはauthor identityを確定せず、age predictionも家庭・学校・platform責任を代替しない。

### High-risk agentはdata minimization、sandbox、audit、model revocabilityを一緒に設計する

- **公開日**：2026-08-18〜2026-08-23
- **テーマ**：zero data retention、sandbox、red team、deletion
- **リンク**：https://openai.com/index/offering-zero-data-retention-for-frontier-models/
- **要約**：Private Safety Processingはcustomer textを見せずrisk patternを探し、smolvmはisolated guest kernel、GPU、live forkでagentを隔離し、AI-Infra-Guardはagent、skill、MCP、infrastructureをred-team対象にし、Meta minor caseはchild dataでtrained modelの削除も求める。data lifecycle、execution isolation、tool permission、anomaly detection、emergency stop、evidence retention、deletionを一つのloopにする必要がある。

## Tool、GitHub、delivery verification

### Context filesystemとportable memoryはagentの仕事をtool間で継続させる

- **公開日**：2026-08-18〜2026-08-21
- **テーマ**：hierarchical context、portable memory、session state
- **リンク**：https://github.com/volcengine/OpenViking
- **要約**：OpenVikingはresource、memory、skillをhierarchical filesystemへ統合し、ai-memoryはGit-backed Markdown wikiでcoding agent間のcontextを運び、nodetermはspatial canvas、tmux、hooksでmulti-session stateを管理する。portable contextはtool switch costを下げるが、memory writeはreviewable、expirable、revertibleであるべきで、secret、誤仮説、短期noiseの永久伝播を防ぎたい。

### Skillとagent packageは独立したgovernanceが必要なsupply chainになる

- **公開日**：2026-08-20〜2026-08-23
- **テーマ**：skills、hooks、MCP、security scan、compatibility
- **リンク**：https://github.com/affaan-m/ECC
- **要約**：/wayfinder、mattpocock/skills、ECC、Anthropic-Cybersecurity-Skillsはplanning、TDD、review、memory、security framework、commandをportable capabilityへする。reuse costを下げる一方、instruction、hooks、external MCP、auto-update、persistent memoryがexecution surfaceを共有する。source、version、permission、host compatibility matrix、install path、rollbackを確認し、star数をsafety proofにしないことが重要だ。

### Enterprise migrationの成果はisolation、full test、per-change approvalから生まれる

- **公開日**：2026-08-20〜2026-08-23
- **テーマ**：legacy migration、enterprise workflow、human approval
- **リンク**：https://openai.com/index/asana
- **要約**：Asanaは最大4 isolated Codex agentで約1.5週のengineering effort内にEnzymeを除去し、Stampliはrelease productionを243時間から77時間へ短縮し、Headwayはdisposable containerでcompliant internal assistantを作った。共通点は放任autonomyではなく、simple task definition、isolated environment、complete test、定期review、各変更のhuman approvalだ。vendor co-published caseは独立再現が必要で、cost、failure rate、unmigrated scopeも評価へ含めたい。

### AI infrastructure投資はGPUからmemory、packaging、datacenter、power、community commitmentへ広がる

### Automation後のhuman valueはproblem selection、design、explanation、final accountabilityへ移る
