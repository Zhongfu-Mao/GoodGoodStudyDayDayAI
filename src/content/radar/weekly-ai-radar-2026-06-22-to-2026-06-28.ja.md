# 対象範囲

- 時間窓：2026-06-22 ~ 2026-06-28
- 対象日報：2026-06-22 から 2026-06-28 までの各日報

# トレンドカード

- Agent engineering の重心は「model が tool を呼べるか」から、loop、harness、memory、permissions、evaluation、cost、review、deployable workflow へ移りました。
- Model competition はさらに細分化しました。Long context、computer use、post-training RL、MTP retrofit、open MoE、evaluation contamination、frontier model access gating が engineering decisions に入っています。
- Enterprise adoption は ChatGPT seat だけではありません。OpenAI / Samsung、Omio、Coinbase、Baseten、Anthropic research は、AI が budget、permission、payment、employee responsibility、organization process に入ることを示します。
- GitHub trends は single tools から、agent-readable specs、code graphs、memory layers、video / SEO / document processing など agent-callable business systems に広がりました。
- 来週も見るべき論点は 3 つです。Long-horizon agent evaluation は cheating に強いか。Codebase / memory graph は token waste を本当に減らすか。Model access gating は small teams and independent builders にどう影響するか。

## Agent engineering と runnable systems

### Loop、harness、verifiable completion condition は agent engineering の基盤になる

- **公開日**：2026-06-22 から 2026-06-24
- **テーマ**：Agent loop、harness、verification
- **リンク**：[Daily Dose](https://blog.dailydoseofds.com/)
- **要約**：6 月 22 日から 24 日までの signals は、agent engineering を systemization に押し出しました。DeerFlow、ruflo、Hermes Agent、ByteByteGo の agentic engineering setup、Daily Dose の loop engineering、Vercel Eve、MDN MCP server、CopilotKit は同じことを示します。Agent reliability は longer prompt から生まれず、clear context boundaries、tool-facing docs、external verification、team collaboration interface、rollbackable specs、continuous runtime から生まれます。Agent の “done” も self-claim ではなく、external checks、tests、review、stop conditions で定義されます。

### Long-horizon evaluation、permissions、security は agent を governance object にする

- **公開日**：2026-06-23 から 2026-06-28
- **テーマ**：Security、evaluation、permission boundary
- **リンク**：[OpenAI Daybreak](https://openai.com/index/daybreak/)
- **要約**：OpenAI Daybreak、Patch the Planet、Gray Swan、Strix、AgentCard、METR、OSWorld 2.0、MirrorCode、local coding agent permission checklists は、agent risk が prompt layer から real system layer に移ったことを示します。Agents は browser、files、shell、payment、identity、vulnerability fixes、long tasks を扱うため、evaluate、limit、log、review される必要があります。High-quality agent workflow は engineering control system に近づきます。Input surface と permissions を定義し、execute し、self-evaluate / third-party evaluate し、traceable artifact を残します。

### Code knowledge graphs、memory layers、requirement protocols は blind file reading を減らす

- **公開日**：2026-06-28
- **テーマ**：Codebase graph、memory、spec protocol
- **リンク**：[Fission-AI OpenSpec](https://github.com/Fission-AI/OpenSpec)
- **要約**：OpenSpec、CodeGraph、TencentDB Agent Memory、graphify、open-seo は、agent workflow の bottleneck が context management にあることを示しました。OpenSpec は change folders and task lists で requirement alignment を管理します。CodeGraph と graphify は code and documents を queryable graph にします。TencentDB Agent Memory は layered memory と Mermaid task canvas で long task history を圧縮します。open-seo は vertical business workflow を agent-callable にします。Agent efficiency は “read more files” から “read structured context” に移っています。

## Models、evaluation、infrastructure

### Open models、long context、post-training は finer competition に入る

- **公開日**：2026-06-24 から 2026-06-26
- **テーマ**：Open models、long context、post-training
- **リンク**：[Latent.Space / AINews](https://www.latent.space/)
- **要約**：GLM-5.2、Ornith、Liquid LFM2.5、slime、OpenPipe ART、ByteByteGo の LLM / SLM analysis、The Batch の realistic agentic benchmarks は、model competition が leaderboard だけではないことを示します。Long context、agentic coding、post-training RL、reward design、deployment cost、SLM + LLM routing、evaluation contamination は、model が real workflow に入れるかを左右します。Engineering teams にとって、model choice は task、cost、evaluation、serving path の組み合わせになっています。

### Frontier model access、evaluation contamination、release gating は R&D supply chain を変える

- **公開日**：2026-06-26 から 2026-06-28
- **テーマ**：Model access、safety gating、evaluation realism
- **リンク**：[OpenAI GPT-5.6 preview](https://openai.com/index/previewing-gpt-5-6-sol/)
- **要約**：OpenAI GPT-5.6 Sol / Terra / Luna、trusted-partner preview、real-time high-risk classifiers、Cursor の benchmark contamination discussion、OSWorld 2.0、METR long-horizon evaluation は、model release を capability announcement ではなく supply-chain event にしています。Frontier models が強くなるほど、access threshold、evaluation environment、red-team records、cost tiers、degradation paths が重要になります。Small teams は peak capability だけでなく、alternative models、failure modes、reproducible evaluation を記録する必要があります。

### Inference efficiency は cheaper model から cache、speculation、routing、serving path に移る

- **公開日**：2026-06-24 から 2026-06-28
- **テーマ**：Inference efficiency、cost governance
- **リンク**：[Google Research](https://x.com/GoogleResearch/status/2070579898465567159)
- **要約**：Google Research の Multi-Token Prediction retrofit、Daily Dose の DFlash speculative decoding、Coinbase / Baseten cost governance、Recursive Language Models、Corrective RAG は、inference efficiency が system design layer に入ったことを示します。Enterprise は model calls を減らすだけではありません。Routing、cache hit、speculative decoding、RAG correction、context policy、task tiering で cost を制御します。Model serving path 自体が model capability の一部になっています。

## Organization adoption、industry、commercialization

### Enterprise AI は seat adoption から workflow redesign に入る

- **公開日**：2026-06-22 から 2026-06-28
- **テーマ**：Enterprise adoption、workflow redesign
- **リンク**：[OpenAI / Samsung](https://openai.com/index/samsung-chatgpt-enterprise/)
- **要約**：OpenAI / Samsung、Omio conversational travel、Every の token budget、Coinbase / Baseten cost governance、Anthropic work-impact research、Hugging Face ARR over $100M は、enterprise AI を single chat entrypoint から押し出しました。Companies は AI を employee workflows、transaction inventory、budget control、support、procurement、R&D、compliance に入れています。Adoption barrier も変わりました。Employee accounts ではなく、AI permission、budget、metrics、audit path、responsibility boundary を設計する必要があります。

### AI industry competition は talent、compute、capital、organization structure で同時に起こる

- **公開日**：2026-06-22 から 2026-06-26
- **テーマ**：Talent、compute、capital、organization
- **リンク**：[老范讲故事](https://lukefan.com/)
- **要約**：老范讲故事 の DeepMind talent movement、Anthropic / Alibaba distillation controversy、Sakana Fugu orchestration capability、DeepSeek and China AI structure analysis と、AINews の SpaceX / xAI neocloud、OpenAI in-house chip、Hugging Face commercialization signals を合わせると、AI competition は organization、talent、capital、compute、product route の総合競争です。Model capability は surface result であり、long-term advantage は talent flow、compute efficiency、commercial distribution、organizational execution に左右されます。
