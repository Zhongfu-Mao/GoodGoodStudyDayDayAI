### Celeris-1-decision：型付き確率出力はキャリブレーションおよびテスト条件と合わせて確認が必要

- 出典：The Rundown AI / Celeris
- 日付：2026-10（ベンダー評価）；2026-10-12（ニュースレター紹介）
- リンク：https://celeris.ai/celeris-1-decision
- 要約：Celeris は拡散言語モデルを型付き意思決定に適用：テキスト、構造化データ、または画像を入力し、選択肢の確率を出力するとともに、1文の説明を添付できる。ベンダーは22のデータセット、3,210問からなる jev-bench において80.0%の正解率を報告し、同時に確率誤差を測定するための Brier スコアも報告している；AWS us-east-1 から測定した単一問題リクエストのエンドツーエンド遅延の中央値は67ミリ秒であった。これらはベンダーが提供した特定の評価であり、すべての業務シナリオにおける正解率や応答時間を保証するものではない。今回の提供はマネージド API であり、重みの公開やファインチューニングは行われていない；確率、説明、およびフォーマットの正しさも、業務上の検証の代わりにはならない。

### SANDO：障害物が到達しうる空間を飛行コリドーに組み込む、安全性の証明には依然として前提が存在

- 出典：The Rundown AI / MIT / arXiv
- 日付：2026-10-07（MIT 発表）；2026-10-12（技術分析）
- リンク：https://arxiv.org/html/2604.07599v3
- 要約：SANDO は動的障害物の最大速度に基づいて将来の到達可能領域を推定し、時間とともに変化する3次元セーフティコリドーを構築してドローンの軌道を最適化する。これは言語モデルではなく軌道計画手法である。研究では12回の実機飛行で衝突なしと報告されているが、論文では現実の知覚および制御の誤差が理論的証明のすべての仮定を満たしてはいないと説明されている；知覚を用いたシミュレーション実験でも衝突が発生した。保証は現在の計画ウィンドウに対するものであり、次のウィンドウに実行可能なパスが必ず存在することを保証するものではない。変数の簡略化による最大7.4倍の改善は、簡略化されていない SANDO と比較した最適化時間の短縮を指しており、飛行速度や全体的な安全性の向上ではない。

- 要約：HarnessRouter のコミュニティ版は、Codex や Claude Code などの既存 harness を統一タスクインターフェースに接続し、永続セッション、ストリーミング進捗、ファイルと成果物、キャンセル、構造化された失敗を処理し、OpenAI Responses 互換 API を提供する。UHP はこの共通タスクプロトコルであり、これをモデル自体と同一視することはできない。コミュニティ版は Apache-2.0 を採用しており、セルフホストには依然としてプロバイダーの認証情報と管理された実行環境が必要であり、モデルや試用キーは付属していない。インターフェースが置換可能であることは、異なる harness の権限、振る舞い、タスク品質が完全に同一であることを示すものではなく、移行時には依然として失敗および回復パスの検証が必要である。

### ByteByteGo：エネルギー関数による候補解の評価は、トークン単位で言語を生成するのとは異なるアプローチ

- 出典：ByteByteGo
- 日付：2026-10-12（ニュースレター）
- リンク：https://blog.bytebytego.com/p/how-to-build-models-without-language
- 要約：インタビューでは Logical Intelligence の Kona と数独タスクを取り上げ、エネルギーベースの推論について議論：エネルギー関数は問題と候補解の一致度を測定し、候補解を調整することでより低いエネルギー状態を探索し、その後に制約を検証するアプローチであり、単に順序通りに離散トークンを生成するわけではない。記事では、この技術的説明はエネルギーベースの推論に関する一般的な要件を述べており、Kona の内部実装に関する完全な公開説明ではないことを明記している。数独や形式的証明には明確な検証器（チェッカー）が存在するため、特定のデモからすべての現実のタスクにおいて信頼性がより高いと直接推断することはできず、ベンダー自身の述べる成功率や異なるコスト算出基準を一般的な比較の結論とみなすこともできない。
