# 今週の範囲

- 対象期間：2026-05-18 〜 2026-05-24
- 対象日報：2026-05-18 〜 2026-05-24 の各号

# トレンドカード

- Google I/O は Search、Workspace、Shopping、Antigravity、Managed Agents、multimodal device agents を同じ agent-first platform narrative に置きました。
- AWS の最も密度が高い signal は単一 model ではなく、AgentCore、SageMaker、Strands、Nova Sonic、Kiro memory、code evaluators、programmatic tool calling からなる production foundation です。
- Agent evaluation は model leaderboard から system leaderboard へ移っています。Open Agent Leaderboard、multimodal judges、code evaluators、harness analysis が wrapper、tool use、failure cost、context management を評価します。
- Inference economics は product shape に再び影響しています。DeepSeek price cut、OpenAI-compatible endpoints、programmatic tool calling、R2 / asset compression、sandbox cost が、常時動かせる agent workflow を決めます。
- Documents、remote sensing、OCR、voice、accessibility、commerce、medical judgment は、AI value が single model output ではなく input structure、domain responsibility、real workflow に依存することを示しています。

## Agent platforms and runtimes

### Google I/O 2026 は Gemini、Antigravity、Managed Agents、WebMCP を developer platform として整理した
- **公開日**：2026-05-20
- **テーマ**：Agent platforms and runtimes
- **リンク**：[Google I/O 2026 announcements](https://blog.google/innovation-and-ai/technology/ai/google-io-2026-all-our-announcements/)
- **要約**：Google は Gemini 3.5 Flash、Gemini Omni、Antigravity 2.0、Managed Agents、AI Studio、WebMCP を同じ agent-first line に置きました。Antigravity は desktop、CLI、SDK、subagents、hooks、async tasks を追加し、Managed Agents は remote Linux、code execution、file management、web browsing を提供します。Google の platform focus は “model is available” から “model、tools、execution environment、IDE が one agent surface としてどう協調するか” に移っています。

### AWS AgentCore と Nova Sonic は voice、tools、memory、evaluation が同じ production stack に入ることを示した
- **公開日**：2026-05-19
- **テーマ**：Agent platforms and runtimes
- **リンク**：[Amazon Nova Sonic voice agent design](https://aws.amazon.com/blogs/machine-learning/scalable-voice-agent-design-with-amazon-nova-sonic-multi-agent-tools-and-session-segmentation/)
- **要約**：Nova Sonic voice agents、AgentCore Runtime、Gateway、Memory、Code Interpreter、Strands、Lambda evaluators は同じ方向を指しています。Agent production systems には low-latency streaming、tool governance、state handoff、long-term memory、executable sandbox、observable evaluation が必要です。AWS の今週の signal density は、cloud platforms が agent を sample code から managed infrastructure へ移していることを示しています。

### MCP stateless、sandboxes、memory layers は agent runtime を scalable protocol に近づける
- **公開日**：2026-05-23
- **テーマ**：Agent platforms and runtimes
- **リンク**：[Latent.Space AINews](https://www.latent.space/p/ainews-all-model-labs-are-now-agent)
- **要約**：Latent.Space がまとめた MCP release candidate、CoreWeave Sandboxes、Cloudsail、Gemini Managed Agents、Hermes、AI-Q、gBrain などの signal は、agent runtime が one-off tool calls から protocolized runtime system へ進んでいることを示します。Stateless MCP、per-task sandbox、skills、shared memory、key management は cross-vendor agents の common foundation になります。

## Evaluation, reliability, and harnesses

### Open Agent Leaderboard は evaluation target を model から full agent system へ進めた
- **公開日**：2026-05-18
- **テーマ**：Evaluation, reliability, and harnesses
- **リンク**：[Open Agent Leaderboard](https://huggingface.co/blog/ibm-research/open-agent-leaderboard)
- **要約**：IBM Research と Hugging Face は Open Agent Leaderboard を公開しました。Exgentic framework で SWE-Bench Verified、BrowseComp+、AppWorld、tau2-Bench などを統合し、success rate と average cost per task を同時に報告します。同じ model でも wrapper が違うと quality と cost が変わり、failed runs は successful runs より 20% から 54% 高くなり得ます。Agent evaluation は base model だけでなく planning、tool selection、context management、memory、recovery を測る必要があります。

### Multimodal judges と code evaluators は visual grounding と deterministic rules を同時に扱う
- **公開日**：2026-05-20
- **テーマ**：Evaluation, reliability, and harnesses
- **リンク**：[Strands multimodal evaluators](https://aws.amazon.com/blogs/machine-learning/multimodal-evaluators-mllm-as-a-judge-for-image-to-text-tasks-in-strands-evals/)
- **要約**：Strands Evals の multimodal judges は image、query、response、reference answer を直接見て、captioning、visual QA、document extraction、OCR、chart interpretation を評価できます。AgentCore custom code evaluators は Lambda で schema、numeric drift、workflow、PII を検査します。Production evaluation は original input、system trace、deterministic business rules を同時に扱う必要があります。

### Agent harness は product differentiation の core engineering layer になった
- **公開日**：2026-05-24
- **テーマ**：Evaluation, reliability, and harnesses
- **リンク**：[The Anatomy of an Agent Harness](https://www.dailydoseofds.com/p/the-anatomy-of-an-agent-harness/)
- **要約**：Daily Dose of DS は harness を orchestration loop、tools、memory、context management、state、error handling、guardrails、verification、subagents に分解しました。この framework は、同じ model でも products によって performance が違う理由を説明します。Production agent の competition point は model outside の systems engineering に移っています。OpenAI、Anthropic、LangGraph、CrewAI、Claude Code の違いは、process、permission、I/O、recovery mechanisms の design differences に近づいています。

## Inference economics and tool calling

### Programmatic Tool Calling は deterministic work を context window から sandbox code へ移す
- **公開日**：2026-05-19
- **テーマ**：Inference economics and tool calling
- **リンク**：[Programmatic Tool Calling on Amazon Bedrock](https://aws.amazon.com/blogs/machine-learning/implementing-programmatic-tool-calling-on-amazon-bedrock/)
- **要約**：AWS の PTC example は model に Python code を生成させ、sandbox 内で loops、filtering、aggregation、multiple tool calls を実行し、final answer だけを model に戻します。その結果 token usage は 87% から 92% 下がり、accuracy も安定しました。Long-running agents では、model が逐次 tool call するより、model が plan / program を作り sandbox が deterministic execution を担当するほうが reliable software system に近くなります。

### DeepSeek price cut、OpenAI-compatible SageMaker endpoints、R2 asset pressure は runtime cost を作り替える
- **公開日**：2026-05-23
- **テーマ**：Inference economics and tool calling
- **リンク**：[Latent.Space AINews](https://www.latent.space/p/ainews-all-model-labs-are-now-agent)
- **要約**：DeepSeek-V4-Pro の price cut は long-task inference cost を product design の中心に戻しました。SageMaker AI の OpenAI-compatible endpoints は owned models を existing SDK、LangChain、Strands に接続する migration cost を下げます。同時に media assets と NotebookLM outputs の増加は、content agent workflow にも storage and publishing cost があることを示しています。2026 年の agent economics は API tokens だけでなく、sandbox、media、cache、deployment、reuse を含みます。

### Voice agents と realtime transcription は latency budget を architecture issue にする
- **公開日**：2026-05-20
- **テーマ**：Inference economics and tool calling
- **リンク**：[SageMaker AI and vLLM realtime voice](https://aws.amazon.com/blogs/machine-learning/build-real-time-voice-applications-with-amazon-sagemaker-ai-and-vllm/)
- **要約**：SageMaker bidirectional streaming と vLLM Realtime API は managed realtime speech transcription path を示しました。Nova Sonic voice agent design は tool count、sub-agent、session segmentation、prefetch、filler phrases が voice interaction にどう影響するかを示します。Voice agent の key metric は average answer quality ではなく、end-to-end latency、barge-in handling、tool parallelism、state handoff、safety prompt timing です。

## Open models, documents, and scientific AI

### PaddleOCR 3.5 と Ettin Reranker は RAG / Agent の input quality chain を補う
- **公開日**：2026-05-18
- **テーマ**：Open models, documents, and scientific AI
- **リンク**：[PaddleOCR 3.5 Transformers backend](https://huggingface.co/blog/PaddlePaddle/paddleocr-transformers)
- **要約**：PaddleOCR 3.5 は OCR と document parsing を Transformers backend に接続しました。Ettin Reranker は 17M から 1B の cross-encoder rerankers、training data、recipe を公開しました。前者は documents を structured information に変える入口で、後者は candidate context を正しく並べる段階です。RAG と agent memory の quality は final LLM だけでなく、この input chain に大きく依存します。

### OlmoEarth v1.1 は scientific model efficiency が data-structure-aware tokenization から生まれることを示す
- **公開日**：2026-05-19
- **テーマ**：Open models, documents, and scientific AI
- **リンク**：[OlmoEarth v1.1](https://huggingface.co/blog/allenai/olmoearth-v1-1)
- **要約**：OlmoEarth v1.1 は Sentinel-2 remote sensing input の token structure を再設計し、running cost を up to one third に下げつつ v1 に近い performance を維持します。Scientific and geospatial AI の efficiency は faster GPU だけではなく、input data の physical structure、resolution、time dimension、task objective を理解することからも生まれます。

### Running Guide agent は on-device multimodal、risk tiers、hardware form factor を accessibility に持ち込んだ
- **公開日**：2026-05-20
- **テーマ**：Open models, documents, and scientific AI
- **リンク**：[Running Guide agent](https://blog.google/innovation-and-ai/models-and-research/google-deepmind/running-guide-agent/)
- **要約**：Google の Running Guide agent は chest-mounted Pixel 10 Pro、on-device segmentation、Gemma 4 E4B、Planner / Coach / Break multi-agent architecture で blind and low-vision runners を支援します。この case は AI を screen assistant から high-responsibility physical scene へ持ち込みます。必要なのは low-latency STOP cues、offline reliable path、strict risk hierarchy、appropriate hardware form factor です。

## Adoption, multi-agent work, and human judgment

### Cheap competence は human work を framing、boundaries、responsibility へ押し出す
- **公開日**：2026-05-24
- **テーマ**：Adoption, multi-agent work, and human judgment
- **リンク**：[Cheap Competence, New Frontier](https://every.to/context-window/cheap-competence-new-frontier)
- **要約**：Every は “After Automation” を軸に cheap competence を論じました。Agents が code、emails、newsletter を生成できても、人間の仕事は消えず、problem framing、quality judgment、responsibility へ移ります。Medical observation も同じ結論です。Knowledge が cheaper になると、excellent doctors の situated judgment はより valuable になります。

### Gas City は 100-agent software factory の potential と cost を同時に見せた
- **公開日**：2026-05-19
- **テーマ**：Adoption, multi-agent work, and human judgment
- **リンク**：[Inside the 100-agent Software Factory](https://every.to/context-window/inside-the-100-agent-software-factory)
- **要約**：Gas City は persistent “mayor” agent が disposable workers を coordinate することで、light factory / dark factory、disposable workers、multi-model code review を示しました。同時に multi-agent factory の real cost も明らかにしました。Context rereading、token consumption、task tracking、tool complexity です。結論は特定 toolkit をすぐ採用することではなく、coordination patterns を existing engineering workflow に取り込むことです。

### Agentic commerce と marketing agents は payment、checkout、business systems に入っている
- **公開日**：2026-05-20
- **テーマ**：Adoption, multi-agent work, and human judgment
- **リンク**：[Google Shopping updates](https://blog.google/products-and-platforms/products/shopping/shopping-updates-google-marketing-live/)
- **要約**：Universal Cart、Agent Payments Protocol、Universal Commerce Protocol、Ask Advisor は、commerce agents が product recommendation から payment、merchant of record、promotion、brand visibility、campaign launch、cross-system data explanation に進んでいることを示します。Consumer agents が transaction に入ると、responsibility boundary、channel allocation、business system consistency を扱う必要があります。
