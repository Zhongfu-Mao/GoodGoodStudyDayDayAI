# 今週の範囲

- 対象期間：2026-05-25 〜 2026-05-31
- 対象日報：2026-05-25 〜 2026-05-31 の各号

# トレンドカード

- Agent engineering の keyword は “tool calling ができる” から “evaluatable、recoverable、auditable、deliverable” へ移りました。DoorDash、Braintrust、OpenAI、Cisco、Tax AI、Warp が production loop を示しています。
- Deep Research、vector indexing、document parsing、RAG / Graph RAG / Agentic RAG は、agent の基礎能力が retrieval layer、context engineering、input quality に依存することを示しています。
- Evaluation and governance は public narrative の中心になりました。Third-party evaluation playbook、LLM-as-judge、ITBench-AA、OpenAI election safeguards、Rosalind Biodefense は claim、harness、budget、responsibility boundary を明示させます。
- Organization adoption は “one agent per employee” から、compound engineering、AI Forward Deployed Engineer、Codex workflow、Cursor habits、reusable plugins へ移っています。
- GitHub の hot projects は agent harness、research workbench、Agentic RAG、lightweight document parsing、voice / training / evaluation tools に集中し、methodology が runnable systems へ落ちています。

## Agent systems and production loops

### DoorDash、Tax AI、Braintrust は agent improvement を observable flywheel にした
- **公開日**：2026-05-28 〜 2026-05-30
- **テーマ**：Evaluation flywheel and production feedback
- **リンク**：[DoorDash LLM evaluation](https://careersatdoordash.com/blog/how-doordash-built-a-testing-system-to-evaluate-llms/)
- **要約**：DoorDash は simulated conversations、LLM-as-judge、人手 review で support LLM の hallucination を下げました。OpenAI、Thrive、Crete の Tax AI case は user edits、retries、production traces を post-training data に変えます。Braintrust は customer request を Codex が実行できる experiment と code change に変えます。共通点は、一度きりの prompt ではなく trace、evaluation、human feedback、preview branch で継続改善することです。

### Codex は assistant から enterprise engineering workflow の一部へ進んだ
- **公開日**：2026-05-27 〜 2026-05-31
- **テーマ**：Coding agent adoption
- **リンク**：[OpenAI Codex customer stories](https://openai.com/codex/)
- **要約**：Cisco、Endava、Braintrust、The Rundown の Codex /goal example は同じ方向を示します。Coding agent の value は code completion ではなく、requirements breakdown、build-log analysis、cross-repository fixes、review、preview、delivery rhythm に入ることです。Cursor habits report も、adoption gap が model button ではなく review loop、task boundary、team method から生まれることを示しています。

### Warp Oz と Onyx Deep Research は agent control plane と research workflow を open source 化する
- **公開日**：2026-05-25 〜 2026-05-28
- **テーマ**：Agent control plane
- **リンク**：[Onyx Deep Research lessons](https://www.onyx.app/blog/lessons-from-building-deep-research)
- **要約**：Onyx の lessons は、strong research agent が coordinator により多くの tools を渡すことではなく、isolated research workers、clear context boundary、result merging から生まれることを示します。Warp Oz は local terminal、cloud agent、open-source collaboration を control plane にします。競争点は task orchestration、state display、permission boundary、collaboration interface へ移っています。

## Retrieval, context, and data layer

### CockroachDB C-SPANN は vector indexing に distributed database semantics を持ち込む
- **公開日**：2026-05-25 〜 2026-05-26
- **テーマ**：Vector indexing and transactional systems
- **リンク**：[CockroachDB vector indexing](https://www.cockroachlabs.com/blog/vector-search-indexing/)
- **要約**：C-SPANN は vector index を distributed SQL system 内の ordinary table data として扱い、transaction、partitioning、multi-tenancy、regional compliance を継承します。RAG と agent memory は embedding similarity だけでなく、existing data systems の isolation、recovery、permissions、operations model に入れる必要があります。

### RAG、Graph RAG、Agentic RAG の役割分担は engineering decision になった
- **公開日**：2026-05-28 〜 2026-05-30
- **テーマ**：Retrieval system design
- **リンク**：[RAG vs. Graph RAG vs. Agentic RAG](https://www.dailydoseofds.com/p/rag-vs-graph-rag-vs-agentic-rag)
- **要約**：Daily Dose は standard RAG、Graph RAG、Agentic RAG を query type ごとに比較しました。liteparse、ONNX、Transformer Lab、Qwen 3 Agentic RAG tutorial は document parsing、model conversion、training / evaluation、private deployment を補います。Retrieval は vector DB 単体ではなく、input structure、relationship modeling、tool calling、deployment path の組み合わせになっています。

### Backend context engineering は coding-agent cost に直接効く
- **公開日**：2026-05-27 〜 2026-05-29
- **テーマ**：Context engineering
- **リンク**：[InsForge](https://github.com/InsForge/InsForge)
- **要約**：InsForge case は、backend schema、API、data state、execution feedback を agent-friendly に公開すると blind search と token waste を減らせることを示しました。Firecracker microVM、Vercel Hive、agent crash recovery と同じく、model outside の runtime、context interface、recovery point が long-running agent の stability を決めます。

## Evaluation, recovery, and governance

### Third-party evaluation playbook は model claim を auditable structure に戻した
- **公開日**：2026-05-29 〜 2026-05-30
- **テーマ**：Evaluation governance
- **リンク**：[OpenAI third-party evaluations](https://openai.com/index/third-party-evaluations/)
- **要約**：OpenAI は third-party evaluation に claim、task、harness、budget、failure cases、limitations の明示を求めています。ITBench-AA は frontier models が enterprise SRE root-cause localization で 50% 未満であることを示しました。Evaluation は leaderboard や marketing claim から engineering audit へ移っています。

### Agent crash recovery は database state だけでなく decision chain を保存する必要がある
- **公開日**：2026-05-29 〜 2026-05-31
- **テーマ**：Recovery and state consistency
- **リンク**：[Why Agent Crashes Are Nothing Like Database Crashes](https://www.dailydoseofds.com/p/why-agent-crashes-are-nothing-like)
- **要約**：Agent crash は database crash と違います。Recovery point には data だけでなく decision chain、tool trace、context window、plan、verified assumptions、unfinished actions が必要です。Long-running agent には checkpoint、resume、branch、human review、readable logs が必要になります。

### Security and public responsibility は model release から application boundary へ広がった
- **公開日**：2026-05-25 〜 2026-05-30
- **テーマ**：Safety, compliance, and high-responsibility domains
- **リンク**：[OpenAI election integrity](https://openai.com/index/2026-election-integrity/)
- **要約**：Project Glasswing、Perplexity Bumblebee、OpenAI election safeguards、Rosalind Biodefense、Boston Children’s Hospital、Pope の AI ethics statement は、AI governance を vulnerability disclosure、endpoint supply chain、public health、hospital operations、democratic process に接続しました。Question は “what can the model do” から “under what boundary can it responsibly act” へ移っています。
