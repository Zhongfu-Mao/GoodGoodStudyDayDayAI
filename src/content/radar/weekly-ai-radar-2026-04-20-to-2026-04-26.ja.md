# トレンドカード

- Agent engineering の主線は「tool を呼べるか」から、memory、context budget、安全境界、UI 出力、監査可能な runtime へ移った。
- GPT-5.5、DeepSeek V4、Kimi K2.6、Qwen3.6、GLM-5.1 は、モデル競争を「能力 + context 長 + 推論コスト + agentic runtime」の複合戦に変えた。
- Coding agent の競争は model score だけでは決まらず、CLI、desktop workflow、安定性、組織の token 運用、品質回帰への対応が実採用を左右し始めている。
- Data platform、API realtime pattern、database structure、tracing、推論 topology が、AI system を実運用できるかどうかの基礎制約として戻ってきた。

## モデルリリース & システム

### GPT-5.5 / Spud は frontier 競争を cost-performance に引き戻した
- 初出日：2026-04-24
- テーマ：モデルリリース & システム
- リンク：<https://www.latent.space/p/ainews-gpt-55-and-openai-codex-superapp>
- 要約：GPT-5.5 は単なる benchmark 更新ではなく、Codex superapp、browser control、workspace agents、auto-review guardian と同時に現れた。つまり OpenAI は frontier model を、より統合された知識作業台の入口へ組み込もうとしている。The Rundown 側は、Claude を上回る frontier ranking と、input/output 100 万 token あたり $5/$30 という価格を、同種の coding model より安い cost advantage として強調している。

### DeepSeek V4 Pro / Flash は 1M context を deployable engineering ledger に載せた
- 初出日：2026-04-24
- テーマ：モデルリリース & システム
- リンク：<https://huggingface.co/blog/deepseekv4>
- 要約：DeepSeek V4-Pro は 1.6T total / 49B active、V4-Flash は 284B total / 13B active で、どちらも 1M context、CSA/HCA hybrid attention、FP8/FP4 storage、tool call をまたいだ reasoning 保持を組み合わせている。重要なのは、長文脈が容量の宣伝ではなく、KV cache、single-token FLOPs、license、Ascend/CANN 互換、価格構造まで含む deployment issue になったことだ。

### Open-weight agentic models は長時間 tool use 競争に入った
- 初出日：2026-04-23
- テーマ：モデルリリース & システム
- リンク：<https://www.latent.space/p/ainews-tasteful-tokenmaxxing>
- 要約：Kimi K2.6、Qwen3.6、Xiaomi MiMo-V2.5、GLM-5.1 のまとまりは、open-weight model が long-running coding、tool call 数、多模态 checkpoint、thinking/non-thinking 切替、100k+ context を軸に上を目指していることを示した。追うべきなのは単発 score ではなく、長い task の中で failure path を見つけ、replan し、context cost を制御できるかどうかだ。

### Claude Opus 4.7 と Mythos は旗艦 model のリリース階層化を示した
- 初出日：2026-04-20
- テーマ：モデルリリース & システム
- リンク：<https://www.latent.space/p/ainews-anthropic-claude-opus-47-literally>
- 要約：Claude Opus 4.7 は旗艦 model が高頻度に改善され続けることを示した一方、今週の follow-up は、それが 4.6 の painless upgrade ではないことも示した。prompt、tool call、product regression は再検証が必要だ。Mythos の leak はもう一つの方向を示している。より強い能力は狭く制御された channel に置かれ、公開旗艦版、gated frontier 版、vertical 版が並存する構造になりつつある。

## アーキテクチャ & Engineering Paradigm

### Agent memory は vector retrieval から relation + graph + domain vocabulary へ進んだ
- 初出日：2026-04-25
- テーマ：アーキテクチャ & Engineering Paradigm
- リンク：<https://blog.dailydoseofds.com/p/top-ai-labs-share-an-agent-memory>
- 要約：Daily Dose の agent memory 記事は、vector retrieval だけでは multi-hop fact chain を落とし、context を大きくしても lost in the middle は消えないと整理している。推奨されているのは `Cognee` の ECL pipeline で relation layer、vector layer、graph layer に同時書き込みし、domain vocabulary で entity disambiguation を行う設計だ。これは「全部 context に詰める」よりも long-running agent memory に近い。

### Context Engineering と tokenmaxxing は組織レベルの governance になった
- 初出日：2026-04-21
- テーマ：アーキテクチャ & Engineering Paradigm
- リンク：<https://blog.dailydoseofds.com/p/karpathys-context-engineering-principles>
- 要約：Karpathy の Context Engineering 原則は、Claude Code の token 使用量を 2.8x 圧縮する実践として具体化された。context は大きいほどよいのではなく、task spec、state、tool result、history を model が使える形に裁断する必要がある。Latent Space の “tasteful tokenmaxxing” はこれを組織論に引き上げ、深い serial research loop と parallel probing を区別すべきだと示した。

### GitHub Agentic Workflow は「Agent が侵害済み」という前提で境界を設計する
- 初出日：2026-04-21
- テーマ：アーキテクチャ & Engineering Paradigm
- リンク：<https://blog.bytebytego.com/p/github-agentic-workflow>
- 要約：ByteByteGo の GitHub agentic workflow 分析が重要なのは、agent が prompt injection、悪意ある依存、repository content の影響を受けることを前提にしている点だ。そのため isolation、least privilege、audit logs、human approval、rollback capability が system design に入る。これは「agent に PR を開かせる」よりも production に近い視点だ。

### LLM serving は throughput、topology、tracing に戻った
- 初出日：2026-04-20
- テーマ：アーキテクチャ & Engineering Paradigm
- リンク：<https://blog.dailydoseofds.com/p/72-techniques-to-optimize-llms-in>
- 要約：72 Techniques to Optimize LLMs in Production、Prefill-as-a-Service、Save the Traces をまとめると、AI system の bottleneck は model choice から serving topology、batching、cache、observability、cross-DC inference に戻っている。実際の競争力は、model leaderboard より latency、throughput、cost、replayable traces から生まれる。

## Toolchain & Repositories

### mcp-use は MCP tool output を React UI widgets に押し上げた
- 初出日：2026-04-26
- テーマ：Toolchain & Repositories
- リンク：<https://manufact.com/docs/typescript/server/ui-widgets>
- 要約：`mcp-use` の UI widgets は、MCP tool registration と React component delivery を同じ resource directory に統合する。`.tsx` ファイルは model-callable tool になり、同時に ChatGPT Apps SDK / MCP Apps client で interactive UI として表示できる。解決しているのは engineering duplication であり、tool schema、frontend props、state view、interaction component を別々に glue code でつなぐ必要を減らしている。

### Transformers.js Chrome Extension は browser-local agent の実装テンプレートを出した
- 初出日：2026-04-23
- テーマ：Toolchain & Repositories
- リンク：<https://huggingface.co/blog/transformersjs-chrome-extension>
- 要約：Hugging Face は Gemma 4 E2B を使った Chrome extension を分解し、background service worker が model と agent lifecycle を管理し、side panel が chat UI を担い、content script が page extraction と highlight を担当する構成を示した。browser-local AI を作る team にとって、MV3 entry points、message passing、tool-call layering、reference repository がそのまま使える。

### mlinter、trace 保存、post-training test は model engineering を inspectable に戻す
- 初出日：2026-04-23
- テーマ：Toolchain & Repositories
- リンク：<https://huggingface.co/blog/mlinter>
- 要約：`mlinter` は Transformers modeling files を lint し、Save the Traces は training / inference trajectory の保存を促し、ML Intern post-training test は task-level quality gate として機能する。これらは、model と agent が複雑になるほど、static checks、trace artifacts、task-level tests が demo の印象を置き換える必要があることを示している。

### React Compiler と Playwright screencast は Agent UI loop の速度を左右する
- 初出日：2026-04-24
- テーマ：Toolchain & Repositories
- リンク：<https://react.statuscode.com/issues/471>
- 要約：React Compiler、TSRX、Rspack/Rsbuild 2.0、Playwright `page.screencast` は AI 専用 tool ではないが、agent が UI generation、refactor、testing に参加する時の feedback speed を直接左右する。Agent loop が visual verification に依存するほど、compiler、bundler、type system、test recording は engineering efficiency の一部になる。

## Research & Methodology

### Diffusion LLM は概念から production deployment issue へ進んだ
- 初出日：2026-04-22
- テーマ：Research & Methodology
- リンク：<https://blog.dailydoseofds.com/p/the-anatomy-of-diffusion-llms>
- 要約：Diffusion LLM の解説は、non-autoregressive generation、iterative denoising、token-level refinement を engineering view に戻した。すぐに mainstream autoregressive LLM を置き換えるという話ではなく、low-latency、editable generation、parallel decoding に別ルートを与える研究線として重要だ。

### RL foundation と reward-free fine-tuning は post-training の主線に戻った
- 初出日：2026-04-25
- テーマ：Research & Methodology
- リンク：<https://www.dailydoseofds.com/rl-course-part-1/>
- 要約：Daily Dose の RL foundations は、bandit、reward、policy、credit assignment、exploration-exploitation から直觉を作り直している。同週の “How to Fine-Tune LLMs in 2026” は GRPO、RULER、reward-free RL を LLM post-training の文脈に置いた。Prompt だけでなく、reward signal が behavior をどう形作るかを理解する必要がある。

### DenseOn / LateOn と RBF Kernel は similarity learning を基盤に戻した
- 初出日：2026-04-22
- テーマ：Research & Methodology
- リンク：<https://huggingface.co/blog/denseon-lateon>
- 要約：DenseOn / LateOn は single-vector と multi-vector retrieval の新しい open model として、RAG の recall と reranking に直接効く。RBF Kernel の導出は infinite-dimensional feature space で kernel trick を説明し直す。片方は modern retrieval、もう片方は classic methodology だが、どちらも similarity function と representation learning が AI application の底座であることを示している。

### QIMMA と Noetik TARIO-2 は benchmark と task definition の重要性を示した
- 初出日：2026-04-21
- テーマ：Research & Methodology
- リンク：<https://huggingface.co/blog/qimma>
- 要約：QIMMA は Arabic benchmark の品質を先に検証し、その上で model ranking を議論する。Noetik TARIO-2 は Transformer を cancer clinical trial matching という失敗率の高い task に投入した。どちらも、役に立つ AI research には model swap だけでなく、task definition、data quality、evaluation standard、error analysis の再設計が必要だと示している。
