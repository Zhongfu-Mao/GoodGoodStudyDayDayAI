# 本周范围

- 时间窗口：2026-05-25 ~ 2026-05-31
- 覆盖日报：2026-05-25 至 2026-05-31 各期

# 趋势卡片

- Agent 工程的关键词从“会调用工具”转向“可评测、可恢复、可审计、可交付”，DoorDash、Braintrust、OpenAI、Cisco、Tax AI 与 Warp 都在展示生产闭环。
- Deep Research、向量索引、文档解析、RAG / Graph RAG / Agentic RAG 说明，agent 的基础能力越来越依赖检索层、上下文工程和输入质量。
- 评测与治理成为公开叙事中心：第三方评测 playbook、LLM-as-judge、ITBench-AA、OpenAI election safeguards、Rosalind Biodefense 都在把 claim、harness、预算和责任边界讲清楚。
- 组织采用从“每人一个 agent”降温，转向 compound engineering、AI Forward Deployed Engineer、Codex workflow、Cursor habits 和可复用插件。
- GitHub 热门项目集中在 agent harness、研究工作台、Agentic RAG、轻量文档解析、语音 / 训练 / 评测工具，说明开发者侧正在把方法论沉淀成可运行系统。

## Agent 系统与生产闭环

### DoorDash、Tax AI 与 Braintrust 把 agent 改进做成可观测飞轮
- **发布日期**：2026-05-28 至 2026-05-30
- **主题**：评测飞轮与生产反馈
- **链接**：[DoorDash LLM evaluation](https://careersatdoordash.com/blog/how-doordash-built-a-testing-system-to-evaluate-llms/)
- **摘要**：DoorDash 用模拟对话、LLM-as-judge 和人工复核降低客服 LLM 幻觉；OpenAI、Thrive 与 Crete 的 Tax AI 案例把用户编辑、重试和生产痕迹变成后训练数据；Braintrust 则把客户请求转成 Codex 可执行实验和代码改动。共同趋势是，agent 产品不再依赖一次性 prompt，而是通过 trace、评测、人工反馈和可预览分支持续改进。

### Codex 从助手变成企业工程流程的一部分
- **发布日期**：2026-05-27 至 2026-05-31
- **主题**：Coding agent 采用
- **链接**：[OpenAI Codex customer stories](https://openai.com/codex/)
- **摘要**：Cisco、Endava、Braintrust 与 The Rundown 的 Codex /goal 示例都指向同一件事：coding agent 的价值不只是补全代码，而是进入需求拆解、构建日志分析、跨仓库修复、评审、预览和交付节奏。Cursor habits report 又从团队行为层显示，采用差距往往来自 review loop、任务边界和组织方法，而不是模型按钮本身。

### Warp Oz 与 Onyx Deep Research 把 agent 控制面和研究流程继续开源化
- **发布日期**：2026-05-25 至 2026-05-28
- **主题**：Agent 控制面
- **链接**：[Onyx Deep Research lessons](https://www.onyx.app/blog/lessons-from-building-deep-research)
- **摘要**：Onyx 的经验显示，强 research agent 不一定要把更多工具塞给 coordinator，而是要隔离研究 worker、明确上下文边界和结果合并方式。Warp 的 Oz 把本地终端、云端 agent 和开源协作连成控制面。二者都说明，agent workflow 的竞争点正在移向任务编排、状态展示、权限边界和协作接口。

## 检索、上下文与数据层

### CockroachDB C-SPANN 让向量索引继承分布式数据库语义
- **发布日期**：2026-05-25 至 2026-05-26
- **主题**：向量索引与事务系统
- **链接**：[CockroachDB vector indexing](https://www.cockroachlabs.com/blog/vector-search-indexing/)
- **摘要**：C-SPANN 把向量索引作为分布式 SQL 系统里的普通表数据处理，继续承载事务、分区、多租户和地域合规语义。它提醒我们，RAG 与 agent memory 不能只谈 embedding 和相似度，真正的生产问题是索引如何进入已有数据系统的隔离、恢复、权限和运维模型。

### RAG、Graph RAG、Agentic RAG 的分工变成工程决策
- **发布日期**：2026-05-28 至 2026-05-30
- **主题**：检索系统设计
- **链接**：[RAG vs. Graph RAG vs. Agentic RAG](https://www.dailydoseofds.com/p/rag-vs-graph-rag-vs-agentic-rag)
- **摘要**：Daily Dose 把普通 RAG、Graph RAG 与 Agentic RAG 放在不同查询类型下比较；liteparse、ONNX、Transformer Lab 与 Qwen 3 Agentic RAG 教程则从文档解析、模型转换、训练评测和私有部署补齐工具链。检索正在从单一向量库问题转向输入结构、关系建模、工具调用和部署路径的组合问题。

### Backend context engineering 开始直接影响 coding-agent 成本
- **发布日期**：2026-05-27 至 2026-05-29
- **主题**：上下文工程
- **链接**：[InsForge](https://github.com/InsForge/InsForge)
- **摘要**：InsForge 案例说明，把后端 schema、API、数据状态和执行反馈以 agent 友好的方式暴露出来，可以减少盲搜和 token 浪费。它与 Firecracker microVM、Vercel Hive、agent crash recovery 形成同一条工程线：模型之外的运行环境、上下文接口和恢复点，正在决定 agent 是否能长期稳定工作。

## 评测、恢复与治理

### 第三方评测 playbook 把模型 claim 拉回可审计结构
- **发布日期**：2026-05-29 至 2026-05-30
- **主题**：评测治理
- **链接**：[OpenAI third-party evaluations](https://openai.com/index/third-party-evaluations/)
- **摘要**：OpenAI 要求第三方评测说明 claim、task、harness、预算、失败案例和限制条件。ITBench-AA 又提醒，前沿模型在企业 SRE 根因定位上仍低于 50%。评测正在从排行榜和 marketing claim 变成工程审计：到底测了什么、花了多少钱、哪些失败能复现，已经比单个分数更重要。

### Agent crash recovery 要保存决策链，而不只是保存数据库状态
- **发布日期**：2026-05-29 至 2026-05-31
- **主题**：恢复与状态一致性
- **链接**：[Why Agent Crashes Are Nothing Like Database Crashes](https://www.dailydoseofds.com/p/why-agent-crashes-are-nothing-like)
- **摘要**：Agent crash 不像数据库 crash，因为恢复点不仅要包含数据，还要包含决策链、tool trace、上下文窗口、计划、已验证假设和未完成动作。这个观点解释了为什么 long-running agent 需要 checkpoint、resume、branch、human review 和可读日志，而不是只靠重新运行 prompt。

### 安全与公共责任从模型发布延伸到应用场景
- **发布日期**：2026-05-25 至 2026-05-30
- **主题**：安全、合规与高责任场景
- **链接**：[OpenAI election integrity](https://openai.com/index/2026-election-integrity/)
- **摘要**：Project Glasswing、Perplexity Bumblebee、OpenAI 选举安全、Rosalind Biodefense、Boston Children’s Hospital 和教宗关于 AI 伦理的公开立场，把 AI 治理放进漏洞披露、终端供应链、公共卫生、医疗运营和民主流程。行业正在把“模型能做什么”改写成“在哪些边界内可以负责任地做”。

## GitHub 与工具链趋势

### Agent harness、research workbench 与 Agentic RAG 模板成为开发者高频方向
- **发布日期**：2026-05-29 至 2026-05-31
- **主题**：GitHub 趋势
- **链接**：[revfactory/harness](https://github.com/revfactory/harness)
- **摘要**：revfactory/harness、transformerlab-app、ai-engineering-hub、CopilotKit、Comet Opik、Onyx、liteparse、ONNX 与 Firecracker 的共同点，是把抽象方法做成可运行的工具层。GitHub 趋势显示，agent 工程的下一波开源价值不在“再包一层聊天 UI”，而在评测、恢复、文档解析、实验管理和安全隔离。

- **发布日期**：2026-05-25 至 2026-05-26
- **主题**：可信工具链
- **链接**：[AlphaProof Nexus results](https://github.com/google-deepmind/alphaproof-nexus-results)
- **摘要**：AlphaProof Nexus 公开可检查结果，Bumblebee 只读扫描开发者机器暴露面，ONNX / ONNX Runtime 继续承担训练框架与运行时之间的契约层。这些项目都不抢眼，但它们构成了 production AI 的底座：证明可检查、风险可扫描、模型可移植。
