# 本周范围

- 时间窗口：2026-05-11 ~ 2026-05-17
- 覆盖日报：2026-05-11 至 2026-05-17 各期

# 趋势卡片

- Agent 工程的主线从“是否能调用工具”转向 runtime、trace、harness、memory、sandbox、gateway、权限和长期委托可靠性。
- Codex、GitHub Copilot App、VS Code Agents、Copilot Memory 与 Copilot metrics 共同显示，coding agent 正在进入组织级开发工作流。
- 企业数据与 RAG 的重点落在 document-level ACL、cross-account query、Unity Catalog lineage、EnterpriseRAG-Bench 与 Graphiti 这类可治理数据层。
- 模型与基础设施同时向低延迟、低抖动、高利用率、专用数据层和非默认硬件路线发展，Cerebras、NVIDIA、HF batching、mimalloc 都属于这条线。
- 采用侧的信号更偏组织和制度：Anthropic / PwC、Gates Foundation、Sea / Shopee、OpenAI / Malta 都说明 AI 进入培训、治理、公共服务和业务流程。

## Agent runtime 与自改进闭环

### LangChain 把 trace、SmithDB、Engine、Gateway 和 Sandboxes 组成 Agent 平台栈
- **发布日期**：2026-05-15
- **主题**：Agent runtime 与自改进闭环
- **链接**：[LangChain Interrupt 2026 overview](https://www.langchain.com/blog/interrupt-2026-overview)
- **摘要**：本周 LangChain 连续释放 Labs、SmithDB、LLM Gateway、LangSmith Engine、Managed Deep Agents、Context Hub 和 Sandboxes 等信号。共同主线是 Agent 平台正在从框架库升级为运行系统：trace 进入专用数据库，失败进入聚类和修复建议，成本 / PII / 审计进入 gateway，AGENTS.md、skills 和 sandbox 变成可管理对象。

### LangGraph DeltaChannel 与 Deep Agents 0.6 把长运行 Agent 状态改成增量事件
- **发布日期**：2026-05-13
- **主题**：Agent runtime 与自改进闭环
- **链接**：[LangGraph DeltaChannel](https://github.com/langchain-ai/langgraph)
- **摘要**：DeltaChannel 与 Deep Agents 0.6 代表同一类工程方向：长链路 Agent 不能一直保存全量快照，而要把状态变化、tool call、streaming output 与 checkpoint 做成增量事件。这样才可能降低存储膨胀，改善回放和审计，并让人类在长任务中插入复核点。

### Microsoft DELEGATE-52 把长时委托可靠性从体验问题变成诊断基准
- **发布日期**：2026-05-15
- **主题**：Agent runtime 与自改进闭环
- **链接**：[Microsoft Research: AI delegation and long-horizon reliability](https://www.microsoft.com/en-us/research/blog/further-notes-on-our-recent-research-on-ai-delegation-and-long-horizon-reliability/)
- **摘要**：DELEGATE-52 用多轮 transformation-and-inversion 测试模型在文档、表格、代码和结构化文件里是否保留语义。结果显示部分前沿模型在 20 轮委托后出现明显 artifact fidelity degradation，而 Python 工作流平均低于 1%。这提醒团队：长时 Agent 需要专门评测语义漂移、可逆性和复核机制，不能只看短题准确率。

### Codex 从移动端、Windows sandbox 和职能模板进入日常工作流
- **发布日期**：2026-05-15
- **主题**：开发工具与组织工作流

- **摘要**：本周 Codex 线索从开发机扩展到移动端控制、Windows sandbox、Sea / Shopee 工程实践，以及业务运营、数据科学、销售等职能模板。最重要的变化是 Codex 不再只代表“让 AI 写代码”，而是代表一个能读取真实上下文、生成可审阅 artifact、支持远程接管和组织 workflow 的工作层。

### GitHub Copilot App、Memory、usage metrics 和模型路由把 coding agent 做成组织系统
- **发布日期**：2026-05-15

### CoreWeave Sandboxes 与 agent debugging stack 把执行隔离变成默认能力
- **发布日期**：2026-05-15
- **主题**：开发工具与组织工作流

- **摘要**：CoreWeave Sandboxes、LangSmith Sandboxes 与本地 agent debugging stack 都指向同一需求：Agent 需要能安全执行代码、破坏性命令和工具调用，同时保留 trace 给评测与修复系统使用。沙箱不再只是安全附加项，而是 RL、tool use、coding agent 和自动评测的共同底座。

## 企业数据、权限与治理

### Amazon Quick 的 S3 ACL 和跨账号 Athena 把企业知识访问做成可审计边界
- **发布日期**：2026-05-15
- **主题**：企业数据、权限与治理
- **链接**：[Amazon Quick S3 knowledge base ACL](https://aws.amazon.com/blogs/machine-learning/restrict-access-to-sensitive-documents-in-your-amazon-quick-knowledge-bases-for-amazon-s3/)
- **摘要**：Amazon Quick 支持 S3 knowledge base document-level ACL，同时新增 cross-account Athena access。前者解决“谁能看到哪份文档”，后者解决“中央分析入口如何访问业务账号数据、成本归属和审计”。这两条共同说明，企业 RAG / BI Agent 的核心已经从接入数据转向身份链、权限传播、默认拒绝、成本归属和 CloudTrail 可追溯。

### EnterpriseRAG-Bench、Graphiti 与 Unity Catalog lineage 让 RAG 从检索准确率进入数据系统问题
- **发布日期**：2026-05-12
- **主题**：企业数据、权限与治理
- **链接**：[Graphiti](https://github.com/getzep/graphiti)
- **摘要**：EnterpriseRAG-Bench 暴露向量检索在大规模企业语料里的召回塌缩，Graphiti 用双时间知识图谱补足实时 RAG 的时态缺口，Unity Catalog + SageMaker 的微调流程则强调跨服务 lineage。三者合起来说明：企业 AI 的答案质量取决于资产发现、时间语义、权限和数据血缘，而不是单一 embedding 模型。

### AWS 与 Cisco AI Defense 将 MCP、A2A、Agent Skills 纳入供应链扫描
- **发布日期**：2026-05-13
- **主题**：企业数据、权限与治理
- **链接**：[AWS and Cisco AI Defense](https://aws.amazon.com/blogs/machine-learning/securing-ai-agents-how-aws-and-cisco-ai-defense-scale-mcp-and-a2a-deployments/)
- **摘要**：MCP server、A2A agent 和 Agent Skill 的增长带来 tool sprawl、security review bottleneck 和 audit gap。AWS-backed AI Registry 与 Cisco AI Defense 的组合把注册、发现、YARA / LLM / proprietary scanning、自动 disabled 和 admin review 串成治理流程。这是 Agent 生态从开放扩展进入企业供应链安全阶段的标志。

## 模型、推理基础设施与系统性能

### Databricks OfficeQA Pro、MDASH 与 Artificial Analysis 把评测对象从模型扩展到 harness
- **发布日期**：2026-05-16
- **主题**：模型、推理基础设施与系统性能
- **链接**：[Microsoft MDASH](https://www.microsoft.com/en-us/security/blog/)
- **摘要**：Databricks 用 OfficeQA Pro 测企业文档 Agent，Microsoft MDASH 强调安全 Agent 的 harness，Artificial Analysis 把 coding agent 评测对象从模型扩展到 harness + model。评测的重点正在从“哪个模型分数高”转向“在真实工具、文件、权限、任务链和验证器中，系统是否稳定完成工作”。

### NVIDIA Vera Rubin、HF continuous batching 与 mimalloc 指向推理基础设施的细节竞争
- **发布日期**：2026-05-16
- **主题**：模型、推理基础设施与系统性能
- **链接**：[Microsoft Research mimalloc](https://www.microsoft.com/en-us/research/blog/mimalloc-a-high-performance-scalable-memory-allocator-for-the-modern-era/)
- **摘要**：NVIDIA 把 agentic 推理定义成低抖动、长上下文和跨芯片调度问题；Hugging Face 用异步 continuous batching 把 GPU 利用率推到 99.4%；Microsoft mimalloc 则提醒 allocator、cache locality 和 cross-thread memory sharing 仍然决定大服务延迟。推理基础设施竞争已经进入硬件、runtime、batching、内存分配器和服务架构共同优化阶段。

### Cerebras IPO 与非默认硬件路线让 inference economics 被重新定价
- **发布日期**：2026-05-16
- **主题**：模型、推理基础设施与系统性能
- **链接**：[Latent Space: Cerebras IPO](https://www.latent.space/p/ainews-cerebras-60b-ipo-slowly-then)
- **摘要**：Cerebras 上市后的市场反应说明，推理时代正在重新评估非 NVIDIA 默认架构。最稳妥的解读不是 Cerebras 已经证明全面胜出，而是市场需求更接近其 wafer-scale thesis：frontier inference 的成本、延迟、供给、利用率和路由正在成为资本和工程共同关注的问题。
