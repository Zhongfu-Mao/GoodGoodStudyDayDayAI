# 今週の範囲

- 対象期間：2026-05-04 〜 2026-05-10
- 対象日報：2026-05-04 から 2026-05-10 までの各日報

# トレンドカード

- Agent 工学は「ツールを呼べるか」から、runtime、権限、記憶、checkpoint、ブラウザ/デスクトップ接続、安全監査まで含むシステム設計へ進んでいる。
- 評価は本番インフラになりつつある。ProgramBench、OBLIQ-Bench、Terminal-Bench、ByteByteGo の eval recipe は、grader、タスクデータ、失敗再現を工程資産として扱う流れを示した。
- モデル最前線では、低 active parameter の MoE、リアルタイム音声、多モーダル医療、訓練効率が同時に進み、会話能力だけでなく場面別のデプロイ能力が競争軸になっている。
- 企業 RAG とデータ Agent のボトルネックは、検索リコール、業務語彙、資産発見、権限、検証可能な回答に移っている。
- AI 商業化はインフラ段階へ入った。計算資源提携、従量課金、健康データ入口、政府契約、組織再編が、AI を企業のコスト構造とリスク構造そのものにしている。

## モデルリリース & システム

### GPT-Realtime-2 は GPT-5 級の推論をリアルタイム音声 Agent に入れる
- **公開日**：2026-05-08
- **テーマ**：モデルリリース & システム
- **リンク**：[OpenAI リアルタイム音声モデル](https://openai.com/index/advancing-voice-intelligence-with-new-models-in-the-api/)
- **要約**：GPT-Realtime-2、GPT-Realtime-Translate、GPT-Realtime-Whisper は、リアルタイム音声、ストリーミング文字起こし、翻訳、ツール呼び出しを同じ API ラインにまとめています。128K context と Big Bench Audio 96.6% という結果は、音声 Agent が単なる会話 UI から、聞きながら推論し、必要に応じてツールを呼ぶ生産システムへ近づいていることを示します。

### EMO と ZAYA 系列は MoE 競争が低 active cost へ向かうことを示す
- **公開日**：2026-05-08
- **テーマ**：モデルリリース & システム
- **リンク**：[EMO on Hugging Face](https://huggingface.co/blog/allenai/emo)
- **要約**：Ai2 EMO は文書レベルの弱教師ありで専門家モジュールを自然に形成し、ZAYA1-74B / ZAYA1-VL-8B は active parameter を抑えた MoE 路線を広げています。両者の共通点は、開放モデルの競争が総パラメータだけでなく、高並行、本地デプロイ、多モーダル利用でのコスト弾性へ移っていることです。

### OncoAgent は Corrective RAG、二層モデル、HITL を腫瘍意思決定支援に組み込む
- **公開日**：2026-05-09
- **テーマ**：モデルリリース & システム
- **リンク**：[OncoAgent on Hugging Face](https://huggingface.co/blog/lablab-ai-amd-developer-hackathon/oncoagent-official-paper)
- **要約**：OncoAgent は 8 ノードの LangGraph、4 段階 Corrective RAG、3 層 Reflexion safety validator、強制 HITL gate を使う腫瘍臨床意思決定支援システムです。ローカルデプロイ、Zero-PHI、ガイドライン追跡性、モデルルーティングをまとめており、医療 Agent が demo から規制対象の業務フローへ進む代表的なシグナルです。

## アーキテクチャ & エンジニアリング范式

### Claude Code vs. OpenClaw は Agent runtime の違いを明確にする
- **公開日**：2026-05-09
- **テーマ**：アーキテクチャ & エンジニアリング范式
- **リンク**：[ByteByteGo: Claude Code vs. OpenClaw](https://blog.bytebytego.com/p/ep214-claude-code-vs-openclaw-5-design)
- **要約**：ByteByteGo は Claude Code と OpenClaw を scope、runtime、extension、memory、routing の 5 軸で比較しています。Claude Code は短命のタスクプロセスに近く、OpenClaw は常駐 daemon + gateway + queue に近い。この比較は、coding agent の差分をモデル性能ではなく、実行環境、キュー、記憶境界、プラグイン登録表として捉え直します。

### Firefox の agentic security harness はモデル監査を脆弱性ライフサイクルに接続する
- **公開日**：2026-05-08
- **テーマ**：アーキテクチャ & エンジニアリング范式
- **リンク**：[Mozilla Hacks: hardening Firefox](https://hacks.mozilla.org/2026/05/behind-the-scenes-hardening-firefox/)
- **要約**：Mozilla はモデルの報告をそのまま保守者へ渡すのではなく、harness に再現可能なテストケースを作らせ、重複排除、割り当て、修正、リリースの流れへ接続しています。Firefox 150 関連では 271 件の bug がモデルによって識別されており、安全 Agent の価値が単発スキャンではなく、再現性と既存プロセスへの統合にあることを示します。

### vLLM + Mooncake と OpenAI MRC は AI インフラをプロトコル層へ押し上げる
- **公開日**：2026-05-08
- **テーマ**：アーキテクチャ & エンジニアリング范式
- **リンク**：[Mooncake on arXiv](https://arxiv.org/abs/2407.00079)
- **要約**：vLLM + Mooncake は Agent prefix cache のヒット率を 92% まで押し上げ、OpenAI MRC は大規模訓練ネットワークの障害復旧をプロトコル層の能力として扱います。AI Infra の競争は、キャッシュ、ネットワーク復旧、prefill/decode 分離、ハードウェアトポロジーの最適化まで降りてきています。

### 企業データ Agent の核心は資産発見、業務語彙、検証ループにある
- **公開日**：2026-05-09
- **テーマ**：アーキテクチャ & エンジニアリング范式
- **リンク**：[Latent Space: AI News](https://www.latent.space/p/ainews-anthropic-growing-10xyear)
- **要約**：Databricks Genie の実践は、企業データ Agent のボトルネックを資産発見、衝突する業務文脈、決定論的テストの不足、複数モデル協調に分解しています。企業 Agent の本当の難しさは、モデルが SQL を書けるかではなく、正しいデータを見つけ、組織の口径を理解し、検証可能な答えを出せるかにあります。

## ツールチェーン & リポジトリ

### ProgramBench は完全なソフトウェア再構築を AI Coding Agent の新しい試験にする
- **公開日**：2026-05-10
- **テーマ**：ツールチェーン & リポジトリ
- **リンク**：[ProgramBench 解説](https://lukefan.com/2026/05/10/programbench-ai-software-reconstruction-benchmark/)
- **要約**：ProgramBench はモデルに実行ファイルと使用文書を渡し、振る舞いを探索して完全なプログラムを再構築させます。9 つのモデルは 200 個の実ソフトウェア、248,853 個のテスト項目で、1 つのソフトウェアも完全通過できませんでした。次の Coding Agent 競争が、長期計画、振る舞い探索、自動テスト、記憶、ツールチェーン協調に向かうことを示しています。

### CrewAI checkpointing は長い Flow を復旧・分岐可能な状態にする
- **公開日**：2026-05-08
- **テーマ**：ツールチェーン & リポジトリ
- **リンク**：[Daily Dose of Data Science](https://blog.dailydoseofds.com/p/a-smarter-claude-model-burns-more)
- **要約**：CrewAI v1.14 は Flow の各メソッドを保存可能な checkpoint にし、任意の保存状態から復旧または分岐できるようにしました。長い Agent ワークフローでは、checkpoint は単なるデバッグ補助ではなく、人間との協働、失敗復旧、実験分岐管理の基盤になります。

### CyberSecQwen-4B はセキュリティ小型モデルのデプロイ可能な道筋を示す
- **公開日**：2026-05-08
- **テーマ**：ツールチェーン & リポジトリ
- **リンク**：[CyberSecQwen-4B on Hugging Face](https://huggingface.co/blog/lablab-ai-amd-developer-hackathon/cybersecqwen-4b)
- **要約**：CyberSecQwen-4B は CWE 分類、CVE-to-CWE マッピング、CTI QA を対象にし、12GB 級 GPU でもローカル実行できます。LoRA、ROCm、vLLM serving、transformers 推論例も示しており、防御側セキュリティ小型モデルが研究基線から実装可能なツールチェーンへ近づいています。

### Spotify Save to Spotify CLI は Agent の出力を既存の音声配信システムに入れる
- **公開日**：2026-05-07
- **テーマ**：ツールチェーン & リポジトリ
- **リンク**：[Spotify Personal Podcasts](https://newsroom.spotify.com/2026-05-07/personal-podcasts-launch/)
- **要約**：Spotify の Save to Spotify beta tool により、デスクトップ Agent は予定の要約、学習ルート、授業ノートなどを Personal Podcast として生成し、ユーザーの Library に保存できます。価値は音声ファイルを生成することではなく、Agent の出力を既存の再生、保存、複数デバイス配信の仕組みに入れることです。

## 研究 & 方法論

### Direct Corpus Interaction は「標準でベクトルDB」という RAG 形式を問い直す
- **公開日**：2026-05-09
- **テーマ**：研究 & 方法論
- **リンク**：[Latent Space: AI News](https://www.latent.space/p/ainews-anthropic-growing-10xyear)
- **要約**：Direct Corpus Interaction は、モデルが grep、find、bash などの道具で原始コーパスへ直接アクセスする方法を提案し、embedding + top-k 検索を唯一の標準にしない姿勢を示します。実運用の RAG は、ベクトル検索、疎検索、ファイルシステム道具、コード的なアクセスを組み合わせる方向へ進みそうです。

### Benchmark 設計は「タスクが完全か」と「ソフトウェアを再構築できるか」を見るようになった
- **公開日**：2026-05-05
- **テーマ**：研究 & 方法論
- **リンク**：[Meta FAIR Autodata](https://ai.meta.com/research/publications/autodata-automated-data-engineering-for-ai-research/)
- **要約**：今週の OBLIQ-Bench、Terminal-Bench 2.1、Harvey LAB、ProgramBench は、評価を単発正答率からより現実的なタスク構造へ移しています。新しい問いは、モデルが条件不足を認識できるか、ブラックボックスの振る舞いを探索できるか、テストを作って継続的に修正できるかです。

### Open ASR Leaderboard は非公開テストセットを音声認識評価に入れる
- **公開日**：2026-05-07
- **テーマ**：研究 & 方法論
- **リンク**：[Open ASR Leaderboard](https://huggingface.co/spaces/hf-audio/open_asr_leaderboard)
- **要約**：Open ASR Leaderboard は非公開データセットを追加し、benchmark への過適合や benchmaxxing を抑えようとしています。この動きは生成 AI 評価全体にも示唆があります。モデルとデータリークの区別が難しくなるほど、評価基盤には隠しテスト、再評価、タスク単位の説明が必要になります。
