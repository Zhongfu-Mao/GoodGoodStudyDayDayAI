# 今週の範囲

- 対象期間：2026-04-27 〜 2026-05-03
- 対象 Daily：2026-04-27 〜 2026-05-03 の各号

# トレンドカード

- Agent engineering の焦点は「ツールを呼べるか」から、runtime、権限、記憶、検索、pause/resume、そして cross-tool skills の体系設計へ移っています。
- オープンモデル競争は、チャット性能だけでなく、長文脈、coding agent、低ビット学習、多モーダル、edge inference を含む総合的な deployment 能力の競争になっています。
- 評価が新しいボトルネックです。RULER、GEPA、BARRED、Hugging Face の評価コスト分析はいずれも、reward、eval、安全レビューを production engineering の一部として扱う必要性を示しています。
- AI compute の商業モデルが変わっています。DeepSeek V4 の価格、Copilot の usage-based billing、クラウド企業の Capex、agent fraud は、compute が新しい cash constraint になっていることを示します。
- AI はより現実的な産業システムへ入り始めています。医療画像、自動運転、車載システム、推薦、決済リスク管理では、latency、reliability、責任境界が前面に出ています。

![AI evaluation cost chart](https://cdn-uploads.huggingface.co/production/uploads/6413251362e6057cbb6259bd/C7hWgk9B5aCrUE_c0TSzF.png)

*代表画像は [Hugging Face / EvalEval Coalition の AI 評価コスト分析](https://huggingface.co/blog/evaleval/eval-costs-bottleneck) より。今週の主線は単独のモデル発表ではなく、Agent 能力が実務に入るほど runtime、evaluation、cost、安全性が同時に可用性を決める、という点です。*

## モデルリリース & システム

### DeepSeek V4 Pro / Flash は長文脈、低コスト、Agent workload を結びつけた
- **初出日**：2026-04-28
- **テーマ**：モデルリリース & システム
- **リンク**：[DeepSeek-V4 技術解説](https://huggingface.co/blog/deepseekv4)
- **要約**：DeepSeek V4 の 1M context、CSA/HCA hybrid attention、Pro / Flash の階層化は、長文脈を単なる容量指標ではなく、coding agent、GUI agent、多ツール workflow 向けの deployment constraint として位置づけました。さらに価格面のシグナルが加わり、低い input price と cache hit cost によって長時間 Agent の economics が大きく変わり始めています。

### Qwen3.6、Kimi K2.6、Grok 4.3 はオープンモデルを長時間 Agent 競争へ押し出した
- **初出日**：2026-05-02
- **テーマ**：モデルリリース & システム
- **リンク**：[AINews: AI Engineer World's Fair](https://www.latent.space/p/ainews-ai-engineer-worlds-fair-autoresearch)
- **要約**：Qwen3.6 27B、Kimi K2.6、Grok 4.3 に共通するのは、長いタスク、tool calling、agent swarm、価格効率、信頼性指標が競争軸になっていることです。単発 benchmark よりも、長い実行の中で context を保ち、失敗を検知し、cost を制御できるかが重要になっています。

### Granite 4.1 と Falcon-E は小型オープンモデルにも実務上の余地が大きいことを示す
- **初出日**：2026-04-30
- **テーマ**：モデルリリース & システム
- **リンク**：[IBM Granite 4.1](https://huggingface.co/blog/ibm-granite/granite-4-1)
- **要約**：IBM Granite 4.1 は、15T token の段階的学習、512K context 拡張、GRPO post-training により、3B / 8B / 30B dense model を透明性のある enterprise base として提示しました。Falcon-E の 1.58-bit ternary LLM も、低ビット学習をコミュニティで再現可能な方向へ進めています。最大規模だけでなく、訓練経路、deployment cost、hardware fit が価値になります。

## アーキテクチャ & エンジニアリング・パラダイム

### MCP、Skills、Compound Engineering が Agent platform の三層構造を作り始めている
- **初出日**：2026-05-03
- **テーマ**：アーキテクチャ & エンジニアリング・パラダイム
- **リンク**：[MCP vs Skills, Clearly Explained](https://blog.bytebytego.com/p/ep213-mcp-vs-skills-clearly-explained)
- **要約**：MCP は realtime system connection、schema、permission boundary に向き、Skills は再利用可能な作業知識に向きます。Compound Engineering plugin は、script、skills、project convention を IDE をまたいだ組織資産としてまとめる方向です。platform team は「何に接続するか」「何を許可するか」「経験をどう再利用するか」を分けて設計する必要があります。

### LangGraph と Cloudflare は Agent runtime を session tool から durable execution へ進めている
- **初出日**：2026-05-03
- **テーマ**：アーキテクチャ & エンジニアリング・パラダイム
- **リンク**：[AINews: AI Engineer World's Fair](https://www.latent.space/p/ainews-ai-engineer-worlds-fair-autoresearch)
- **要約**：LangGraph は multi-user data isolation、delegated credentials、operator RBAC、human intervention、pause/resume を重視し、Cloudflare Dynamic Workflows は agent plan に durable execution を持ち込みました。実運用上の差分は、tool calling そのものより、sandbox、checkpoint、permission、audit、failure recovery が制御可能かどうかに移っています。

### ReaLM-Retrieve と OCR-Memory は長期 Agent の検索と記憶を再設計する
- **初出日**：2026-05-03
- **テーマ**：アーキテクチャ & エンジニアリング・パラダイム
- **リンク**：[AINews: AI Engineer World's Fair](https://www.latent.space/p/ainews-ai-engineer-worlds-fair-autoresearch)
- **要約**：ReaLM-Retrieve は検索を回答前の固定 RAG 処理ではなく、推論途中に必要に応じて呼ぶ action として扱います。OCR-Memory は GUI / Web 操作の軌跡を視覚的な記憶として保存します。長期 Agent には、context を増やすだけでなく、いつ検索し、何を検索し、どの証拠を残すかという runtime strategy が必要です。

### 推論の焦点は GPU だけでなく CPU、sandbox、routing layer まで広がった
- **初出日**：2026-04-30
- **テーマ**：アーキテクチャ & エンジニアリング・パラダイム
- **リンク**：[AINews: The Inference Inflection](https://www.latent.space/p/ainews-the-inference-inflection)
- **要約**：今週の inference 議論は prefill / decode を超え、CPU、sandbox、code execution environment、Agent scheduling まで広がりました。DeepInfra が Hugging Face routing ecosystem に入ったことも、推論層が platform 化していることを示します。企業には model API だけでなく、cost routing、isolation、monitoring、long-running task governance が必要になります。

## ツールチェーン & リポジトリ

### GEPA、RULER、BARRED は Agent 最適化を scalar reward から trajectory、ranking、専用 evaluator へ移す
- **初出日**：2026-05-02
- **テーマ**：ツールチェーン & リポジトリ
- **リンク**：[GEPA: Reflective Prompt Evolution Can Outperform Reinforcement Learning](https://arxiv.org/abs/2604.06331)
- **要約**：GEPA は実行軌跡と reflection を使い、単一の scalar reward に頼らず prompt を改善します。RULER は open-ended task の reward を multi-trajectory ranking に変換し、BARRED は高価な general LLM-as-a-judge ではなく domain-specific evaluator を推奨します。Agent optimization は、trajectory、evaluator、cost、reliability を扱う toolchain になっています。

### Claude Security、Cursor Security Review、prompt injection defense は code generation を安全基線に戻す
- **初出日**：2026-05-02
- **テーマ**：ツールチェーン & リポジトリ
- **リンク**：[AINews: Agents for Everything Else](https://www.latent.space/p/ainews-agents-for-everything-else)
- **要約**：AI code review は生成後の後始末ではなく、generation、dependency governance、patch review、高影響操作の前に置かれる default safety layer になっています。ByteByteGo の prompt injection 整理も、Spotlighting / Instruction Hierarchy のような model-layer defense と、least privilege、human confirmation、planner / executor separation の system-layer defense を組み合わせる必要を示しています。

### OpenRA-RL と ML Intern は research task を実行可能な Agent 実験環境へ変換する
- **初出日**：2026-04-28
- **テーマ**：ツールチェーン & リポジトリ
- **リンク**：[OpenRA-RL](https://huggingface.co/blog/jadetan/openra-rl)
- **要約**：OpenRA-RL は RTS game を traditional RL と LLM Agent の両方に対応する training environment として包み、concurrent sessions、MCP tool interface、有界 channel で LLM latency に対応します。ML Intern は MATH-500 実験の設計、実装、分析を Agent が担う例です。research agent は、論文について答えるだけでなく、再現可能な実験 loop を回せるかが問われています。

### GraphRAG、Vamana、Blockify は RAG 競争を data structure layer へ押し下げている
- **初出日**：2026-05-01
- **テーマ**：ツールチェーン & リポジトリ
- **リンク**：[FalkorDB GraphRAG SDK](https://www.falkordb.com/blog/falkordb-graphrag-sdk)
- **要約**：FalkorDB GraphRAG SDK、Vamana vector search optimization、Blockify はいずれも、embedding や reranker の交換ではなく、graph structure、data layout、block representation を最適化対象にしています。RAG の次の効率改善は、モデル呼び出しの工夫よりも database / indexing engineering に近づいています。

## ビジネス & 組織

### AI compute は定額補助から利用量課金へ移り、cost governance が組織能力になる
- **初出日**：2026-05-01
- **テーマ**：ビジネス & 組織
- **リンク**：[DeepSeek V4 価格インパクト](https://lukefan.com/2026/05/01/deepseek-v4-price-cuts-disrupt-ai-agent-economics/)
- **要約**：DeepSeek V4 の低価格と cache hit 効果、Copilot / Anthropic の usage-based pricing への移行、クラウド企業の大規模 Capex は、AI cost が補助期間から精密な ledger 管理へ移っていることを示します。token burn、cache hit、model tiering、task routing、budget cap は日常運用の対象になります。

### OpenAI、Microsoft、Anthropic、Cursor の関係変化は workbench ecosystem の支配権を再配分している
- **初出日**：2026-04-29
- **テーマ**：ビジネス & 組織
- **リンク**：[OpenAI-Microsoft 関係の調整](https://www.latent.space/p/ainews-imagegen-is-on-the-path-to)
- **要約**：OpenAI と Microsoft の model distribution、Cursor の資本取引観測、Anthropic Mythos の controlled access、Codex / Claude Code / Cowork の workbench competition は、model supply、desktop entry point、enterprise data connection、developer relationship が再び結び直されていることを示します。moat は単体モデルではなく、組織がどの Agent platform に workflow、permission、history を蓄積するかに移ります。

### Robotaxi、車載 Gemini、physical AI の量産検証は現実世界システムの境界を露出させる
- **初出日**：2026-05-03
- **テーマ**：ビジネス & 組織
- **リンク**：[武漢 Robotaxi cloud failure](https://lukefan.com/2026/05/03/wuhan-baidu-robotaxi-cloud-failure/)
- **要約**：武漢の Robotaxi 事故は、クラウド依存の自動運転が network failure に弱いことを示しました。一方、Gemini が Google built-in 車載システムに入り、Figure humanoid robot が量産検証へ進む動きもあります。physical AI の論点は、demo から network redundancy、liability、manufacturing consistency へ移っています。

## 研究 & 方法論

### 医療 AI は後処理分類から、信号再構成と早期予測へ進んでいる
- **初出日**：2026-05-01
- **テーマ**：研究 & 方法論
- **リンク**：[REDMOD pancreatic cancer warning](https://huggingface.co/blog/redmod-pancreatic-cancer)
- **要約**：NV-Raw2Insights-US は医療超音波を後処理画像の分類ではなく、raw signal reconstruction の問題として扱い、REDMOD は過去画像から膵臓がんの早期シグナルを探します。医療 AI は、既成画像を分類する段階から、data generation chain と longitudinal evidence を扱う段階へ進みつつあります。

### GPT-5.5、データリーク、AlphaEvolve は evaluation design 自体の重要性を示す
- **初出日**：2026-05-03
- **テーマ**：研究 & 方法論
- **リンク**：[Every: GPT-5.5](https://every.to/vibe-check/gpt-5-5)
- **要約**：GPT-5.5 は強い実行能力と高い hallucination risk を同時に示し、random split による data leakage は見かけ上の metric を疑う必要を教え、AlphaEvolve 的な behavior inference は decision explanation の新しい方向を示します。evaluation はリリース後の表ではなく、model selection、system safety、product reliability の中心設計です。
