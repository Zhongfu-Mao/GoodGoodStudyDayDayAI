# 今週の結論

- **Harness Engineering（ハーネス・エンジニアリング）** は今週、技術トレンドの主軸として完全に定着しました。その影響はエンジニアリング記事の枠を超え、IDE、PRプロセス、メモリ管理、プラットフォーム境界、そしてワークスペース設計にまで波及しています。
- Claude Opus 4.7、Mythos、GPT-Rosalind の動向を俯瞰すると、モデル製品ラインは「高速反復するフラッグシップ版 + ゲート付きフロンティア版 + 垂直領域専用版」という三層構造へ進化しつつあります。
- プラットフォームの「入口」を巡る争いが激化しており、Codex、Windsurf、Perplexity、OpenClaw は単なるツール提供を超え、次世代 AI オペレーティングシステムの覇権を争っています。

## 1. Harness Engineering が「概念」から「共通言語」へ

- **[Evolution of Agent Landscape From 2022-26](https://blog.dailydoseofds.com/p/evolution-of-agent-landscape-from)** は、その進化の軌跡を「weights（重み） → context（文脈） → harness engineering（ハーネス工学）」として明快に定義しました。
- **[Build Agents That Never Forget](https://blog.dailydoseofds.com/p/build-agents-that-never-forget-98a)**、**[Google solved an Old RNN Problem](https://blog.dailydoseofds.com/p/google-solved-an-old-rnn-problem)**、**Notion's Token Town** といった記事は、メモリ機構、コンテキスト管理、ソフトウェアファクトリ層の実装詳細を補完しています。
- 今週の議論の中心は、エージェントが「ツールを呼べるか」ではなく、ランタイム、メモリ、ワークスペース、承認フロー、リカバリ、可観測性をどう統合・協調させるかへとシフトしました。

## 2. エージェントによるコーディング・ワークフローの体系的再構築

- **[AINews RIP Pull Requests (2005-2026)](https://www.latent.space/p/ainews-rip-pull-requests-2005-2026)**、**[Windsurf 2.0 — Agent Command Center](https://windsurf.com)**、**[10 Must-use Slash Commands in Claude Code](https://blog.dailydoseofds.com/p/10-must-use-slash-commands-in-claude)**、**[OpenAI Codex のスーパーアプリ化](https://www.therundown.ai/p/openai-superapp-hiding-inside-codex)** は、AI コーディングが単なるコード補完から、開発プロセス全体の代行へと進化していることを示しました。
- PR、レビュー、CI、承認、ワークスペース管理、マルチエージェント協調といった、従来エンジニアリングマネジメントの領域だった課題が、プロダクト設計の中核に組み込まれています。
- 前週がエージェント構成要素の定義フェーズだったとすれば、今週は「チームによるソフトウェア開発の在り方」そのものの書き換えが始まった週と言えます。

## 3. モデル市場の「三層構造」への移行

- **[Anthropic Claude Opus 4.7](https://www.latent.space/p/ainews-anthropic-claude-opus-47-literally)** は、高頻度に更新されるフラッグシップラインを代表しており、コーディング能力だけでなくビジョンや推論の粒度も大幅に向上しました。
- **Mythos** はゲート付きフロンティアモデルの形態を示しており、ラボが最強の能力をより制御されたチャネルに留める戦略の象徴となっています。
- **[OpenAI GPT-Rosalind — 初の生命科学専用モデル](https://www.therundown.ai/p/openai-superapp-hiding-inside-codex)** は第三の層、すなわち高価値産業向けの特化型モデルが現実のビジネスシーンに投入されたことを示しています。
- 単なるベンチマーク比較よりも、この三層構造を捉える方が、今後のモデル市場のプロダクト戦略を理解しやすくなります。

## 4. 推論効率、サービング・トポロジー、コスト最適化が再び核心に

- **[72 Techniques to Optimize LLMs in Production](https://blog.dailydoseofds.com/p/72-techniques-to-optimize-llms-in)** は、今週最も重要なエンジニアリングの指針となりました。実運用における真の格差は、モデルのスコアではなく、スループット、レイテンシ、コスト、安定性から生まれます。
- メモリキャッシング、最新ローカルモデルリスト、ローカルデプロイ手法、多層サービス設計といった話題は、プロダクトの競争力がシステム設計そのものによって決まることを裏付けています。
- ByteByteGo による JVM、データベース設計、サービスアーキテクチャの解説も、今週は「AIシステムをいかに効率的に稼働させるか」という文脈で重要なピースとなっています。

## 5. ガバナンス、プラットフォーム境界、ビジネスモデルによるプロダクトの逆規定

- **[Claude KYC 上線：中国開発者への影響解析](https://lukefan.com/2026/04/17/anthropic-claude-selective-kyc-china-user-crackdown/)** は、利用資格やコンプライアンスそのものがユーザー体験の重要な構成要素になり始めたことを示唆しています。
- **[Microsoft のエージェント戦略への懸念](https://lukefan.com/2026/04/16/microsoft-openclaw-ai-agent-cloud-client-tradeoffs/)** は、プラットフォーム・アーキテクチャとビジネスモデルの緊張関係が、そのままエージェント製品の設計に影響を与えることを再認識させます。
- **Perplexity Personal Computer**、**Claude Design**、**AI コンピュートへの投資シフト** などの動きは、入口争い、デザインワークフロー、資本市場のナラティブが複雑に絡み合いながら動いていることを示しています。

## 今週引き続き追うべきこと

- マルチエージェント IDE とエージェント指向ワークフローは、実際に従来の PR フローをどれだけ圧縮・効率化できるか。
- KYC、決済、地域制限といった制約が、開発者の標準的なモデル選択にどのような影響を与えるか。
- Codex、Perplexity、OpenClaw、Claude Design の中で、誰が次世代 AI オペレーティングシステムの入口を掌握するか。
