# 今週の結論

- Harness Engineering はこの週で完全に主線として定着し、engineering 記事の中だけでなく IDE、PR、memory、platform boundary、workspace design にまで広がった。
- Claude Opus 4.7、Mythos、GPT-Rosalind をまとめて見ると、モデル製品線は「高速反復する旗艦版 + gate 付き前線版 + 垂直専用版」の三層構造に入りつつある。
- Codex、Windsurf、Perplexity、OpenClaw は、単なる tool ではなく、次の AI operating system 層の入口を奪い合っている。

## 1. Harness Engineering が「概念」から「共通語」になった

- **[Evolution of Agent Landscape From 2022-26](https://blog.dailydoseofds.com/p/evolution-of-agent-landscape-from)** は、その進化線を一枚で言い切っている。weights → context → harness engineering。
- **[Build Agents That Never Forget](https://blog.dailydoseofds.com/p/build-agents-that-never-forget-98a)**、**[Google solved an Old RNN Problem](https://blog.dailydoseofds.com/p/google-solved-an-old-rnn-problem)**、**Notion's Token Town** といった記事は、memory、context management、software factory 層の実装ディテールを補った。
- 今週の議論の中心は、Agent が tool を呼べるかどうかではなく、runtime、memory、workspace、approval、recovery、observability をどう協調させるかへ移った。

## 2. Coding workflow は Agent によって体系的に書き換えられている

- **[AINews RIP Pull Requests (2005-2026)](https://www.latent.space/p/ainews-rip-pull-requests-2005-2026)**、**[Windsurf 2.0 — Agent Command Center](https://windsurf.com)**、**[10 Must-use Slash Commands in Claude Code](https://blog.dailydoseofds.com/p/10-must-use-slash-commands-in-claude)**、**[OpenAI Codex 超级 App 化](https://www.therundown.ai/p/openai-superapp-hiding-inside-codex)** は、AI coding が単なる補完ではなく workflow ごと引き受け始めていることを示した。
- PR、review、CI、approval、workspace、parallel agent 協調といった、もともと engineering management に属していた問題が product design の一部になっている。
- 前週が Agent component の定義週だったとすれば、この週は「チームはどう software を作るのか」を rewrite し始めた週だ。

## 3. モデル側は「旗艦 + gate 前線版 + 垂直専用版」の三層構造へ

- **[Anthropic Claude Opus 4.7](https://www.latent.space/p/ainews-anthropic-claude-opus-47-literally)** は、高頻度に更新される旗艦線の代表であり、coding だけでなく vision と reasoning granularity も押し上げた。
- **Mythos** は gate 付き frontier model の存在形を示しており、実験室が最強能力をより狭い配布チャネルに留める動きの象徴だ。
- **[OpenAI GPT-Rosalind — 首个生命科学专用模型](https://www.therundown.ai/p/openai-superapp-hiding-inside-codex)** は第三の層、つまり高価値産業向けの専用 model が現実のビジネスに入ってきたことを示す。
- 単なる benchmark 一覧よりも、この三層を並べた方が、今後のモデル市場の product shape を理解しやすい。

## 4. 推論効率、serving topology、コスト最適化が再び中核競争力になった

- **[72 Techniques to Optimize LLMs in Production](https://blog.dailydoseofds.com/p/72-techniques-to-optimize-llms-in)** は、この週でもっとも重要な engineering 下敷きの一つだった。実際の差は model score ではなく throughput、latency、cost、stability から生まれる。
- Memory Caching、Top Local Models List、local deployment route、多層サービス設計といった話題も、production の競争力が system design によって決まることを補強している。
- だからこそ ByteByteGo の JVM、database design、service architecture 記事群も今週は「脱線」ではなく、AI system をどう動かすかという同じ問いに接続していた。

## 5. 合規制、platform boundary、商業モデルが product を逆方向から形作り始めた

- **[Claude KYC 上线：中国开发者影响解析](https://lukefan.com/2026/04/17/anthropic-claude-selective-kyc-china-user-crackdown/)** は、利用資格そのものが product experience の一部になり始めたことを示した。
- **[微软龙虾要来了？CEO 亲自下场，为什么我却不看好？](https://lukefan.com/2026/04/16/microsoft-openclaw-ai-agent-cloud-client-tradeoffs/)** は、platform architecture と business model の緊張が、そのまま Agent product の設計に跳ね返ることを思い出させる。
- **Perplexity Personal Computer**、**Claude Design**、**Allbirds ditches sneakers for AI compute** は、入口争い、design workflow、資本市場 narrative が同時に動いていることを見せた。

## 今週引き続き追うべきこと

- 多 Agent IDE と agentic workflow は本当に従来の PR フローを圧縮するのか。
- KYC、決済、地域制限は、開発者の標準 model choice を変えるのか。
- Codex、Perplexity、OpenClaw、Claude Design の中で、次の AI operating system 入口を誰が握るのか。
