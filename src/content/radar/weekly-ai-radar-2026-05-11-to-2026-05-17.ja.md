# 今週の範囲

- 時間範囲：2026-05-11 ~ 2026-05-17
- 対象日報：2026-05-11 〜 2026-05-17 の各号

# トレンドカード

- Agent engineering の主線は「tool を呼べるか」から、runtime、trace、harness、memory、sandbox、gateway、permission、long-horizon delegation reliability へ移りました。
- Codex、GitHub Copilot App、VS Code Agents、Copilot Memory、Copilot metrics は、coding agent が organization-level developer workflow に入っていることを示します。
- Enterprise data と RAG の焦点は document-level ACL、cross-account query、Unity Catalog lineage、EnterpriseRAG-Bench、Graphiti などの governable data layer にあります。
- Model と infrastructure は low latency、low jitter、高 utilization、specialized data layer、non-default hardware route へ進んでおり、Cerebras、NVIDIA、HF batching、mimalloc が同じ線上にあります。
- Adoption signal は組織と制度寄りになりました。Anthropic / PwC、Gates Foundation、Sea / Shopee、OpenAI / Malta は、AI が training、governance、public service、business process に入ったことを示します。

## Agent runtime と self-improvement loop

### LangChain は trace、SmithDB、Engine、Gateway、Sandboxes を Agent platform stack として組み合わせた
- **発表日**：2026-05-15
- **テーマ**：Agent runtime と self-improvement loop
- **リンク**：[LangChain Interrupt 2026 overview](https://www.langchain.com/blog/interrupt-2026-overview)
- **要約**：今週の LangChain は Labs、SmithDB、LLM Gateway、LangSmith Engine、Managed Deep Agents、Context Hub、Sandboxes などを連続して出しました。共通する主線は、Agent platform が framework library から execution system に移ったことです。Trace は専用 database に入り、failure は clustering と fix proposal に進み、cost / PII / audit は gateway に入り、AGENTS.md、skills、sandbox は管理可能な object になります。

### LangGraph DeltaChannel と Deep Agents 0.6 は long-running Agent state を delta event に変える
- **発表日**：2026-05-13
- **テーマ**：Agent runtime と self-improvement loop
- **リンク**：[LangGraph DeltaChannel](https://github.com/langchain-ai/langgraph)
- **要約**：DeltaChannel と Deep Agents 0.6 は同じ engineering direction を示しています。Long-running Agent は full snapshot を保存し続けるのではなく、state change、tool call、streaming output、checkpoint を delta event として扱う必要があります。これにより storage growth を抑え、replay と audit を改善し、人間が長い task の途中で review point を入れやすくなります。

### Microsoft DELEGATE-52 は long-horizon delegation reliability を診断 benchmark にした
- **発表日**：2026-05-15
- **テーマ**：Agent runtime と self-improvement loop
- **リンク**：[Microsoft Research: AI delegation and long-horizon reliability](https://www.microsoft.com/en-us/research/blog/further-notes-on-our-recent-research-on-ai-delegation-and-long-horizon-reliability/)
- **要約**：DELEGATE-52 は multi-turn transformation-and-inversion で、model が document、spreadsheet、code、structured file の semantic content を維持できるかを測ります。一部 frontier model は 20 round の delegation 後に大きな artifact fidelity degradation を示しましたが、Python workflow は平均 1% 未満でした。Long-horizon Agent には semantic drift、reversibility、review mechanism を測る専用評価が必要で、短い benchmark だけでは足りません。

## Enterprise data、permission、governance

### Amazon Quick の S3 ACL と cross-account Athena は enterprise knowledge access を auditable boundary にする
- **発表日**：2026-05-15
- **テーマ**：Enterprise data、permission、governance
- **リンク**：[Amazon Quick S3 knowledge base ACL](https://aws.amazon.com/blogs/machine-learning/restrict-access-to-sensitive-documents-in-your-amazon-quick-knowledge-bases-for-amazon-s3/)
- **要約**：Amazon Quick は S3 knowledge base document-level ACL をサポートし、cross-account Athena access も追加しました。前者は「誰がどの document を見られるか」を扱い、後者は「central analytics entry が business account data にどう access し、cost attribution と audit をどう保つか」を扱います。Enterprise RAG / BI Agent の核心は、data access そのものから identity chain、permission propagation、deny-by-default、cost attribution、CloudTrail traceability へ移っています。

### EnterpriseRAG-Bench、Graphiti、Unity Catalog lineage は RAG を retrieval accuracy から data system 問題へ広げる
- **発表日**：2026-05-12
- **テーマ**：Enterprise data、permission、governance
- **リンク**：[Graphiti](https://github.com/getzep/graphiti)
- **要約**：EnterpriseRAG-Bench は大規模企業 corpus における vector retrieval の recall collapse を示し、Graphiti は bi-temporal knowledge graph で real-time RAG の temporal gap を補い、Unity Catalog + SageMaker workflow は cross-service lineage を強調しました。Enterprise AI の answer quality は、単一 embedding model ではなく、asset discovery、temporal semantics、permission、data lineage に依存します。

### AWS と Cisco AI Defense は MCP、A2A、Agent Skills を supply-chain scanning に入れる
- **発表日**：2026-05-13
- **テーマ**：Enterprise data、permission、governance
- **リンク**：[AWS and Cisco AI Defense](https://aws.amazon.com/blogs/machine-learning/securing-ai-agents-how-aws-and-cisco-ai-defense-scale-mcp-and-a2a-deployments/)
- **要約**：MCP server、A2A agent、Agent Skill の増加は tool sprawl、security review bottleneck、audit gap を生みます。AWS-backed AI Registry と Cisco AI Defense は registration、discovery、YARA / LLM / proprietary scanning、automatic disabled state、admin review を一つの governance flow にします。これは Agent ecosystem が open extension から enterprise supply-chain security に入るサインです。

## Model、inference infrastructure、system performance

### Databricks OfficeQA Pro、MDASH、Artificial Analysis は evaluation target を model から harness に広げる
- **発表日**：2026-05-16
- **テーマ**：Model、inference infrastructure、system performance
- **リンク**：[Microsoft MDASH](https://www.microsoft.com/en-us/security/blog/)
- **要約**：Databricks は OfficeQA Pro で enterprise document Agent を測り、Microsoft MDASH は security Agent の harness を強調し、Artificial Analysis は coding agent evaluation を model から harness + model へ広げました。Evaluation の焦点は、どの model score が高いかではなく、real tools、files、permission、task chain、validator の中で system が安定して仕事を終えられるかに移っています。

### NVIDIA Vera Rubin、HF continuous batching、mimalloc は inference infrastructure の detail competition を示す
- **発表日**：2026-05-16
- **テーマ**：Model、inference infrastructure、system performance
- **リンク**：[Microsoft Research mimalloc](https://www.microsoft.com/en-us/research/blog/mimalloc-a-high-performance-scalable-memory-allocator-for-the-modern-era/)
- **要約**：NVIDIA は agentic inference を low jitter、long context、cross-chip scheduling の問題として定義し、Hugging Face は asynchronous continuous batching で GPU utilization を 99.4% まで高め、Microsoft mimalloc は allocator、cache locality、cross-thread memory sharing が大規模 service latency を左右すると示しました。Inference infrastructure は hardware、runtime、batching、memory allocator、service architecture の共同最適化に入っています。

### Cerebras IPO と non-default hardware route は inference economics を repricing する
- **発表日**：2026-05-16
- **テーマ**：Model、inference infrastructure、system performance
- **リンク**：[Latent Space: Cerebras IPO](https://www.latent.space/p/ainews-cerebras-60b-ipo-slowly-then)
- **要約**：Cerebras 上場後の市場反応は、inference era が non-NVIDIA default architecture を再評価していることを示します。最も慎重な読み方は、Cerebras が全面的に勝ったということではなく、市場需要が同社の wafer-scale thesis に近づいたということです。Frontier inference の cost、latency、supply、utilization、routing が capital と engineering の共通関心になりました。
