# 今週の範囲

- 対象期間：2026-07-13 ~ 2026-07-19
- 対象日報：2026-07-13 から 2026-07-19

# トレンドカード

- Agent engineering は「tool を呼べる」段階から「長期稼働できる」段階へ進んだ。LLM routing、prompt caching、agentic RL、verifier runtime、SPEC.md、agent loop、sandbox、MCP、skills、browser / terminal / voice interface が、agent を復旧可能で監査しやすく、測定できる system に変えている。
- モデル競争は「能力 + 制御 + コスト」の 3 軸に入った。Kimi K3 と Inkling は open model の規模を引き上げ、GPT-Red と LLM-as-a-Verifier は評価と安全を訓練部品にし、SparDA、reasoning effort、GPT-Live、Mercury 2 は推論効率と realtime interaction を product architecture に接続した。
- Enterprise AI の指標は token price から useful work per dollar へ移る。OpenAI Scorecard、Every の workflow measurement、Codex growth、Cars24、support agent、voice lead intake は、成功 task、human handoff、operation patch、revenue / cost outcome を追う必要を示している。
- Tool ecosystem は work object を skill 化している。FineTune Studio、mcp-use、Hermes、Hallmark、Spec Kit、Graphify、Graphiti、wigolo、Open Interpreter、AIRI、PostHog、Copilot SDK は、code、document、training、design、memory、search、observability、product analytics を agent callable workflow に変えている。
- 産業境界は software から hardware、data center、制度へ広がった。OpenAI / Apple dispute、Codex Micro、OpenAI screenless hardware、Claude Code regional controversy、Grok Build upload controversy、New York data center limit、frontier safety federal framework、Hassabis の pre-release review proposal が platform responsibility を書き換えている。

## Agent 工学、harness、実行システム

### Routing、cache、cloud、task cost が agent cost governance を architecture 層へ押し上げる

- **発表日**：2026-07-13 から 2026-07-14
- **テーマ**：LLM routing、prompt caching、AI cloud、cost per task
- **リンク**：https://blog.dailydoseofds.com/p/how-llm-routing-actually-works-in
- **要約**：Daily Dose は LLM routing と prompt caching を production architecture の問題として分解した。model affinity、session pinning、KV cache、static prefix、routing policy が実際の cost を決める。AINews も agent competition が token price から cost per task へ移っていると指摘した。Lightning AI cloud、Transformer Lab、Arch-Router と合わせると、企業は model price だけでなく、task routing、cache hit、training / evaluation environment、cloud resource state を管理する必要がある。

### Agent loop、SPEC.md、verifier runtime が停止条件と評価を明示する

- **発表日**：2026-07-14 から 2026-07-15
- **テーマ**：Agentic RL、agent loop、verifier harness、spec-driven development
- **リンク**：https://blog.dailydoseofds.com/p/the-four-types-of-agent-loops
- **要約**：Daily Dose は agent loop を turn-based、goal-based、time-based、proactive に分けた。Prime Intellect の verifiers は RL environment を taskset、harness、runtime に分解し、Spec Kit と SPEC.md の流れは requirement、test、delivery boundary を agent 実行可能な project process にしている。agent engineering の焦点は、単に「より多く step を走らせる」ことではなく、いつ続け、いつ止め、どう評価し、どう review するかになっている。

### Sandbox、permission、memory、interface layer が coding agent の土台になる

- **発表日**：2026-07-16 から 2026-07-19
- **テーマ**：Local agent audit、sandbox、memory、web intelligence、runtime interfaces
- **リンク**：https://github.com/KnockOutEZ/wigolo
- **要約**：Grok Build の code upload controversy、Claude Code regional controversy、agent sandbox discussion、Open Interpreter、AIRI、Graphiti、wigolo は同じ方向を示している。coding agent は prompt constraint だけでは足りない。file、network、permission、memory、search、cache、execution log、human takeover が runtime の一部になる必要がある。長期稼働 agent は、audit と recovery を備えた local / cloud hybrid workspace に近づいている。

## モデル、評価、リアルタイム interaction

### Open model competition は trillion-scale、multimodal、long-context へ入った

- **発表日**：2026-07-15 から 2026-07-17
- **テーマ**：Open-weight models、long-context coding、multimodal MoE
- **リンク**：https://www.kimi.com/blog/kimi-k3
- **要約**：Kimi K3 は open model competition を 3T class、million-token context、multimodal long-horizon coding へ押し上げた。Thinking Machines Inkling は 975B MoE と native multimodality で open-weight narrative を強めた。open model の競争は benchmark score だけではなく、long context、tool use、coding task、reasoning cost、multimodal input をどう deployable capability に組み合わせるかに移っている。

### GPT-Red、Puppet、LLM-as-a-Verifier は evaluation を model system の一部にする

- **発表日**：2026-07-16 から 2026-07-18
- **テーマ**：Automated red teaming、user-belief evaluation、verifier models
- **リンク**：https://openai.com/index/unlocking-self-improvement-gpt-red
- **要約**：OpenAI の GPT-Red は self-play reinforcement learning で automated red teaming を拡張した。Puppet benchmark は model が user belief に与える影響を測る難しさを扱い、LLM-as-a-Verifier は大規模言語モデルを汎用 verifier として使う。evaluation は release 前 checklist ではなく、training、deployment、runtime control の一部になっている。

### Reasoning effort、SparDA、GPT-Live、Mercury 2 が reasoning control surface を書き換える

- **発表日**：2026-07-15 から 2026-07-19
- **テーマ**：Reasoning control、KV cache、realtime voice、diffusion reasoning
- **リンク**：https://magazine.sebastianraschka.com/p/controlling-reasoning-effort-in-llms
- **要約**：Ahead of AI は reasoning effort を整理し、SparDA は Forecast projection で長文 context の KV blocks を先読みする。The Batch の GPT-Live は realtime voice と background reasoning を二層化し、The Rundown の Mercury 2 は diffusion reasoning を realtime voice agent へ持ち込む。モデル側の焦点は、いつ深く考え、いつ速く応答し、どう cache / context cost を下げ、どう continuous interaction を支えるかになっている。

## Toolchain、knowledge asset、GitHub trend

### MCP app、skills、design / fine-tuning tools が workflow を再利用可能 asset にする

- **発表日**：2026-07-13 から 2026-07-15

### Code knowledge graph、semantic metadata、observability foundation が agent 開発基盤になる

### GitHub trend は local backend、command guard、long-term memory の需要を示す

- **発表日**：2026-07-13 から 2026-07-19

- **リンク**：https://github.com/InsForge/InsForge
