# 今週の結論

- **Agent runtime に関する業界の共通認識が形を取り始めた**：zero-secret、構造化レビュー、失敗時の再計画、必要な文脈だけを渡す設計は、個別テクニックではなく、まとまった engineering 原則になりつつある。
- **Context Engineering は prompt 技巧ではなく system design 問題になった**：backend が schema、state、error をどう見せるかの方が、model を一段強くすること以上に token cost と成功率へ効く場面が増えている。
- **frontier model の競争は外へ広がった**：多 Agent の継続実行、design tool 生成、robotics VLA、diffusion LLM、retrieval foundation までが同時に競争軸に乗った。

## 今週の四つの主線

## 1. Zero-secret runtime が理念から標準設計へ移り始めた

- GitHub Agentic Workflow が重要なのは「新しい AI 機能を出した」からではなく、Agent を制限付きコンテナへ閉じ込め、secret を proxy 層に隔離し、write を deterministic review pipeline に通す構成を明示した点にある。
- これは OpenAI Codex 側の「Agent は secret に触れるべきではない」という運用哲学とも一致しており、runtime security に関する業界共通語が生まれ始めている。

## 2. Context Engineering が backend と toolchain の仕事になった

- `04-21` の signal で最も大きかったのは、Agent の token cost とエラー回数は、model の賢さ不足より backend が返す情報が散漫で重すぎることに起因する、という点だった。
- Skills、CLI、MCP の三層分業はかなり実用的な template に見える。静的知識は段階的ロード、実行結果は構造化 JSON、状態確認だけを軽量 MCP が担う。

## 3. Frontier model の競争軸は「より強い」から「より仕事ができる」へ移った

- Kimi K2.6 は 300 並列 sub-agent と 12 時間以上の継続実行という、system-level な働き方を前面に出した。
- Claude Design、ambient memory、Monologue Notes などは、model 能力を chat window の外へ押し広げている。
- Diffusion LLM、DenseOn / LateOn、GR00T N1.7 は、推論、検索、ロボティクスの下層技術が同時に更新されていることを示した。

## 4. 資本、プラットフォーム、供給網の signal が技術主線と絡み始めた

- DeepMind と Anthropic の計算資源競争は、frontier race が compute と capital の軍拡局面にあることを示す。
- DeepSeek の資金調達と governance 問題、北京のロボット半マラソン、SpaceX IPO 論争は、AI トレンドを技術だけで切り離して見られない段階に入ったことを物語っている。

## 継続観察ポイント

- zero-secret runtime がより多くの IDE / agent platform に広がるか。
- Context Engineering が一部エンジニアの jargon ではなく、チーム共通の backend 設計言語になるか。
- Kimi、Claude、Codex、Hermes がどの入口で棲み分けるか。
