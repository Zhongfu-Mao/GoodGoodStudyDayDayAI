- 時間窓：2026-06-29 ~ 2026-07-05
- 対象日報：2026-06-29 から 2026-07-05

# トレンドカード

- Agent engineering は今週さらに system 化しました。Google Agents CLI の end-to-end path、ByteByteGo の memory / realtime voice、Vercel agents、software factory、prompt-context-harness-loop engineering は、model calls を deployable、recoverable、auditable engineering substrate に置く必要を示しています。
- Model competition は leaderboard から workflow constraints に広がりました。GRPO の verifiable rewards、GeneBench-Pro の life-science judgement、Fable / Sonnet の product positioning、Speechmatics TDT の voice latency、Fugu の model orchestration、RoboReward の robotics reward model は、capability を scenario-specific metric に変えています。
- Tool ecosystem は agent-readable interface を中心に再編されています。MCP、skills、Chrome DevTools、terminal orchestrator、browser / page / meeting agents、codebase memory、PDF pipeline、local-first assistant が、real development and knowledge work の操作層になりつつあります。
- Enterprise adoption はより具体的になりました。Frontier / HP、OpenAI EU jobs framework、Every AI strategy、Claude account risk、OpenAI governance、Sierra agent engineer、Google / NYC AI education summit は、AI が budget、jobs、governance、training、vendor risk management に入ることを示します。
- GitHub trends の意味は repo 数ではなく、agent の long-term state、skill distribution、browser debugging、sandbox execution、web GUI、meeting notes、ML systems education が installable infrastructure になっていることです。

## Agent engineering and runnable systems

### Scaffolding から evaluation、deployment、recovery まで、agent project は lifecycle を持ち始めた

- **公開日**：2026-06-29 から 2026-07-05
- **テーマ**：Agent lifecycle、deployment、state management
- **リンク**：[Daily Dose](https://blog.dailydoseofds.com/p/karpathys-agentic-engineering-finally)
- **要約**：Google Agents CLI、agent-starter-pack、ByteByteGo の memory architecture、Latent.Space の autoresearch / software factory、Cursor FDE、Daily Dose の prompt-context-harness-loop engineering は、agent engineering を full lifecycle に押し出しました。High-quality agent projects は scaffolding、eval、deployment、runtime observability、memory、context boundary、human review、enterprise registration を一緒に扱う必要があります。Reliability は longer prompt ではなく、external state、clear boundaries、reviewable completion conditions から生まれます。

### Realtime、multi-region、identity boundary は agent engineering を infrastructure layer に移す

- **公開日**：2026-07-02 から 2026-07-05
- **テーマ**：Realtime infra、multi-region、identity
- **リンク**：[ByteByteGo](https://blog.bytebytego.com/p/how-openai-delivers-low-latency-voice)
- **要約**：OpenAI low-latency voice architecture、ByteByteGo の multi-region architecture、Proof of Human、local meeting assistant Meetily は、agent が IDE 内の code generator にとどまらないことを示します。Realtime sessions には WebRTC、relay、stateful transceiver、hot-path optimization、recovery strategy が必要です。Global services には multi-region design が必要です。Identity systems は human uniqueness、anonymous proof、agent delegation を同じ mechanism に置く必要があります。

### Control layer、software factory、skills standard は prompt tricks を software engineering に戻す

- **公開日**：2026-07-01 から 2026-07-04
- **テーマ**：Software factory、skills、engineering principles
- **リンク**：[12-factor-agents](https://github.com/humanlayer/12-factor-agents)
- **要約**：herdr、12-factor-agents、Latent.Space の Vercel agents / skill engineering、obra/superpowers、agentskills、openai/codex-plugin-cc、Vercel Labs skills は、agent development を one-off prompt から versioned capability packages に移しています。Teams は skills、plugins、terminal orchestration、browser QA、development methodology、agent-readable specs を組み合わせ、新しい engineering control surface を作り始めています。

## Models、evaluation、multimodal capability

### Verifiable rewards、domain evaluation、real workflow は single leaderboard narrative を置き換える

- **公開日**：2026-06-30 から 2026-07-04
- **テーマ**：Verifiable rewards、domain evaluation、workflow evaluation
- **リンク**：[Daily Dose GRPO](https://blog.dailydoseofds.com/p/verifiable-rewards-and-grpo-in-rl)
- **要約**：GRPO は reasoning model training を math、code、formal logic など checkable tasks に戻します。OpenAI GeneBench-Pro は life-science evaluation を knowledge QA から research judgement へ進めました。Every の Sonnet 5 and PowerPoint observations は、model evaluation が real templates、organization standards、delivery constraints に入る必要を示します。Model choice は「誰が最高点か」ではなく、「target workflow で誰が stable、cheap、verifiable か」になっています。

### Speech、image、video、robotics reward models は agent workflow に入る

- **公開日**：2026-07-03 から 2026-07-05
- **テーマ**：Speech、image/video generation、robotics reward
- **リンク**：[Speechmatics TDT](https://www.speechmatics.com/company/articles-and-news/token-duration-transducer-tdt-explained)
- **要約**：Speechmatics TDT は duration head と frame skipping で ASR latency を下げます。Google の Nano Banana 2 Lite と Gemini Omni Flash は image and video generation を developer APIs に接続します。The Batch が追った RoboReward は、robot training の reward function を trainable and evaluable model asset にします。Multimodal capability は demo feature から、agent の input、editing、verification、action loop へ入っています。

### Orchestration layer は model competition の新しい位置になる

- **公開日**：2026-07-04
- **テーマ**：Model orchestration、access governance
- **リンク**：[Fugu](https://arxiv.org/abs/2606.21228)
- **要約**：Sakana AI の Fugu / Fugu-Ultra と GPT-5.6 restricted release は、frontier competition が single-model parameters and scores だけで起きていないことを示します。Model orchestration、access gating、safety review、trusted partner previews、task-level composition は R&D supply chain を変えています。Enterprises は single peak capability だけでなく、alternative models、access risk、evaluation environment、degradation strategy を記録する必要があります。
