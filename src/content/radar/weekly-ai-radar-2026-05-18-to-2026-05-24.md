# 本周范围

- 时间窗口：2026-05-18 ~ 2026-05-24
- 覆盖日报：2026-05-18 至 2026-05-24 各期

# 趋势卡片

- Google I/O 把 Search、Workspace、Shopping、Antigravity、Managed Agents 和 multimodal device agents 放进同一个 agent-first 平台叙事。
- AWS 本周最密集的信号不是单个模型，而是 AgentCore、SageMaker、Strands、Nova Sonic、Kiro memory、code evaluators 和 programmatic tool calling 组成的生产底座。
- Agent 评测从模型榜单转向系统榜单：Open Agent Leaderboard、multimodal judges、code evaluators 和 harness analysis 都在评估 wrapper、tool use、failure cost 和 context management。
- 推理经济学重新影响产品形态：DeepSeek 降价、OpenAI-compatible endpoints、programmatic tool calling、R2 / asset 压缩和 sandbox 成本都在决定哪些 agent 工作流可以常态化。
- 文档、遥感、OCR、voice、accessibility、commerce 和 medical judgment 显示，AI 的价值越来越依赖输入结构、场景责任和真实工作流，而不是单次模型输出。

## Agent 平台与运行时

### Google I/O 2026 把 Gemini、Antigravity、Managed Agents 和 WebMCP 组织成开发者平台
- **发布日期**：2026-05-20
- **主题**：Agent 平台与运行时
- **链接**：[Google I/O 2026 announcements](https://blog.google/innovation-and-ai/technology/ai/google-io-2026-all-our-announcements/)
- **摘要**：Google 把 Gemini 3.5 Flash、Gemini Omni、Antigravity 2.0、Managed Agents、AI Studio 与 WebMCP 放在同一条 agent-first 线上。Antigravity 加入桌面、CLI、SDK、subagents、hooks 和 async tasks；Managed Agents 提供远程 Linux、代码执行、文件管理与网页浏览。Google 的平台重心已经从“模型可用”转向“模型、工具、执行环境和 IDE 如何作为一个 agent surface 协同”。

### AWS AgentCore 与 Nova Sonic 显示语音、工具、记忆和评测正在进入同一个生产栈
- **发布日期**：2026-05-19
- **主题**：Agent 平台与运行时
- **链接**：[Amazon Nova Sonic voice agent design](https://aws.amazon.com/blogs/machine-learning/scalable-voice-agent-design-with-amazon-nova-sonic-multi-agent-tools-and-session-segmentation/)
- **摘要**：Nova Sonic voice agents、AgentCore Runtime、Gateway、Memory、Code Interpreter、Strands 和 Lambda evaluators 共同指向同一件事：agent 生产系统需要低延迟 streaming、工具治理、状态交接、长期记忆、可执行沙箱和可观测评测。AWS 本周的信号密度说明，云平台正在把 agent 从示例代码变成托管基础设施。

### MCP stateless、sandboxes 与 memory layers 让 agent runtime 更接近可扩缩协议
- **发布日期**：2026-05-23
- **主题**：Agent 平台与运行时
- **链接**：[Latent.Space AINews](https://www.latent.space/p/ainews-all-model-labs-are-now-agent)
- **摘要**：Latent.Space 汇总的 MCP release candidate、CoreWeave Sandboxes、Cloudsail、Gemini Managed Agents、Hermes、AI-Q 和 gBrain 等信号显示，agent runtime 正在从一次性工具调用走向协议化运行系统。stateless MCP、per-task sandbox、skills、shared memory 和 key management 会成为跨供应商 agent 的共同基础件。

## 评测、可靠性与 Harness

### Open Agent Leaderboard 把评测对象从模型推进到完整 agent system
- **发布日期**：2026-05-18
- **主题**：评测、可靠性与 Harness
- **链接**：[Open Agent Leaderboard](https://huggingface.co/blog/ibm-research/open-agent-leaderboard)
- **摘要**：IBM Research 与 Hugging Face 发布 Open Agent Leaderboard，通过 Exgentic framework 汇集 SWE-Bench Verified、BrowseComp+、AppWorld、tau2-Bench 等任务，同时报告 success rate 和 average cost per task。它证明同一模型配不同 wrapper 会得到不同质量与成本，失败运行还可能比成功运行贵 20% 到 54%。agent 评测必须测 planning、tool selection、context management、memory 和 recovery，而不只是基础模型。

### 多模态 judge 与代码评测器让 agent evaluation 同时覆盖视觉 grounding 和确定性规则
- **发布日期**：2026-05-20
- **主题**：评测、可靠性与 Harness
- **链接**：[Strands multimodal evaluators](https://aws.amazon.com/blogs/machine-learning/multimodal-evaluators-mllm-as-a-judge-for-image-to-text-tasks-in-strands-evals/)
- **摘要**：Strands Evals 的 multimodal judges 可以直接看图像、query、response 和 reference answer，评估 captioning、visual QA、document extraction、OCR 与 chart interpretation。AgentCore 的 custom code evaluators 则用 Lambda 检查 schema、数值漂移、workflow 和 PII。两者合起来说明，生产评测需要同时看原始输入、系统 trace 和确定性业务规则。

### Agent harness 成为产品差异的核心工程层
- **发布日期**：2026-05-24
- **主题**：评测、可靠性与 Harness
- **链接**：[The Anatomy of an Agent Harness](https://www.dailydoseofds.com/p/the-anatomy-of-an-agent-harness/)
- **摘要**：Daily Dose of DS 把 harness 拆成 orchestration loop、tools、memory、context management、state、error handling、guardrails、verification 和 subagents。这个框架能解释为什么同一模型在不同产品里差异很大：生产 agent 的竞争点已经转向模型外部的系统工程。OpenAI、Anthropic、LangGraph、CrewAI 和 Claude Code 的差异，越来越像不同操作系统对进程、权限、I/O 与恢复机制的设计差异。

## 推理经济学与工具调用

### Programmatic Tool Calling 把可确定工作从上下文窗口移到沙箱代码
- **发布日期**：2026-05-19
- **主题**：推理经济学与工具调用
- **链接**：[Programmatic Tool Calling on Amazon Bedrock](https://aws.amazon.com/blogs/machine-learning/implementing-programmatic-tool-calling-on-amazon-bedrock/)
- **摘要**：AWS 的 PTC 示例让模型生成 Python 代码，在沙箱里完成循环、过滤、聚合和多工具调用，只把最终答案交回模型。结果是 token 用量下降 87% 到 92%，准确率也更稳定。对长任务 agent 来说，这比“让模型逐步调用工具”更接近可靠软件系统：模型负责规划和生成程序，沙箱负责确定性执行。

### DeepSeek 降价、OpenAI-compatible SageMaker endpoints 与 R2 资产压力共同重塑运行成本
- **发布日期**：2026-05-23
- **主题**：推理经济学与工具调用
- **链接**：[Latent.Space AINews](https://www.latent.space/p/ainews-all-model-labs-are-now-agent)
- **摘要**：DeepSeek-V4-Pro 价格下调把长任务推理成本推回产品设计中心；SageMaker AI 的 OpenAI-compatible endpoints 则降低企业把自有模型接入现有 SDK、LangChain 与 Strands 的迁移成本。与此同时，媒体资产和 NotebookLM 输出持续增长提醒内容型 agent 工作流也有存储与发布成本。2026 年的 agent 经济学不只算 API token，还要算沙箱、媒体、缓存、部署与复用。

### 语音 agent 与实时转写把延迟预算变成架构问题
- **发布日期**：2026-05-20
- **主题**：推理经济学与工具调用
- **链接**：[SageMaker AI and vLLM realtime voice](https://aws.amazon.com/blogs/machine-learning/build-real-time-voice-applications-with-amazon-sagemaker-ai-and-vllm/)
- **摘要**：SageMaker bidirectional streaming 与 vLLM Realtime API 的组合展示了托管实时语音转写路径；Nova Sonic voice agent 设计则展示了工具数量、sub-agent、session segmentation、prefetch 和 filler phrases 如何影响语音交互体验。语音 agent 的关键指标不是平均回答质量，而是端到端延迟、语音中断处理、工具并行、状态交接和安全提示时机。

## 开放模型、文档与科学场景

### PaddleOCR 3.5 与 Ettin Reranker 补齐 RAG / Agent 的输入质量链路
- **发布日期**：2026-05-18
- **主题**：开放模型、文档与科学场景
- **链接**：[PaddleOCR 3.5 Transformers backend](https://huggingface.co/blog/PaddlePaddle/paddleocr-transformers)
- **摘要**：PaddleOCR 3.5 把 OCR 与文档解析接入 Transformers backend，Ettin Reranker 则公开 17M 到 1B 的 cross-encoder reranker、训练数据和 recipe。两者分别处理“先把文档变成结构化信息”和“再把候选上下文排准”。RAG 与 agent memory 的质量很大程度上取决于这条输入链，而不是最后一层 LLM。

### OlmoEarth v1.1 展示科学模型效率来自数据结构感知的 tokenization
- **发布日期**：2026-05-19
- **主题**：开放模型、文档与科学场景
- **链接**：[OlmoEarth v1.1](https://huggingface.co/blog/allenai/olmoearth-v1-1)
- **摘要**：OlmoEarth v1.1 通过重新设计 Sentinel-2 遥感输入的 token 结构，把运行成本最高降至原来的三分之一，同时维持与 v1 接近的表现。它提醒我们，科学与地理空间 AI 的效率不只来自更快 GPU，也来自理解输入数据的物理结构、分辨率、时间维度和任务目标。

### Running Guide agent 把端侧多模态、风险分级和硬件形态带进无障碍场景
- **发布日期**：2026-05-20
- **主题**：开放模型、文档与科学场景
- **链接**：[Running Guide agent](https://blog.google/innovation-and-ai/models-and-research/google-deepmind/running-guide-agent/)
- **摘要**：Google 的 Running Guide agent 用胸前 Pixel 10 Pro、端侧 segmentation、Gemma 4 E4B 和 Planner / Coach / Break 多 agent 架构帮助盲人和低视力跑者独立跑步。这个案例把 AI 从屏幕内助手带到高责任物理场景，要求低延迟 STOP 提示、离线可靠路径、严格风险等级和合适硬件形态。

## 组织采用、多 agent 与人类判断

### Cheap competence 把人类工作推向 framing、边界和责任
- **发布日期**：2026-05-24
- **主题**：组织采用、多 agent 与人类判断
- **链接**：[Cheap Competence, New Frontier](https://every.to/context-window/cheap-competence-new-frontier)
- **摘要**：Every 本周围绕 “After Automation” 讨论 cheap competence：当 agent 可以写代码、整理邮件和生成通讯，人类工作并没有被清空，而是转向定义问题、设定框架、判断质量和承担责任。医疗观察也指向同一结论：知识更便宜后，优秀医生的情境判断更贵。

### Gas City 把 100-agent 软件工厂的潜力和成本同时摊开
- **发布日期**：2026-05-19
- **主题**：组织采用、多 agent 与人类判断
- **链接**：[Inside the 100-agent Software Factory](https://every.to/context-window/inside-the-100-agent-software-factory)
- **摘要**：Gas City 通过一个持续 “mayor” agent 协调大量一次性 worker，展示 light factory / dark factory、一次性 worker、多模型 code review 等思想。它也暴露出多 agent 工厂的真实成本：重复读取上下文、token 消耗、任务追踪和工具复杂度。结论不是立即采用某个 toolkit，而是把这些 coordination patterns 吸收到现有工程流程里。

### Agentic commerce 与 marketing agents 正在进入支付、结账和业务系统
- **发布日期**：2026-05-20
- **主题**：组织采用、多 agent 与人类判断
- **链接**：[Google Shopping updates](https://blog.google/products-and-platforms/products/shopping/shopping-updates-google-marketing-live/)
- **摘要**：Universal Cart、Agent Payments Protocol、Universal Commerce Protocol 和 Ask Advisor 说明，商业 agent 的难点正在从推荐商品进入支付、商户记录、促销、品牌曝光、campaign launch 和跨系统数据解释。消费级 agent 一旦进入交易，就必须处理责任边界、渠道分配和业务系统一致性。
