## 这节课解决什么问题

AI Fundamentals 的作用是给初学者一张地图：AI 不是一个单独工具，而是一类可以从数据中学习模式、识别输入并产出结果的软件系统。ChatGPT、Codex 和 API 都是把模型能力包装给用户使用的不同入口。

如果没有这张地图，后续很容易把几个层级混在一起：

| 层级 | 说明 |
| --- | --- |
| AI | 总领域，包含不同类型的软件系统和任务 |
| 模型 | 从数据中训练出来、能处理特定任务的系统 |
| LLM | 面向语言理解和生成的大语言模型 |
| ChatGPT / Codex | 把模型能力产品化后的使用界面或工作环境 |
| API | 面向开发者的可编程模型能力入口 |

## 核心概念

### AI 是类别，不是单个产品

AI 可以出现在导航、风控、客服、写作、编程、图像、语音等许多场景里。OpenAI Academy 的基础页很适合用来纠正一个误解：ChatGPT 是 AI 产品，但 AI 不等于 ChatGPT。

这个区分对学习路线很重要。学 ChatGPT 是学一个产品和它的工作流；学 LLM 是理解语言模型这类系统；学 Building with AI 则是把模型能力接进真实系统。

### LLM 的关键能力是语言模式建模

LLM 面向语言工作。它通过大量文本学习语言中的模式，再根据上下文生成、改写、总结、解释或转换文本。

对学习者来说，最实用的理解不是“模型知道答案”，而是“模型根据上下文生成最可能有用的语言输出”。这能解释为什么上下文、约束、示例和复核都很重要。

### 训练不是一次完成

OpenAI Academy 把模型演进拆成两个有用阶段：

| 阶段 | 学习者可以怎样理解 |
| --- | --- |
| Pre-training | 模型从大量数据里学习广泛模式，获得总结、翻译、解释、生成等基础能力 |
| Post-training | 模型被进一步调整，以更可靠地遵循指令、匹配语气、处理安全和不确定情境 |

这也解释了为什么模型更新后，语气、谨慎程度、默认行为可能会变化。想要稳定输出，不能只依赖模型默认行为，要明确目标、受众、格式和约束。

### Reasoning 与 non-reasoning 的差别

OpenAI Academy 用“速度和深度的取舍”来解释不同模型类别。非 reasoning 模型适合快速、流畅、低摩擦的任务，比如改写、草稿、提炼要点。Reasoning 模型更适合多步骤、约束多、需要仔细分析的问题。

我的使用准则：

| 任务 | 更合适的模式 |
| --- | --- |
| 改写邮件、整理会议纪要、生成备选标题 | 快速模型或默认 Auto |
| 多约束计划、复杂调试、架构判断、风险评估 | Thinking / reasoning 模型 |
| 不确定哪种合适 | 先 Auto，发现浅层错误再切换到更深思考 |

## 可复用工作流

学完这一节后，可以把任何 AI 使用需求先放进四层判断：

1. **任务是什么**：语言、代码、图像、数据、研究，还是多工具流程。
2. **入口是什么**：ChatGPT、Codex、API，还是现有软件里的 AI 功能。
3. **风险是什么**：低风险草稿，还是高风险决策、事实判断、对外发布。
4. **复核方式是什么**：人工审读、来源引用、测试、数据校验，还是多人审批。

这四步比“写一个好 prompt”更底层。prompt 是交互技术，任务分层才是工作流设计。

## 和 Anthropic Academy 的对照

Anthropic Academy 的 AI Fluency 更强调人和 AI 的协作能力，比如 Delegation、Description、Discernment、Diligence。OpenAI Academy 的 AI Fundamentals 更像工具路线的前置地图，先帮助用户分清 AI、模型、LLM、产品和 API。

两边合起来，一个讲“怎么判断和委派”，一个讲“系统和产品分别是什么”。



## 完整版学习稿

### 学习定位

这一页可以当作 **AI Fundamentals** 的系统学习稿。它面向需要补齐 AI 基础概念和判断框架的读者，重点不是背官方术语，而是把页面里的能力、场景和边界转成可以反复使用的工作方法。

### 学习目标

- 理解 AI、ML、deep learning、generative AI、LLM 之间的层级关系。
- 知道模型擅长生成、分类、总结、推理辅助，但不等于事实来源。
- 建立后续使用 ChatGPT、Codex 和 AI 应用构建时的共同语言。

### 官方内容拆解

| 模块 | 学习重点 | 可产出材料 |
| --- | --- | --- |
| 概念层级 | AI 是大范畴，ML/DL/LLM 是其中不同技术路径 | 画出自己的术语图 |
| 能力边界 | 生成文本、图片、代码、摘要和分析都依赖输入质量 | 列出适合/不适合 AI 的任务 |
| 人机协作 | AI 更像工作台上的助手而不是权威 | 定义复核和决策责任 |
| 学习迁移 | 基础概念会贯穿所有后续课程 | 把每个新工具归类到能力图里 |

### 实操工作流

1. 先用一页纸画出 AI 概念地图。
2. 把自己日常任务按“生成、整理、分析、决策”分类。
3. 标出哪些任务可以让 AI 起草，哪些必须人工判断。
4. 每遇到一个新功能，回到概念地图定位它解决的问题。
5. 用真实任务检验：它节省的是搜索、组织、表达还是执行时间。

### 可复用 Prompt

```text
请用面向非技术读者的方式解释 AI、机器学习、深度学习、生成式 AI 和大语言模型的区别，并用我日常工作中的例子说明每一层能做什么、不能做什么。
```

### 复核清单

- 输出是否只使用已提供或可追溯的信息，不把推断写成事实。
- 是否标出不确定性、待确认项和需要人工判断的地方。
- 是否给出可执行的下一步，而不是只生成漂亮文字。
- 是否符合团队、学校、公司或行业的隐私与合规要求。

### 学完应该留下什么

学完这一页，最好不要只留下摘要，而是留下 一份可复用的学习笔记、prompt 模板和实践清单。如果以后要补自己的课程心得，可以在这份材料后面继续追加：真实使用场景、失败案例、改进后的 prompt、以及哪些判断必须由人完成。

### 虚构案例

你要给完全非技术的朋友讲清 AI、机器学习、生成式 AI 和 ChatGPT 的关系。 你可以把输入材料设定为：读者背景、他们最常见的误解、你希望他们学完能做的第一件事。最后产出 一页概念地图、5 个生活类比、适合/不适合 AI 的任务清单。

### 原创 Prompt Pack

1. 请把 AI、ML、Deep Learning、Generative AI、LLM 的关系画成层级说明。
2. 请用 5 个非技术类比解释大语言模型的能力和限制。
3. 请列出 10 个日常任务，并判断哪些适合 AI 辅助、哪些不适合。
4. 请把“模型输出不是事实来源”解释给初学者，并给出检查方法。
5. 请为 AI 基础课设计 8 道自测题，答案要解释为什么。

## 亲测记录模板

> 这一段用于后续真正学完官方材料、跑过练习后继续追加。公开发布时，建议保留方法、过程和复盘，隐藏敏感输入、账号信息、客户资料、未验证结论和不可公开的内部材料。

### 最小实测任务

- 场景类型：个人/通用工作流
- 建议任务：选择一个自己会反复遇到的小任务，用本页方法跑完整个输入、输出、复核流程
- 输入材料：目标、背景、材料、受众、输出格式、限制
- 目标产物：可复用 prompt、检查清单、示例输出、改进记录
- 关键边界：事实来源、隐私信息、人工判断和公开发布边界

### 记录表

| 记录项 | 建议填写方式 |
| --- | --- |
| 我为什么学这一页 | 写清它和当前工作、学习或项目的关系 |
| 我实际用了什么输入 | 列出材料类型，避免公开敏感原文 |
| 第一版 prompt | 保留自己的写法，方便以后比较 |
| 第一版输出问题 | 记录含糊、遗漏、编造、格式不对或不适用之处 |
| 第二轮反馈 | 写出你如何纠偏：补上下文、加限制、改格式、要求来源 |

| 可公开内容 | 只发布脱敏后的流程、经验、失败案例和自己的理解 |

### 复盘问题

1. 这页内容在真实任务中最有用的一点是什么？
2. 第一次输出为什么不够好，是输入问题、模型问题，还是任务本身不清楚？
3. 哪个约束最能提升质量：角色、上下文、来源、格式、示例，还是评价标准？
4. 如果让朋友照着做，哪些步骤需要写得更明确？
5. 这次实测后，我会如何改写本文的个人心得部分？
