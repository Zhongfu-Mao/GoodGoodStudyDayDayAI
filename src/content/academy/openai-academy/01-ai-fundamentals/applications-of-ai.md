## 这节课解决什么问题

这一节把 OpenAI 的产品形态讲清楚：模型能力并不只通过一个聊天框出现，它可以被包装成普通用户可直接使用的产品，也可以通过 API 变成开发者可组合的构建块。

对学习者来说，这个区分很关键。你在 ChatGPT 里完成一个任务，和你在自己的系统里调用 OpenAI API，是两种不同的使用层级。

## 三层地图

| 层级 | 代表 | 学习重点 |
| --- | --- | --- |
| 面向个人和团队的产品 | ChatGPT | 对话、写作、研究、学习、办公工作流 |
| 面向开发和代码任务的产品 | Codex | 读写项目、运行任务、修复代码、自动化工程工作 |
| 面向开发者的能力入口 | OpenAI API | 把模型能力接进产品、内部系统和自动化流程 |

ChatGPT 更像通用工作台，Codex 更像可操作项目的工程助手，API 则是把模型能力嵌入系统的接口。

## 我的实践理解

如果目标是“今天完成一篇文档”，优先考虑 ChatGPT。它适合快速构思、改写、总结材料和生成初稿。

如果目标是“改这个仓库、跑检查、修错误”，优先考虑 Codex。它能读取文件、应用补丁、运行命令，适合可验证的项目任务。

如果目标是“给站点或内部工具加 AI 功能”，才进入 API 层。API 层要考虑鉴权、日志、成本、延迟、评估、错误处理和数据边界。

## 可复用判断

每次想使用 OpenAI 工具前，先问三个问题：

| 问题 | 倾向入口 |
| --- | --- |
| 这是一次性思考、写作或学习任务吗 | ChatGPT |
| 这需要修改文件、运行测试或交付代码吗 | Codex |
| 这需要集成到我自己的应用或流程里吗 | API |

## 完整版学习稿

### 学习定位

这一页可以当作 **Applications of AI at OpenAI** 的系统学习稿。它面向想把 AI 能力映射到实际产品和任务的人，重点不是背官方术语，而是把页面里的能力、场景和边界转成可以反复使用的工作方法。

### 学习目标

- 把文本、图像、语音、代码、搜索和自动化看成一组可组合能力。
- 理解“应用”不只是模型本身，而是模型、界面、工具和流程的组合。
- 为后续工作流设计建立能力清单。

### 官方内容拆解

| 模块 | 学习重点 | 可产出材料 |
| --- | --- | --- |
| 文本能力 | 写作、总结、改写、问答、规划 | 邮件、报告、FAQ、说明文档 |
| 视觉能力 | 图像理解、图像生成、视觉反馈 | 创意稿、教学图、营销素材草案 |
| 语音能力 | 低摩擦输入和对话式练习 | 口述复盘、演讲练习、访谈整理 |
| 代码能力 | 理解代码库、修改、测试、审查 | patch、测试计划、迁移说明 |
| 研究能力 | 搜索、来源比较、深度综合 | brief、竞品表、带引用的报告 |

### 实操工作流

1. 列出一个任务需要哪些输入和输出。
2. 判断它主要依赖哪类 AI 能力。
3. 补齐工具：是否需要文件、搜索、图像、代码或项目上下文。
4. 要求模型输出可复核的中间产物。
5. 把成功案例沉淀成自己的能力地图。

### 可复用 Prompt

```text
请把我接下来这个任务拆成 AI 能力模块：文本、图像、语音、代码、搜索、数据分析、自动化。请说明每个模块能帮什么、需要什么输入、最后如何人工复核。
```

### 复核清单

- 输出是否只使用已提供或可追溯的信息，不把推断写成事实。
- 是否标出不确定性、待确认项和需要人工判断的地方。
- 是否给出可执行的下一步，而不是只生成漂亮文字。
- 是否符合团队、学校、公司或行业的隐私与合规要求。

### 学完应该留下什么

学完这一页，最好不要只留下摘要，而是留下 一份可复用的学习笔记、prompt 模板和实践清单。如果以后要补自己的课程心得，可以在这份材料后面继续追加：真实使用场景、失败案例、改进后的 prompt、以及哪些判断必须由人完成。

## 原创学习增强包

### 三档练习

| 时间 | 练习任务 | 交付物 |
| --- | --- | --- |
| 30 分钟 | 只读本页和来源核对区，提炼 5 条最有用的行动建议。 | 一张“今天就能试”的清单 |
| 2 小时 | 用下面的虚构案例跑一遍完整流程，记录输入、输出、修改和复核点。 | 一份可发布的练习记录 |
| 半天 | 把练习结果改造成自己的模板或小项目，并写下失败案例。 | 模板、prompt pack、复盘笔记 |

### 虚构案例

你要帮一个小团队盘点哪些工作可以用文本、图像、语音、代码和研究能力改造。 你可以把输入材料设定为：团队的重复任务、当前工具、可接受风险、希望节省的时间。最后产出 AI 能力地图、任务机会清单、优先级矩阵。

### 原创 Prompt Pack

1. 请把这个团队的任务按文本、图像、语音、代码、研究、数据分析分类。
2. 请找出 10 个最适合 AI 辅助的低风险任务，并说明理由。
3. 请把每个任务对应到输入、模型能力、输出和人工复核。
4. 请设计一个两周 AI 应用试点，不涉及敏感数据。
5. 请为这些 AI 应用机会做影响/风险矩阵。

### 自测问题

- 我能不能用自己的话解释“Applications of AI at OpenAI”解决的核心问题？

- 我能不能指出输出中哪些内容必须人工复核？
- 我能不能把这页内容沉淀成一个模板、清单或小项目？

## 亲测记录模板

> 这一段用于后续真正学完官方材料、跑过练习后继续追加。公开发布时，建议保留方法、过程和复盘，隐藏敏感输入、账号信息、客户资料、未验证结论和不可公开的内部材料。

### 最小实测任务

- 场景类型：个人/通用工作流
- 建议任务：选择一个自己会反复遇到的小任务，用本页方法跑完整个输入、输出、复核流程
- 输入材料：目标、背景、材料、受众、输出格式、限制
- 目标产物：可复用 prompt、检查清单、示例输出、改进记录
- 关键边界：事实来源、隐私信息、人工判断和公开发布边界

### 记录表

| 记录项 | 建议填写方式 |
| --- | --- |
| 我为什么学这一页 | 写清它和当前工作、学习或项目的关系 |
| 我实际用了什么输入 | 列出材料类型，避免公开敏感原文 |
| 第一版 prompt | 保留自己的写法，方便以后比较 |
| 第一版输出问题 | 记录含糊、遗漏、编造、格式不对或不适用之处 |
| 第二轮反馈 | 写出你如何纠偏：补上下文、加限制、改格式、要求来源 |
| 最终可复用产物 | 沉淀成模板、清单、流程图、评估集或小项目 |
| 人工复核结论 | 标明哪些可以直接用，哪些必须找专业人员或同事确认 |
| 可公开内容 | 只发布脱敏后的流程、经验、失败案例和自己的理解 |

### 复盘问题

1. 这页内容在真实任务中最有用的一点是什么？
2. 第一次输出为什么不够好，是输入问题、模型问题，还是任务本身不清楚？
3. 哪个约束最能提升质量：角色、上下文、来源、格式、示例，还是评价标准？
4. 如果让朋友照着做，哪些步骤需要写得更明确？
5. 这次实测后，我会如何改写本文的个人心得部分？
