**说明：** 本文旨在将官方的 Prompting 入门指南提炼为一套在实际工作中具备极高复用价值的稳定写法。

## 解决的核心痛点：从“盲目试错”到“精准委派”

Prompting 的本质并非寻找某种“咒语”，而是建立一种高效的沟通协议。高质量的交付成果通常源于三个基础要素的对齐：清晰的任务动词、丰富的上下文支撑以及具体的成功标准。

## 驱动高质量输出的四步法

| 维度 | 关键动作 | 实战示例 |
| --- | --- | --- |
| **任务 (Task)** | 使用具体的行动动词，明确核心动作。 | “起草 (Draft)”、“总结 (Summarize)”、“审计 (Audit)”。 |
| **上下文 (Context)** | 提供决策所需的背景信息与边界限制。 | “受众是技术经理”、“参考我上传的竞品分析文件”。 |
| **输出 (Output)** | 定义理想的展现形式、语气及长度。 | “输出为 Markdown 表格”、“语气需专业且不偏不倚”。 |
| **迭代 (Iterate)** | 基于初步反馈进行精准修正。 | “缩短篇幅并增加风险评估章节”、“为结论提供更多数据支撑”。 |

## 推荐的标准化 Prompt 模板

```text
# 任务目标
请协助我 [具体的动作，如：完成一份产品发布计划的初步审计]。

# 上下文背景
背景是 [简述当前情况]，目标受众是 [谁会看这份结果]。

# 输出规范
请以 [如：结构化清单] 形式呈现，语气要求 [如：简洁、批判性]。

# 特别约束
必须包含 [要素 A]，严禁提及 [敏感点 B]。

# 交互确认
如果您认为当前上下文信息不足以给出高质量建议，请在开始前向我提出最多 3 个关键问题。
```

## 避坑指南：如何显著提升输出下限

- **拒绝模糊动词**：用“写出 5 条改进建议”代替“优化这段文字”。
- **分层提供要求**：使用 Markdown 标题或列表来分隔任务、背景与格式要求，避免语义混淆。
- **采用增量工作流**：先要求模型输出“大纲或初步框架”，确认方向后再要求生成全文本。
- **让模型成为“批判者”**：与其只要求它“生成内容”，不如让它“分析该内容的优缺点及潜在风险”。

## 与其他 Academy 的对比洞察

- **OpenAI 视角**：更侧重于**“操作手册”**，强调快速起步与基础结构（Outline -> Context -> Output）。
- **Anthropic 视角**：更侧重于**“协作模型”**，强调为模型设定详细的角色画像 (Description) 与思维链引导。
- **综合建议**：在入门阶段，严格遵循 OpenAI 的三步法（任务-背景-输出）能确保 80% 以上的常见任务达到及格线以上。

## 体系化学习指南

### 核心目标
- 掌握任务、上下文、理想输出的闭环表达技巧。
- 建立“提示词是动态迭代过程”的认知，学会有效反馈。
- 将模糊的业务需求高效转化为 AI 可执行的指令。

### 推荐操作流
1. **动词驱动**：从任务列表（Plan, Draft, Research 等）中选出最契合的动词。
2. **背景建模**：梳理受众、文件、已有尝试及负面约束。
3. **设定基准**：指定成功交付物的具体样貌。
4. **沙盒预演**：观察初次输出，找出模型“偷懒”或“误解”的地方。
5. **策略沉淀**：将成功的提示词结构固化为个人/团队模板。

### 质量控制清单
- [ ] 任务描述是否包含具体的、可衡量的动词？
- [ ] 是否提供了足够的背景材料以减少模型的“盲目猜测”？
- [ ] 最终产出是否完全符合预定的格式与语气规范？
