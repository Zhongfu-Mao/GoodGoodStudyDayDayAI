**说明：** 本文整理 ChatGPT 个性化设置的使用边界，重点是让默认行为更稳定。

## 这节课解决什么问题

如果每次都要重新解释你的角色、语气、输出格式和偏好，ChatGPT 会像临时工一样工作。Personalizing ChatGPT 的目标是把稳定偏好放进默认设置，让每次对话少一点重复说明。

## Custom Instructions

Custom Instructions 适合放长期稳定的信息：

| 类型 | 示例 |
| --- | --- |
| 你的角色 | 我在维护一个 AI 学习博客 |
| 输出偏好 | 优先给结构化清单和可执行步骤 |
| 语气偏好 | 简洁、直接、不要营销腔 |
| 默认约束 | 不确定时先问问题，事实类内容给来源 |

不适合放一次性任务细节。具体任务仍然应该写在当前对话里。

## Memory

Memory 适合保存长期有用的个人背景和偏好，比如常用项目、长期学习目标、写作风格。它不适合保存一次性素材、敏感信息或临时状态。

一个健康的 Memory 使用习惯是定期问：

```text
你现在记得哪些关于我的信息？哪些对当前工作有帮助，哪些应该忘掉？
```

## 我的实践规则

1. 稳定偏好放 Custom Instructions。
2. 长期背景放 Memory。
3. 一次性材料放当前 prompt 或 Project。
4. 敏感数据尽量不放 Memory。
5. 输出不稳定时，先检查默认指令是否太宽泛。

## 和 Skills 的关系

Personalization 管“默认工作风格”，Skills 管“可复用流程”。前者像你的常用工作习惯，后者像一份标准操作手册。不要把复杂流程都塞进个性化设置，否则会让每次对话都背负不必要的上下文。



## 完整版学习稿

### 学习定位

这一页可以当作 **Personalizing ChatGPT** 的系统学习稿。它面向希望减少重复说明、让 ChatGPT 更懂自己工作方式的人，重点不是背官方术语，而是把页面里的能力、场景和边界转成可以反复使用的工作方法。

### 学习目标

- 理解个性化设置、记忆和项目上下文的区别。
- 把长期偏好和一次性材料分开放置。
- 在提升效率的同时控制隐私风险。

### 官方内容拆解

| 模块 | 学习重点 | 可产出材料 |
| --- | --- | --- |
| 长期偏好 | 语言、语气、格式、常用角色 | 自定义指令或稳定说明 |
| 项目上下文 | 某个项目的目标、文件、约束 | Project 或会话说明 |
| 记忆边界 | 可以记住偏好，不应随意保存敏感信息 | 定期审查和清理 |
| 团队一致性 | 多人共享格式和标准 | 模板、Skill、项目说明 |

### 实操工作流

1. 列出你每次都会重复告诉 ChatGPT 的信息。
2. 判断哪些是长期偏好，哪些只属于某个项目。
3. 把长期偏好写成简短、可维护的说明。
4. 对敏感信息采用最小化原则。
5. 定期检查个性化是否仍然符合现在的工作方式。

### 可复用 Prompt

```text
请根据我这段自我介绍和工作习惯，整理一份适合放进 ChatGPT 个性化设置的说明。请分成“长期偏好”“输出格式”“不应记住的信息”和“需要按项目临时提供的上下文”。
```

### 复核清单

- 输出是否只使用已提供或可追溯的信息，不把推断写成事实。
- 是否标出不确定性、待确认项和需要人工判断的地方。
- 是否给出可执行的下一步，而不是只生成漂亮文字。
- 是否符合团队、学校、公司或行业的隐私与合规要求。

### 学完应该留下什么

学完这一页，最好不要只留下摘要，而是留下 一份可复用的学习笔记、prompt 模板和实践清单。如果以后要补自己的课程心得，可以在这份材料后面继续追加：真实使用场景、失败案例、改进后的 prompt、以及哪些判断必须由人完成。

## 原创学习增强包

### 三档练习

| 时间 | 练习任务 | 交付物 |
| --- | --- | --- |
| 30 分钟 | 只读本页和来源核对区，提炼 5 条最有用的行动建议。 | 一张“今天就能试”的清单 |
| 2 小时 | 用下面的虚构案例跑一遍完整流程，记录输入、输出、修改和复核点。 | 一份可发布的练习记录 |
| 半天 | 把练习结果改造成自己的模板或小项目，并写下失败案例。 | 模板、prompt pack、复盘笔记 |

### 虚构案例

你想减少每次重复说明个人偏好，但又不想把敏感信息长期保存。 你可以把输入材料设定为：你的写作偏好、常见任务、隐私边界、团队格式要求。最后产出 个性化设置草案、可记忆/不可记忆边界表、项目上下文模板。

### 原创 Prompt Pack

1. 请根据我的工作方式生成一份安全的个性化设置草案。
2. 请把这些信息分成长期偏好、项目上下文、敏感信息三类。
3. 请帮我写一个项目开始时提供给 ChatGPT 的上下文模板。
4. 请审查我的个性化设置是否泄露过多个人信息。
5. 请把我的输出偏好转成简短、可维护的指令。

### 自测问题

- 我能不能用自己的话解释“Personalizing ChatGPT”解决的核心问题？
- 我能不能说清它适合哪些场景、不适合哪些场景？
- 我能不能用一个真实或虚构任务跑完整个流程？
- 我能不能指出输出中哪些内容必须人工复核？
- 我能不能把这页内容沉淀成一个模板、清单或小项目？

## 亲测记录模板

> 这一段用于后续真正学完官方材料、跑过练习后继续追加。公开发布时，建议保留方法、过程和复盘，隐藏敏感输入、账号信息、客户资料、未验证结论和不可公开的内部材料。

### 最小实测任务

- 场景类型：个人/通用工作流
- 建议任务：选择一个自己会反复遇到的小任务，用本页方法跑完整个输入、输出、复核流程
- 输入材料：目标、背景、材料、受众、输出格式、限制
- 目标产物：可复用 prompt、检查清单、示例输出、改进记录
- 关键边界：事实来源、隐私信息、人工判断和公开发布边界

### 记录表

| 记录项 | 建议填写方式 |
| --- | --- |
| 我为什么学这一页 | 写清它和当前工作、学习或项目的关系 |
| 我实际用了什么输入 | 列出材料类型，避免公开敏感原文 |
| 第一版 prompt | 保留自己的写法，方便以后比较 |
| 第一版输出问题 | 记录含糊、遗漏、编造、格式不对或不适用之处 |
| 第二轮反馈 | 写出你如何纠偏：补上下文、加限制、改格式、要求来源 |
| 最终可复用产物 | 沉淀成模板、清单、流程图、评估集或小项目 |
| 人工复核结论 | 标明哪些可以直接用，哪些必须找专业人员或同事确认 |
| 可公开内容 | 只发布脱敏后的流程、经验、失败案例和自己的理解 |

### 复盘问题

1. 这页内容在真实任务中最有用的一点是什么？
2. 第一次输出为什么不够好，是输入问题、模型问题，还是任务本身不清楚？
3. 哪个约束最能提升质量：角色、上下文、来源、格式、示例，还是评价标准？
4. 如果让朋友照着做，哪些步骤需要写得更明确？
5. 这次实测后，我会如何改写本文的个人心得部分？
