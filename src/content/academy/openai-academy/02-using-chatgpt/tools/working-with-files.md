**说明：** 本文整理文件工作流，不复制官方示例文本。

## 这节课解决什么问题

文件上传让 ChatGPT 从“凭你描述工作”变成“围绕具体材料工作”。适合处理 PDF、DOCX、CSV、XLSX、图片、TXT 等材料，也适合把杂乱信息整理成可读输出。

## 文件任务的四类模式

| 模式 | 适合任务 |
| --- | --- |
| 总结 | 提炼 PDF、报告、会议记录、长文档 |
| 改写 | 把文档变清楚、变短、变成另一种语气 |
| 分析 | 处理表格、数据、指标、异常和变化 |
| 抽取 | 从资料里提取日期、负责人、风险、行动项 |

## 好的文件 prompt 怎么写

不要只说“看看这个文件”。更好的写法是：

```text
请阅读我上传的文件。
目标：帮我准备一份面向 [受众] 的摘要。
请输出：
1. 5 个最重要结论
2. 需要进一步确认的事实
3. 可能的风险或遗漏
4. 下一步行动建议
不要改写文件中没有依据的信息。
```

## 连接应用的边界

当 ChatGPT 连接第三方应用时，便利性会明显提升，但也要关注权限、组织策略和数据范围。尤其在企业环境里，是否可连接、连接哪些应用、数据是否可用于训练，通常受管理员控制。

## 官方页面的操作顺序

官方页面的文件工作流可以重写成四步：

1. 上传或连接材料。
2. 明确任务，例如总结、分析、改写、抽取或生成新文件。
3. 要求具体视图，例如表格、图表、要点、待办或对比。
4. 根据结果继续追问，必要时下载 ChatGPT 生成的输出。

这个顺序的价值在于：文件本身只是上下文，真正决定质量的是你让模型怎样使用这些上下文。

## 练习

上传一份 PDF 或表格后，不要直接问“总结一下”。改成：

```text
请先判断这份文件是什么类型。
然后输出：
1. 关键内容摘要
2. 数据或事实缺口
3. 可以继续追问的 5 个问题
4. 最适合转换成表格的部分
```

## 我的实践建议

文件工作流最适合用于“让材料先变得可读”。比如把官方课程页、长 PDF、讲座记录整理成结构图，再由人决定哪些要写进公开文章。它不应该替代最终事实复核。



## 完整版学习稿

### 学习定位

这一页可以当作 **Working with Files in ChatGPT** 的系统学习稿。它面向经常处理 PDF、表格、文档、图片和工作区文件的人，重点不是背官方术语，而是把页面里的能力、场景和边界转成可以反复使用的工作方法。

### 学习目标

- 知道文件上传后可以被分析、总结、改写和转换。
- 按文件类型选择合适任务，而不是把所有文件都丢给模型。
- 学会要求模型标出页码、字段、假设和不确定性。

### 官方内容拆解

| 模块 | 学习重点 | 可产出材料 |
| --- | --- | --- |
| PDF/文档 | 摘要、结构提取、问答、改写 | 章节摘要、FAQ、要点表 |
| 表格 | 数据概览、清洗建议、分析路径 | EDA、图表建议、洞察摘要 |
| 图片 | 视觉理解、设计反馈、内容提取 | 截图说明、素材反馈、生成提示 |
| 连接工具 | 在权限允许下读取工作区材料 | 跨文件摘要、项目问答 |

### 实操工作流

1. 先说明文件是什么、来源和使用目的。
2. 要求模型先概览结构，不急着给结论。
3. 让它引用页码、列名或文件位置。
4. 把输出转成表格、摘要、清单或可下载草稿。
5. 对关键信息回到原文件核对。

### 可复用 Prompt

```text
我上传了一个[文件类型]，用途是[目标]。请先概览文件结构，再列出关键内容、可疑缺口、需要我确认的问题，并给出适合下一步处理的输出格式。
```

### 复核清单

- 输出是否只使用已提供或可追溯的信息，不把推断写成事实。
- 是否标出不确定性、待确认项和需要人工判断的地方。
- 是否给出可执行的下一步，而不是只生成漂亮文字。
- 是否符合团队、学校、公司或行业的隐私与合规要求。

### 学完应该留下什么

学完这一页，最好不要只留下摘要，而是留下 一份可复用的学习笔记、prompt 模板和实践清单。如果以后要补自己的课程心得，可以在这份材料后面继续追加：真实使用场景、失败案例、改进后的 prompt、以及哪些判断必须由人完成。

### 虚构案例

你收到一份 PDF、一个表格和一张截图，需要在 30 分钟内整理出可行动摘要。 你可以把输入材料设定为：文件类型、文件用途、目标读者、需要引用的页码或字段。最后产出 文件结构摘要、关键发现表、待确认问题和下一步行动。

### 原创 Prompt Pack

1. 请先概览这个文件的结构，不要直接下结论。
2. 请列出文件中的关键事实、缺口、异常和需要我确认的问题。
3. 请把这份文件整理成给管理者看的 1 页摘要。
4. 请从这份表格里找出适合进一步分析的 5 个问题。
5. 请基于这张截图生成问题描述、可能原因和后续检查步骤。

### 复盘问题

1. 这页内容在真实任务中最有用的一点是什么？
2. 第一次输出为什么不够好，是输入问题、模型问题，还是任务本身不清楚？
3. 哪个约束最能提升质量：角色、上下文、来源、格式、示例，还是评价标准？
4. 如果让朋友照着做，哪些步骤需要写得更明确？
5. 这次实测后，我会如何改写本文的个人心得部分？
