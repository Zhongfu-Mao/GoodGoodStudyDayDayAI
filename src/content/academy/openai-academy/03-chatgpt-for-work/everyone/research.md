**说明：** 本文面向工作研究任务，不等同于学术研究方法论。

## 这节课解决什么问题

研究场景的目标不是“多找资料”，而是从模糊问题走向可行动判断。ChatGPT 可以帮你拆问题、找来源、比较证据、整理报告，但你需要审来源和结论强度。

## 研究工作流

| 阶段 | 输出 |
| --- | --- |
| 定义问题 | 主问题、子问题、决策背景 |
| 搜集来源 | 官方、行业、新闻、数据库、内部资料 |
| 综合证据 | 支持、反对、矛盾、缺口 |
| 形成判断 | 确定事实、趋势观察、假设 |
| 转成行动 | 建议、风险、下一步验证 |

## 输出格式

```text
请把研究结果分成：
1. 已验证事实
2. 高可信趋势
3. 仍需确认的假设
4. 关键来源
5. 对 [团队/项目] 的影响
```

## 本站用途

做 Radar 用快速 search，做 Academy/Engineering 长文用 deep research，再人工打开来源复核。公开文章里必须给出官方参考链接，避免只引用模型综合。



## 完整版学习稿

### 学习定位

这一页可以当作 **ChatGPT for Research** 的系统学习稿。它面向需要把问题、证据、来源和决策连接起来的人，重点不是背官方术语，而是把页面里的能力、场景和边界转成可以反复使用的工作方法。

### 学习目标

- 把研究从资料堆积变成结构化 brief。
- 区分 Search 的快速定位和 Deep Research 的系统综合。
- 用引用、日期和证据强弱支撑结论。

### 官方内容拆解

| 模块 | 学习重点 | 可产出材料 |
| --- | --- | --- |
| Question framing | 把模糊问题拆成子问题 | 研究计划 |
| Search | 快速找最新信息 | 带链接摘要 |
| Deep Research | 多来源评估和综合 | brief、memo、比较表 |
| Synthesis | 事实、推断、影响、建议 | 决策材料 |

### 实操工作流

1. 写出研究问题和决策背景。
2. 指定优先来源、时间范围和排除项。
3. 先让模型给研究计划。
4. 要求每条关键发现带来源。
5. 检查原文后再形成自己的结论。

### 可复用 Prompt

```text
请围绕[问题]做研究，用于支持[决策]。请区分事实、推断和建议；每个关键发现附来源、日期和可信度说明；最后给出对我的场景的影响和待验证问题。
```

### 复核清单

- 输出是否只使用已提供或可追溯的信息，不把推断写成事实。
- 是否标出不确定性、待确认项和需要人工判断的地方。
- 是否给出可执行的下一步，而不是只生成漂亮文字。
- 是否符合团队、学校、公司或行业的隐私与合规要求。

### 学完应该留下什么

学完这一页，最好不要只留下摘要，而是留下 一份可复用的学习笔记、prompt 模板和实践清单。如果以后要补自己的课程心得，可以在这份材料后面继续追加：真实使用场景、失败案例、改进后的 prompt、以及哪些判断必须由人完成。

## Search 和 Deep Research 怎么分工

官方页最重要的区分是：Search 适合快速定向，Deep Research 适合多步骤综合。两者都要看引用，但使用心智不同。

| 模式 | 适合问题 | 典型产出 | 检查方式 |
| --- | --- | --- | --- |
| Search | 最新消息、概念定位、快速比较 | 带日期和链接的摘要 | 看来源日期、发布主体、是否遗漏关键方 |
| Deep Research | 市场变化、竞品格局、政策影响、复杂决策 | 结构化 brief、source-backed memo、比较表 | 检查子问题是否覆盖、证据是否支持结论 |
| Manual follow-up | 需要高准确度或高风险判断 | 自己复读原文、二次验证 | 回到一手资料、官方文件或权威来源 |

一个好的 research prompt 应该说明研究对象、时间范围、优先来源、输出格式，以及希望区分“有充分证据的结论”和“方向性观察”。这比“帮我研究一下 X”稳定得多。


## 原创学习增强包

### 三档练习

| 时间 | 练习任务 | 交付物 |
| --- | --- | --- |
| 30 分钟 | 只读本页和来源核对区，提炼 5 条最有用的行动建议。 | 一张“今天就能试”的清单 |
| 2 小时 | 用下面的虚构案例跑一遍完整流程，记录输入、输出、修改和复核点。 | 一份可发布的练习记录 |
| 半天 | 把练习结果改造成自己的模板或小项目，并写下失败案例。 | 模板、prompt pack、复盘笔记 |

### 虚构案例

你要为一个战略问题写研究 brief，需要让读者知道证据强弱和下一步。 你可以把输入材料设定为：研究主题、决策背景、时间范围、目标行业、输出格式。最后产出 研究问题树、来源表、发现摘要、矛盾点和建议。

### 原创 Prompt Pack

1. 请把这个研究主题拆成问题树。
2. 请列出我应该优先检查的来源类型和原因。
3. 请整理关键发现，并为每条标注证据强弱。
4. 请指出不同来源之间的矛盾和可能解释。
5. 请把研究结果转成 1 页决策 brief。

- 我能不能用自己的话解释“ChatGPT for Research”解决的核心问题？

- 我能不能指出输出中哪些内容必须人工复核？
- 我能不能把这页内容沉淀成一个模板、清单或小项目？

## 亲测记录模板

> 这一段用于后续真正学完官方材料、跑过练习后继续追加。公开发布时，建议保留方法、过程和复盘，隐藏敏感输入、账号信息、客户资料、未验证结论和不可公开的内部材料。

### 最小实测任务

- 场景类型：团队业务流程
- 建议任务：选择一个真实但可以脱敏的团队任务，从输入整理到交付复盘跑一遍
- 输入材料：业务目标、受众、现有资料、品牌/流程约束、指标
- 目标产物：brief、memo、表格、复盘或下一步行动清单
- 关键边界：事实准确性、团队口径、客户/公司敏感信息

### 记录表

| 记录项 | 建议填写方式 |
| --- | --- |
| 我为什么学这一页 | 写清它和当前工作、学习或项目的关系 |
| 我实际用了什么输入 | 列出材料类型，避免公开敏感原文 |
| 第一版 prompt | 保留自己的写法，方便以后比较 |
| 第一版输出问题 | 记录含糊、遗漏、编造、格式不对或不适用之处 |
| 第二轮反馈 | 写出你如何纠偏：补上下文、加限制、改格式、要求来源 |
| 最终可复用产物 | 沉淀成模板、清单、流程图、评估集或小项目 |
| 人工复核结论 | 标明哪些可以直接用，哪些必须找专业人员或同事确认 |
| 可公开内容 | 只发布脱敏后的流程、经验、失败案例和自己的理解 |

### 复盘问题

1. 这页内容在真实任务中最有用的一点是什么？
2. 第一次输出为什么不够好，是输入问题、模型问题，还是任务本身不清楚？
3. 哪个约束最能提升质量：角色、上下文、来源、格式、示例，还是评价标准？
4. 如果让朋友照着做，哪些步骤需要写得更明确？
5. 这次实测后，我会如何改写本文的个人心得部分？
