**说明：** 本文把 brainstorming 整理成决策辅助流程。

## 这节课解决什么问题

头脑风暴常卡在两个极端：想法太少，或者想法很多但没有结构。ChatGPT 的价值是快速扩展选项、把选项分组、再按标准收窄。

## Wide to Narrow

1. **Start wide**：先生成足够多的方向，不急着判断。
2. **Add structure**：按主题、受众、成本、风险、时间线分组。
3. **Narrow**：用标准打分，挑出最值得尝试的方案。
4. **Plan**：把选中的方向转成里程碑、负责人和下一步。

## 好的 brainstorm prompt

```text
我需要为 [目标] 做方案选择。
约束是：[时间/预算/团队能力/不可做事项]。
请先给 12 个方向，按主题分组。
然后用 impact、effort、confidence 各 1-5 分评分。
最后推荐 3 个最值得试的方向，并说明取舍。
```

## 人需要做什么

ChatGPT 可以提出选项，但不能替你承担组织现实：谁会反对、哪些资源不可用、哪些政治或合规限制没写出来。头脑风暴输出只能作为第一轮材料。



## 完整版学习稿

### 学习定位

这一页可以当作 **Brainstorming with ChatGPT** 的系统学习稿。它面向需要从模糊方向生成方案、筛选思路和转成行动计划的人，重点不是背官方术语，而是把页面里的能力、场景和边界转成可以反复使用的工作方法。

### 学习目标

- 把头脑风暴从随机灵感改成有约束的决策流程。
- 使用 wide -> narrow 方法：先发散，再聚类、比较、收敛。
- 让模型帮助压力测试，不让它替你拍板。

### 官方内容拆解

| 模块 | 学习重点 | 可产出材料 |
| --- | --- | --- |
| Start with decision | 先定义要选择什么 | 决策问题和评估标准 |
| Add constraints | 受众、时间、资源、渠道、指标 | 可执行边界 |
| Start wide | 生成多种方向 | 创意池、实验池 |
| Narrow | 聚类、比较、优先级 | 候选方案和 tradeoffs |
| Pressure-test | 假设、风险、失败条件 | 验证计划 |

### 实操工作流

1. 写清这次 brainstorm 服务的决策。
2. 补上时间、资源和成功指标。
3. 先要 10-20 个方向，不急着评价。
4. 要求模型聚类并列 tradeoffs。
5. 选 1-3 个方向转成实验计划。

### 可复用 Prompt

```text
我们需要决定[决策]。约束是[时间/资源/受众/指标]。请先发散 15 个方向，再聚类为 4 组，比较优缺点，最后推荐 3 个可在[周期]内验证的小实验。
```

### 复核清单

- 输出是否只使用已提供或可追溯的信息，不把推断写成事实。
- 是否标出不确定性、待确认项和需要人工判断的地方。
- 是否给出可执行的下一步，而不是只生成漂亮文字。
- 是否符合团队、学校、公司或行业的隐私与合规要求。

### 学完应该留下什么

学完这一页，最好不要只留下摘要，而是留下 一份可复用的学习笔记、prompt 模板和实践清单。如果以后要补自己的课程心得，可以在这份材料后面继续追加：真实使用场景、失败案例、改进后的 prompt、以及哪些判断必须由人完成。

## 官方方法拆解

Brainstorming 页强调 ChatGPT 不是替你决定，而是帮助你更快走完“发散、组织、收敛、行动化”的循环。

| 阶段 | 怎么问 | 适合产出 |
| --- | --- | --- |
| Define the decision | 先说明要做什么选择、时间范围和成功标准 | 决策问题、约束、评估维度 |
| Start wide | 要求生成多个方向，暂时不评判 | 创意列表、角度、实验、替代方案 |
| Group and compare | 要求聚类、找模式、列 tradeoffs | 主题分组、优先级、pros/cons |
| Pressure-test | 要求指出假设、风险和失败条件 | 风险清单、需要验证的问题 |
| Turn into plan | 要求把选中的方向变成行动 | owner、timeline、milestone、next steps |

我会把它用于内容选题、产品想法、课程结构和项目计划。关键是不要只问“给我一些点子”，而是问“在这些限制下，我们要做哪个选择”。


## 原创学习增强包

### 三档练习

| 时间 | 练习任务 | 交付物 |
| --- | --- | --- |
| 30 分钟 | 只读本页和来源核对区，提炼 5 条最有用的行动建议。 | 一张“今天就能试”的清单 |
| 2 小时 | 用下面的虚构案例跑一遍完整流程，记录输入、输出、修改和复核点。 | 一份可发布的练习记录 |
| 半天 | 把练习结果改造成自己的模板或小项目，并写下失败案例。 | 模板、prompt pack、复盘笔记 |

### 虚构案例

你要为一个内容系列或产品实验生成方向，然后收敛成 3 个可验证方案。 你可以把输入材料设定为：决策问题、受众、时间、资源、成功指标、不可做事项。最后产出 发散想法池、主题聚类、优先级矩阵、实验计划。

### 原创 Prompt Pack

1. 请围绕这个决策发散 20 个方向，暂时不要评价。
2. 请把这些想法聚类，并命名每一类的核心假设。
3. 请用影响/成本/风险给这些方向排序。
4. 请挑出 3 个可在两周内验证的实验。
5. 请帮我压力测试最强方案，列出失败条件和验证信号。

## 亲测记录模板

> 这一段用于后续真正学完官方材料、跑过练习后继续追加。公开发布时，建议保留方法、过程和复盘，隐藏敏感输入、账号信息、客户资料、未验证结论和不可公开的内部材料。

### 最小实测任务

- 场景类型：团队业务流程
- 建议任务：选择一个真实但可以脱敏的团队任务，从输入整理到交付复盘跑一遍
- 输入材料：业务目标、受众、现有资料、品牌/流程约束、指标
- 目标产物：brief、memo、表格、复盘或下一步行动清单
- 关键边界：事实准确性、团队口径、客户/公司敏感信息

### 记录表

| 记录项 | 建议填写方式 |
| --- | --- |
| 我为什么学这一页 | 写清它和当前工作、学习或项目的关系 |
| 我实际用了什么输入 | 列出材料类型，避免公开敏感原文 |
| 第一版 prompt | 保留自己的写法，方便以后比较 |
| 第一版输出问题 | 记录含糊、遗漏、编造、格式不对或不适用之处 |
| 第二轮反馈 | 写出你如何纠偏：补上下文、加限制、改格式、要求来源 |
| 最终可复用产物 | 沉淀成模板、清单、流程图、评估集或小项目 |
| 人工复核结论 | 标明哪些可以直接用，哪些必须找专业人员或同事确认 |
| 可公开内容 | 只发布脱敏后的流程、经验、失败案例和自己的理解 |

### 复盘问题

1. 这页内容在真实任务中最有用的一点是什么？
2. 第一次输出为什么不够好，是输入问题、模型问题，还是任务本身不清楚？
3. 哪个约束最能提升质量：角色、上下文、来源、格式、示例，还是评价标准？
4. 如果让朋友照着做，哪些步骤需要写得更明确？
5. 这次实测后，我会如何改写本文的个人心得部分？
