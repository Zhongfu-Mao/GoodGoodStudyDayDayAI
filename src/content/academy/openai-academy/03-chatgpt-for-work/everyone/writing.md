**说明：** 本文聚焦于职场写作实战场景，旨在提炼方法论而非单纯复刻官方 Prompt。

## 本模块解决的核心问题

职场写作的主要瓶颈通常不在于“文字修辞”，而在于**目标模糊、受众错位、结构混乱**。ChatGPT 的价值在于协助你跨越“从零到一”的障碍，将原始想法转化为高质量草案，但最终的质量把控与决策权始终属于作者本人。

## 写作四步法

| 步骤 | 核心目标 |
| --- | --- |
| **Plan（规划）** | 明确受众是谁、传达的核心目标、以及希望读者采取的行动。 |
| **Draft（草拟）** | 快速生成第一稿，利用模型打破空白页障碍。 |
| **Revise（修改）** | 优化逻辑结构、调整语气风格、压缩篇幅或增强清晰度。 |
| **Package（包装）** | 针对特定渠道（邮件、备忘录、FAQ、演示文稿脚本）进行格式化适配。 |

## 高效复用模板

```text
任务：请根据以下材料撰写一份 [输出类型]。
受众：[目标读者特征]
核心目标：[读者阅读后需理解/决定/执行的具体事项]
约束条件：
- 必须包含：[关键事实、核心数字、必要限制]
- 严禁包含：[敏感信息、内部行话、夸张性描述]
指令：请先提供逻辑结构大纲，经确认后再输出正文。
```

## 深度解读：从任务导向到流程导向

在 OpenAI 的官方指南中，职场写作被高度抽象为一条极具实战意义的路径：

```text
Plan -> Draft -> Revise -> Package
```

**我的实战理解：**

| 阶段 | 关键自问 |
| --- | --- |
| **Plan** | 这份文档为何而写？读者行动的动力点在哪里？ |
| **Draft** | 如何最快地将零散素材整合为具备逻辑框架的初稿？ |
| **Revise** | 是否存在逻辑断层？语气是否符合职场礼仪？表达是否足够精炼？ |
| **Package** | 渠道属性（如 Slack vs 邮件）对内容格式有哪些特定要求？ |

**这种“流程化写作”的核心优势在于稳定性。** 它将不可控的“创作灵感”转变为可预测、可审计的“标准作业程序”。

## 应用边界：适合与不适合

- **适合场景**：会议纪要跟进、高管摘要提炼、流程说明书起草、多版本语气切换、危机沟通初稿。
- **不适合场景**：未经人工核实的事实声明、涉及法律/合规的外部正式函件、代表组织最终立场的官方公告。



## 完整版学习稿

### 学习定位

本页为 **Writing with ChatGPT** 系统化学习稿。它面向每天需要处理邮件、备忘录、项目更新或演示文稿的职场专业人士。学习重点不在于记忆功能名，而在于将 AI 能力转化为一套闭环的写作方法论。

### 学习目标

- 实现写作模式的转型：从“憋稿”转向 Plan -> Draft -> Revise -> Package 协作模式。
- 确立“人机边界”：由模型负责组织与适配，由人类负责决策事实。
- 建立严苛的复核机制，尤其针对对外发送或涉及敏感信息的文本。

### 官方内容拆解

| 模块 | 学习重点 | 代表性产出物 |
| --- | --- | --- |
| **Plan** | 定义目标、受众与 CTA（行动号召）。 | 写作 Brief、结构大纲、信息架构图。 |
| **Draft** | 快速跨越起步障碍。 | 邮件初稿、备忘录、脚本草案。 |
| **Revise** | 优化多维度的文本表现力。 | 正式版、精炼版、客户导向版。 |
| **Package** | 针对分发渠道进行最后润色。 | 邮件标题、摘要、FAQ 列表。 |

### 标准实操流

1. **前置定义**：明确受众身份与沟通目标。
2. **素材输入**：提供原始笔记、关键事实及明确的“红线”约束。
3. **结构优先**：坚持“先大纲、后正文”的协作顺序。
4. **单点突破**：在修改阶段，每次只针对一个维度（如“缩短篇幅”）下达指令。
5. **责任复核**：发送前强制检查事实准确性、语气得体度及安全边界。

### 核心 Prompt 示例

```text
任务：将以下素材整理为[输出类型]。受众为[受众]，预期目标为[目标]。
要求：先输出文档大纲；严格保留原始事实，禁止虚构未知信息；最后请列出需要我人工进一步确认的潜在风险点。
```
