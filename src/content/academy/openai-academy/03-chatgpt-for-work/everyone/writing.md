**说明：** 本文整理工作写作场景，不复刻官方 prompt pack。

## 这节课解决什么问题

工作写作的难点通常不是“没有文字”，而是目标、受众、结构和下一步动作不清楚。ChatGPT 适合帮助你从粗糙材料到可审阅草稿，但最终判断仍然要由人完成。

## 四步流程

| 步骤 | 目标 |
| --- | --- |
| Plan | 明确写给谁、为什么写、希望读者做什么 |
| Draft | 快速生成第一稿，避免卡在空白页 |
| Revise | 调整清晰度、语气、长度和逻辑 |
| Package | 改成邮件、memo、FAQ、slide copy、script 等渠道格式 |

## 可复用模板

```text
请把以下材料整理成 [输出类型]。
受众：[读者是谁]
目标：[读者看完要理解/决定/行动什么]
必须包含：[事实、数字、限制]
不能包含：[敏感信息、内部术语、夸大说法]
请先给结构，再给正文。
```

## 官方页面的写作流程

Browser Use 抽取到的页面里，官方把多数工作写作归纳成一条很实用的路径：

```text
Plan -> Draft -> Revise -> Package
```

我会这样理解：

| 阶段 | 问题 |
| --- | --- |
| Plan | 这份文字为什么存在，读者看完要做什么 |
| Draft | 先把材料变成可编辑的第一稿 |
| Revise | 调整清晰度、结构、语气、长度和逻辑 |
| Package | 根据渠道改成邮件、memo、公告、脚本或 slide 文案 |

这比“帮我写一封邮件”稳定得多，因为它把写作任务变成了流程。

## 适合和不适合

适合：会议 follow-up、领导摘要、流程说明、公告草稿、不同语气版本。

不适合：未经复核的事实声明、需要法律或合规确认的对外文本、代表组织立场的最终稿。



## 完整版学习稿

### 学习定位

这一页可以当作 **Writing with ChatGPT** 的系统学习稿。它面向每天需要写邮件、memo、更新、FAQ 或演示稿的人，重点不是背官方术语，而是把页面里的能力、场景和边界转成可以反复使用的工作方法。

### 学习目标

- 把写作从“憋最终稿”改成 Plan -> Draft -> Revise -> Package。
- 让模型帮助组织、改写和适配渠道，而不是替你决定事实。
- 建立对外文本和敏感文本的复核习惯。

### 官方内容拆解

| 模块 | 学习重点 | 可产出材料 |
| --- | --- | --- |
| Plan | 目标、受众、读者下一步动作 | brief、大纲、信息架构 |
| Draft | 把材料变成第一稿 | 邮件、memo、公告、脚本 |
| Revise | 清晰度、语气、长度、逻辑 | 短版、正式版、客户版 |
| Package | 适配渠道和格式 | subject、CTA、slide copy、FAQ |

### 实操工作流

1. 先写受众和目标。
2. 给原始材料和必须包含/不能包含项。
3. 先要结构，再要正文。
4. 一次只围绕一个维度修改。
5. 发送或发布前核对事实、语气和责任边界。

### 可复用 Prompt

```text
请把以下材料整理成[输出类型]。受众是[受众]，目标是[目标]。请先给结构，再给正文；保留事实，不补写未知信息；最后列出需要我确认的点。
```

### 复核清单

- 输出是否只使用已提供或可追溯的信息，不把推断写成事实。
- 是否标出不确定性、待确认项和需要人工判断的地方。
- 是否给出可执行的下一步，而不是只生成漂亮文字。
- 是否符合团队、学校、公司或行业的隐私与合规要求。

### 学完应该留下什么

学完这一页，最好不要只留下摘要，而是留下 一份可复用的学习笔记、prompt 模板和实践清单。如果以后要补自己的课程心得，可以在这份材料后面继续追加：真实使用场景、失败案例、改进后的 prompt、以及哪些判断必须由人完成。

## 官方示例拆解

Writing 页的价值在于把“写作”拆成几类可以重复委派的动作，而不是只给一个万能 prompt。

| 任务类型 | 适合输入 | 更好的输出要求 | 人要检查 |
| --- | --- | --- | --- |
| 从零起草 | 目标、受众、必须包含的事实 | 先给结构，再给正文 | 事实是否完整，语气是否符合场景 |
| 改写和收紧 | 粗稿、限制、目标长度 | 标出主要改动，再给新版本 | 是否改变原意，是否删掉关键限制 |
| 调整语气 | 原文、读者、沟通关系 | 给 2-3 个语气版本 | 是否过度圆滑、强硬或营销化 |
| 粗笔记变沟通 | meeting notes、bullet points | 邮件、memo、FAQ、slide copy | 是否把待确认信息写成事实 |
| 渠道包装 | 同一核心信息 | 邮件标题、开头、CTA、短版/长版 | 渠道格式是否真的可发送 |

一个稳定工作法是：先让 ChatGPT 输出 brief 或大纲，再要求它起草，最后只让它针对一类问题修改，比如“缩短 30%”“改成更清楚的 executive tone”“补上风险和下一步”。


## 原创学习增强包

### 三档练习

| 时间 | 练习任务 | 交付物 |
| --- | --- | --- |
| 30 分钟 | 只读本页和来源核对区，提炼 5 条最有用的行动建议。 | 一张“今天就能试”的清单 |
| 2 小时 | 用下面的虚构案例跑一遍完整流程，记录输入、输出、修改和复核点。 | 一份可发布的练习记录 |
| 半天 | 把练习结果改造成自己的模板或小项目，并写下失败案例。 | 模板、prompt pack、复盘笔记 |

### 虚构案例

你有会议记录、几条想法和一个沟通目标，需要产出一封可发送邮件和一页 memo。 你可以把输入材料设定为：受众、目标、原始材料、必须包含/不能包含的信息、语气要求。最后产出 写作 brief、邮件草稿、memo 草稿、修改记录和事实核对表。

### 原创 Prompt Pack

1. 请先根据这些材料生成写作 brief，不要直接写正文。
2. 请把 brief 改成一封邮件，包含 subject、开头、主体和 CTA。
3. 请把同一内容改成一页 memo，适合领导快速阅读。
4. 请把这段文字缩短 30%，但保留事实和下一步动作。
5. 请检查这份草稿是否有夸大、模糊或未经确认的表述。

### 自测问题

- 我能不能用自己的话解释“Writing with ChatGPT”解决的核心问题？
- 我能不能说清它适合哪些场景、不适合哪些场景？
- 我能不能用一个真实或虚构任务跑完整个流程？
- 我能不能指出输出中哪些内容必须人工复核？
- 我能不能把这页内容沉淀成一个模板、清单或小项目？

## 亲测记录模板

> 这一段用于后续真正学完官方材料、跑过练习后继续追加。公开发布时，建议保留方法、过程和复盘，隐藏敏感输入、账号信息、客户资料、未验证结论和不可公开的内部材料。

### 最小实测任务

- 场景类型：团队业务流程
- 建议任务：选择一个真实但可以脱敏的团队任务，从输入整理到交付复盘跑一遍
- 输入材料：业务目标、受众、现有资料、品牌/流程约束、指标
- 目标产物：brief、memo、表格、复盘或下一步行动清单
- 关键边界：事实准确性、团队口径、客户/公司敏感信息

### 记录表

| 记录项 | 建议填写方式 |
| --- | --- |
| 我为什么学这一页 | 写清它和当前工作、学习或项目的关系 |
| 我实际用了什么输入 | 列出材料类型，避免公开敏感原文 |
| 第一版 prompt | 保留自己的写法，方便以后比较 |
| 第一版输出问题 | 记录含糊、遗漏、编造、格式不对或不适用之处 |
| 第二轮反馈 | 写出你如何纠偏：补上下文、加限制、改格式、要求来源 |
| 最终可复用产物 | 沉淀成模板、清单、流程图、评估集或小项目 |
| 人工复核结论 | 标明哪些可以直接用，哪些必须找专业人员或同事确认 |
| 可公开内容 | 只发布脱敏后的流程、经验、失败案例和自己的理解 |

### 复盘问题

1. 这页内容在真实任务中最有用的一点是什么？
2. 第一次输出为什么不够好，是输入问题、模型问题，还是任务本身不清楚？
3. 哪个约束最能提升质量：角色、上下文、来源、格式、示例，还是评价标准？
4. 如果让朋友照着做，哪些步骤需要写得更明确？
5. 这次实测后，我会如何改写本文的个人心得部分？
