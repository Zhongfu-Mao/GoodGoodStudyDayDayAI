**说明：** 本文基于 ChatGPT for Education 公开结构整理，侧重 K-12 学校管理者视角。

## 核心问题

K-12 管理者面对的不是单一工具使用问题，而是全校如何安全、有效、公平地引入 AI。重点包括政策、培训、家校沟通、访问权限、教师支持和评估。

## 管理者要回答的问题

| 问题 | 含义 |
| --- | --- |
| 为什么引入 AI | 是为了教师减负、学生学习、行政效率，还是创新试点 |
| 谁可以使用 | 教师、学生、行政人员的权限是否不同 |
| 如何培训 | 不只是工具操作，还要包括学术诚信、隐私和复核 |
| 如何沟通 | 给家长、教师和学生解释用途和边界 |
| 如何评估 | 看学习支持、教师时间、风险事件和反馈 |

## 实践建议

先从教师工作流和行政支持开始，比直接大规模开放给学生更稳。管理者应先建立透明规则，再逐步扩大场景。



## 完整版学习稿

### 学习定位

这一页可以当作 **K-12 Admins** 的系统学习稿。它面向K-12 学校和学区管理者，重点不是背官方术语，而是把页面里的能力、场景和边界转成可以反复使用的工作方法。

### 学习目标

- 在教师支持、学生安全、家校沟通和政策制定中使用 AI。
- 平衡创新、隐私、年龄适配和公平性。
- 把 AI 使用落到培训、流程和沟通上。

### 官方内容拆解

| 模块 | 学习重点 | 可产出材料 |
| --- | --- | --- |
| Policy | AI 使用范围、学生数据、家长沟通 | policy draft |
| Teacher support | 备课、反馈、资源共享 | PD plan |
| Student safety | 年龄适配、隐私、监督 | safety checklist |
| Communication | 家长、教师、社区说明 | FAQ 和通知 |
| Evaluation | 试点效果和风险 | metrics |

### 实操工作流

1. 先定义学区或学校的 AI 原则。
2. 区分教师、学生和行政用例。
3. 制定隐私和年龄适配规则。
4. 准备培训和沟通材料。
5. 小范围试点并复盘。

### 可复用 Prompt

```text
请为 K-12 学校制定一份 AI 使用试点计划。请覆盖教师用例、学生边界、隐私和家长沟通、培训安排、风险管理和评估指标。
```

### 复核清单

- 输出是否只使用已提供或可追溯的信息，不把推断写成事实。
- 是否标出不确定性、待确认项和需要人工判断的地方。
- 是否给出可执行的下一步，而不是只生成漂亮文字。
- 是否符合团队、学校、公司或行业的隐私与合规要求。

### 学完应该留下什么

学完这一页，最好不要只留下摘要，而是留下 一份可复用的学习笔记、prompt 模板和实践清单。如果以后要补自己的课程心得，可以在这份材料后面继续追加：真实使用场景、失败案例、改进后的 prompt、以及哪些判断必须由人完成。

### 虚构案例

K-12 学区要制定 AI 试点计划，同时回应家长和教师关切。 你可以把输入材料设定为：年级范围、工具、隐私政策、教师需求、家长关切。最后产出 学区 AI 试点计划、家长沟通稿、教师培训大纲。

### 原创 Prompt Pack

1. 请为 K-12 学区设计 AI 试点计划。
2. 请写一份面向家长的 AI 使用说明。
3. 请列出教师培训的核心模块。
4. 请设计学生隐私和年龄适配检查表。
5. 请为试点后复盘设计调查问题。

## 亲测记录模板

> 这一段用于后续真正学完官方材料、跑过练习后继续追加。公开发布时，建议保留方法、过程和复盘，隐藏敏感输入、账号信息、客户资料、未验证结论和不可公开的内部材料。

### 最小实测任务

- 场景类型：教育/学习场景
- 建议任务：选择一个不会违反课程或学校规则的教学、学习支持或行政任务
- 输入材料：课程目标、学生水平、规则边界、评价标准、时间预算
- 目标产物：学习活动设计、反馈清单、复习计划或行政草稿
- 关键边界：学术诚信、学生隐私、教师最终判断

### 记录表

| 记录项 | 建议填写方式 |
| --- | --- |
| 我为什么学这一页 | 写清它和当前工作、学习或项目的关系 |
| 我实际用了什么输入 | 列出材料类型，避免公开敏感原文 |
| 第一版 prompt | 保留自己的写法，方便以后比较 |
| 第一版输出问题 | 记录含糊、遗漏、编造、格式不对或不适用之处 |
| 第二轮反馈 | 写出你如何纠偏：补上下文、加限制、改格式、要求来源 |
| 最终可复用产物 | 沉淀成模板、清单、流程图、评估集或小项目 |
| 人工复核结论 | 标明哪些可以直接用，哪些必须找专业人员或同事确认 |
| 可公开内容 | 只发布脱敏后的流程、经验、失败案例和自己的理解 |

### 复盘问题

1. 这页内容在真实任务中最有用的一点是什么？
2. 第一次输出为什么不够好，是输入问题、模型问题，还是任务本身不清楚？
3. 哪个约束最能提升质量：角色、上下文、来源、格式、示例，还是评价标准？
4. 如果让朋友照着做，哪些步骤需要写得更明确？
5. 这次实测后，我会如何改写本文的个人心得部分？
