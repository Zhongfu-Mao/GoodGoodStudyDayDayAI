Claude API を使う開発では、単に SDK でメッセージを送るだけでは足りません。モデル選択、プロンプト設計、出力形式、ストリーミング、エラー処理、評価、コスト管理まで含めて「壊れにくい呼び出し」を設計します。

## このノートで押さえること

- API リクエストは、入力、システム指示、ツール、モデル、出力制約の組み合わせとして設計する。
- 本番では成功時のレスポンスだけでなく、タイムアウト、レート制限、再試行、監査ログを考える。
- モデル選択は品質、速度、コスト、コンテキスト長、ツール利用の観点で決める。
- 構造化出力と eval を入れると、LLM 呼び出しをアプリの部品として扱いやすくなる。

## API リクエストの基本形

Claude API の中心は Messages API です。ユーザー入力だけでなく、system instruction、過去メッセージ、ツール定義、出力制約、最大トークン数を組み合わせて呼び出します。

アプリケーション側では、ユーザー入力をそのまま渡すのではなく、目的、利用可能なデータ、禁止事項、望ましい形式をサーバー側で組み立てます。これにより、ユーザーごとの入力揺れに強くなります。

出力が UI や後続処理に入る場合は、自由文だけにせず、JSON などの構造を決めます。失敗時に再試行や修復ができるようにするためです。

## 本番アプリで必要な周辺設計

LLM 呼び出しは外部 API なので、失敗を前提にします。タイムアウト、レート制限、ネットワークエラー、コンテンツポリシーによる拒否、予期しない形式の出力をハンドリングします。

ログには、プロンプト全文を無制限に残すのではなく、リクエスト ID、モデル、レイテンシ、トークン、エラー種別、評価結果を残します。機密情報の扱いには注意します。

ストリーミングは体感速度を改善しますが、途中でキャンセルされた場合や不完全な JSON が返る場合を考慮します。UI 用のストリーミングと機械処理用の構造化出力は分けて設計すると扱いやすくなります。

## モデル選択と評価

モデル選択は「一番強いモデルを常に使う」ではありません。短い分類、下書き、要約、深い推論、コード生成、長文読解で必要な品質とコストは違います。

まず代表的な入力を集め、小さな eval セットを作ります。正解が明確なタスクでは期待出力を持ち、文章品質のタスクでは人間レビュー用の観点を定義します。

モデルを変えるときは、コストだけでなく失敗パターンを比較します。速く安いモデルで十分な箇所と、上位モデルが必要な箇所を分けるのが実務的です。

## 読者向け補足：API 呼び出しを製品機能として扱う

Claude API は、単に prompt を送って返答を受け取るだけならすぐ試せます。しかし製品に入れるなら、入力検証、timeout、retry、rate limit、ログ、評価、ユーザーへの失敗表示まで含めて一つの機能として設計する必要があります。

特に生成結果を後続処理に渡す場合は、自由文より schema を優先します。JSON schema、列挙値、最大長、必須フィールドを決め、失敗時に修復するか人間確認に回すかを明示します。

| 層 | 見ること |
| --- | --- |
| Request | system 指示、user 入力、添付文脈、モデル選択 |
| Runtime | timeout、retry、rate limit、cost logging |
| Output | schema validation、引用、禁止表現、fallback |
| Eval | golden cases、失敗分類、regression check |

### ミニ演習

既存アプリに「文章要約」機能を追加する想定で、成功条件、失敗条件、ログに残す項目、ユーザーに見せる fallback 文を設計します。実装前に 10 件のテスト入力も用意します。

## 実務で試すワークフロー

1. 最初に 20 件の代表入力を集め、期待出力と失敗条件を定義する。
2. API 呼び出しを wrapper 化し、モデル、レイテンシ、トークン、エラー種別を必ずログに残す。
3. 構造化出力が必要な箇所は JSON schema と再試行ルールを先に決める。

## Prompt pack

- この LLM API 呼び出しを本番化する前に必要なエラー処理、ログ、評価観点をチェックリスト化してください。
- 次のタスクに対して、安いモデルで十分な部分と高性能モデルが必要な部分を分けてください。
- このプロンプトの出力を JSON schema に合わせるため、制約とリトライ方針を設計してください。

## 自分で確認する

- API 呼び出しの失敗時挙動を説明できる。
- モデル変更を eval で比較できる。
- 構造化出力の検証と再試行が設計されている。
