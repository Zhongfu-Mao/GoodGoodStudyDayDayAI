## 一、认识 Claude Cowork

### 第1节：什么是 Cowork？

> 预计时长：15 分钟

#### 核心概念

Cowork 建立在与 Claude Code 相同的底层架构之上——Claude Code 是用于编写和交付生产级软件的代理系统。这种能力现在被引入到了知识工作领域：分析、研究、写作，以及你每天需要产出的各类文档。

**最核心的转变**：从"对话"到"委托"。你不再是粘贴文本、等待文字回复，而是描述一个结果，Cowork 规划步骤、执行任务，并将完成的文件交付到你的硬盘上。

#### Cowork 与 Chat 的区别

Chat 的价值在于：提问、获取答案、粘贴文档、获取摘要——这个循环本身很有价值，也将继续存在。但某些工作仍然留在你这一侧：你还是需要在工具之间搬运信息、拼装输出、处理中间步骤。

Cowork 通过三件事改变了这种交换模式：

| 阶段 | 说明 |
|------|------|
| **Plan（规划）** | 对于多步骤任务，Claude 在开始前展示执行方案，你审查、调整、批准 |
| **Execute（执行）** | 任务在你电脑上的隔离环境中运行，时间不限——文件创建、分析、长任务，可以放手不管 |
| **Connect（连接）** | Cowork 可以接入你工作所在的系统：邮件、共享云盘、你已登录的工具，上下文自动流入，无需手动复制粘贴 |

#### Cowork 能做什么

- **Connectors（连接器）**：接入邮件、消息、共享云盘等现有工具，上下文自动流入
- **File operations（文件操作）**：直接读取、编辑、创建硬盘上的文件——演示文稿、表格、文档，成品文件保存在你的硬盘上
- **Plugins（插件）**：为你的角色封装领域专业知识，Claude 像专家一样处理任务
- **Scheduled tasks（定时任务）**：按你设定的节奏自动运行任务
- **Local computation（本地计算）**：直接在文件上运行代码并写回结果，无需上传再下载

#### 何时选 Cowork vs Chat

**选 Cowork**，当：
- 你想要一个可以打开的成品文件
- 任务涉及你硬盘上的文件或已连接的工具
- 有很多步骤，或很多条目需要处理
- 你想放手让它运行，自己去做别的事

**选 Chat**，当：
- 你想要一个答案，或自己打磨的草稿
- Claude 需要的内容一次性粘贴就够了
- 你想逐轮一起思考推敲

> 📌 **判断题**：这个任务需要接触我的文件、连接的工具，或者产出一个真实的输出文件吗？如果是，Cowork 是好选择。

### 第2节：开始设置

> 预计时长：7 分钟

#### 前提条件

Cowork 运行在 **Claude 桌面应用**中，需要付费计划。

#### 打开 Cowork

打开 Claude 桌面应用，顶部的模式切换器可以在 Chat、Cowork 和 Code 之间切换，点击 Cowork 即可。

如果看不到 Cowork 选项，检查是否在付费计划，以及桌面应用是否是最新版本。

#### 指向一个工作文件夹

这是与 Chat 最核心的区别：**你给 Claude 一个工作目录，它可以直接在那里读取、创建和编辑文件——无需上传，无需下载。**

点击"Work in a folder"并选择一个文件夹即可开始。

#### 连接工具

Connectors 将 Cowork 链接到你工作所在的服务——Slack、Google Drive、Gmail、Calendar 等。**只需设置一次**，之后每个任务都能从中拉取内容。

在 Cowork 的"Customize"区域找到列表，开启你使用的工具。连接后，你可以在提示中自然地引用它们，Claude 也可以在已连接的工具中执行操作（比如在 Gmail 起草邮件，在 Drive 保存文件）。

#### 添加 Claude in Chrome

有些工作存在于没有连接器的页面上——内部仪表板、供应商门户、登录后的 Web 应用。**Claude in Chrome** 就是 Cowork 触达这些地方的方式。从同一个 Customize 区域安装，按网站授权权限，Cowork 就能打开页面、读取内容，并将其作为任务的一部分进行交互。

## 二、运行你的第一个任务

### 第3节：任务循环

> 预计时长：15 分钟

#### 核心循环

**Claude 提出计划 → 等待你批准 → 你调整后批准 → Claude 执行。** 这是每个 Cowork 任务的固定模式。

**第一步：描述你想要的结果**

好的提示要给 Claude 三个信息：看什么、要什么、放哪里。不需要精心设计完美的提示词——Claude 会针对你遗漏的内容追问。

> 示例提示：*"本周有三家我们覆盖的公司公布了财报，转录稿在我的文件夹里，还有我们的模型和上季度的备忘录。对照我们的模型逐一分析，突出超预期和不及预期的地方，然后将三篇分析汇总成一份报告，格式参考上季度备忘录，保存到同一文件夹。"*

**第二步：回答几个问题**

基于你的提示和 Claude 发现的内容，Claude 会追问几个问题来确保输出正确——采用哪种方式、优先处理什么、成品应该是什么格式。选择 Claude 提供的选项之一，或者输入自己的答案。

**第三步：放手，或介入**

进度面板显示每个步骤：Claude 在读哪些文件、在构建什么。对于大型任务，Claude 会将工作拆分成若干部分并行处理。你可以离开去做别的，也可以在聊天中输入来纠正方向——不需要等它完成。

**第四步：打开成品**

结果保存在你指向的位置——在你的文件夹里，紧邻 Claude 读取的那些文件旁边。

**以对待初稿的心态对待结果**——像对待一个有能力的同事的第一份工作成果一样：好的工作，但仍需你来打磨，然后才能发出去。

#### Cowork 的运作机制（了解一下有助于写更好的提示）

- **Subagents（子代理）**：当任务有独立的部分时，Cowork 可以启动多个子代理同时运行，每个有自己专注的上下文。比如对比四个供应商：每个供应商一个子代理，各自研究定价、集成和评价，互不干扰。结果汇聚成一个输出。
- **进度可见**：面板显示哪个步骤在进行、在读哪些文件、在构建什么。可以跟进，也可以忽略。
- **可以随时介入**：在聊天中输入即可纠偏，无需等待完成。
- **隔离环境**：代码运行和文件构建发生在你电脑上的隔离环境中，与主系统分开，不会触碰你未授权的任何内容。
- **删除有把关**：Cowork 在永久删除文件前会先询问你，你来批准或拒绝。

#### 实战演示：散乱文件夹 → 完成的演示文稿

**起点**：一个有各种积累的项目文件夹：会议记录、清单、时间表格、保存的邮件、对比矩阵——不同格式，松散组织。

**提示**：*"把这个文件夹里的所有内容整理成一份业务案例演示文稿，保存为 PowerPoint。"*

**审查计划**：Cowork 展示计划：读取文件 → 综合提案 → 构建业务案例 → 生成幻灯片 → 审查结果。如果你想加什么（比如同时输出 PDF），在这里说。

**放手运行**：去开会也没关系，任务继续。

**打开文件**：这是一个真实的 PowerPoint 文件，图表是可点击可编辑的元素。这是一份草稿，但起点比自己从头拼装要接近完成得多。

#### 建议：从小处开始

从有清晰边界的任务开始——整理文件夹、综合一批文档。建立直觉，了解 Cowork 擅长什么，然后再放大规模。

### 第4节：给 Cowork 提供上下文

> 预计时长：10 分钟

#### 为什么需要这个

每个 Cowork 任务都从头开始——Claude 不会在任务之间携带对话记忆。**Project（项目）** 就是解决方案：每个项目都有自己的文件、上下文、指令和记忆，专属于一块工作。

如果你在 Chat 中使用过项目，Cowork 项目工作方式类似——但它们本地存储在你的电脑上，与 Chat 项目分开。

项目在 Cowork 的侧边栏里，可以从头新建，或从 Chat 项目导入（文件和指令）。

#### Instructions 里放什么

进入项目后，右侧面板有 **Instructions** 区域。你在里面写的内容会在每次任务时被读取：

| 类型 | 示例 |
|------|------|
| **谁参与其中** | 姓名、角色、联系方式——这样"发给 Rachel"就有意义了 |
| **内容在哪里** | "合同在 ./Contracts，旧报告在 Drive /archive/[年份]" |
| **输出偏好** | "草稿用 .docx，终稿用 PDF，保存到 deliverables 子文件夹" |
| **项目专属规则** | "全程使用公制单位，每个数字都注明来源" |

不需要写得精致，几行就够。效果是：**缩写开始生效**。一旦 Instructions 建立起来，你就可以说"按常规方式发给 Rachel"而不需要解释。

Claude 也会读取你项目文件夹里的所有内容。对于你想让 Claude 持续维护的上下文——持续运行的日志、参考文档——可以把文件放进项目文件夹。

#### 全局指令（Global Instructions）

对于项目之间不变的偏好——你的角色、默认输出格式、固定规则——在全局指令中设置。这些适用于所有 Cowork 任务。

#### 验证是否生效

在你的项目内问：**"告诉我你对我在这里工作方式的了解。"** 你就能看出 Instructions 和文件夹内容是否被正确读取了。

## 三、让 Cowork 成为你的专属工具

### 第5节：插件——让 Cowork 成为专家

> 预计时长：15 分钟

#### 什么是插件

插件给 Cowork 提供领域专业知识。每个插件都带有针对特定角色或领域的内置知识和工作流。

**插件是一个捆绑包**，包含多个部分：

| 组成部分 | 说明 | 示例 |
|----------|------|------|
| **Skills（技能）** | 处理特定工作流的指令，Claude 自动调用或你主动触发 | 如何构建 deal brief、`/prep-call`、`/weekly-report` |
| **Connectors（连接器）** | 接入工作发生的系统 | 你的 CRM、文档、消息工具 |
| **Subagents（子代理）** | 并行处理专项工作 | 按账户并行运行的 book-wide review |

大多数知识工作角色都有开源插件可用：销售、市场、产品、财务等。

#### 安装插件

1. **浏览**：插件在 Cowork 的"Customize"区域，找到匹配你工作的那个
2. **安装**：一键安装，立即生效
3. **自定义**：安装后，插件是你机器上的一个文件夹，所有内容都是可读可编辑的纯文本

#### 插件的内部结构

插件就是一个文件夹，大致结构如下：

```
sales-plugin/
├── plugin.json        ← 清单：名称、描述、依赖
├── skills/
│   ├── prep-call/
│   │   └── SKILL.md   ← 每个 skill 的指令文件
│   └── weekly-report/
│       └── SKILL.md
└── connectors/        ← 连接器配置
```

每个文件都是纯文本。要修改某个 skill 的工作方式，打开文件直接编辑。要添加新 skill，按照同样的结构新建一个文件夹。

#### 关于 Skills

Skills 是插件内部的核心构建模块。一个 skill 是一个 markdown 文件，告诉 Claude 如何完成某件特定的事——Claude 在相关时自动应用，或你使用 `/skill-name` 主动调用。

**Skills 不局限于 Cowork**，它们跨越 Claude 的所有界面工作——在 Chat、Claude Code 等地方都有效。

相关资源：
- [Skills 视频课程（YouTube）](https://www.youtube.com/playlist?list=PLmWCw1CzcFim_hkruZSlABOUOAAQ5JMyo)
- [Introduction to Agent Skills（完整课程）](https://anthropic.skilljar.com/introduction-to-agent-skills)

### 第6节：定时任务

> 预计时长：8 分钟

#### 按节奏运行工作

定时任务可以按你设定的节奏自动运行任何 Cowork 任务——每小时、每天、每周，或自定义间隔。

> 示例：*"每周一早上 9 点，拉取我的日历并起草一封每周优先事项邮件。"*

#### 如何设置

在任意 Cowork 对话中输入 `/schedule`，或使用侧边栏的定时任务区域。Claude 会引导你完成设置。

有一个**批准步骤**——因为你是在签署一个会反复执行的任务。批准后，任务就会按计划运行。

如果你从一个项目内部创建定时任务，它会出现在该项目其他定时任务的旁边。

#### 管理定时任务

在定时任务区域，你可以查看过往运行记录、编辑指令或节奏、暂停任务或删除它。

#### 一个常见组合模式

**定时任务和 skills 天然配合**：skill 编码"做什么"，定时任务决定"什么时候做"。但你不需要 skill 才能安排定时任务——任何运行良好的任务都可以定时化。

**关于睡眠/关闭的行为**：
- 电脑**睡眠**没问题——会话唤醒后继续
- 如果应用程序**关闭时任务到期**——任务会在你重新打开时立即运行

## 四、Cowork 实践案例

### 第7节：文件与文档任务

> 预计时长：10 分钟

#### Cowork 产出的是真实文件

- **演示文稿**：带可编辑图表（点击即可修改数据和格式）
- **表格**：带有效公式
- **文档**：带修订标记

输出是**原生格式**，不是截图或导出件。

#### 适合早期上手的任务类型

**整理现有内容：**
- "将我的下载文件夹按文件类型整理进带日期的子文件夹。"
- "用统一的日期优先格式重命名这个文件夹里的所有文件。"
- "从这个文件夹里的收据生成一份格式化的报销单。"

**创建所需内容：**
- "从这些笔记创建一个项目跟踪表格，包含状态列和摘要视图。"
- "把这些会议记录做成幻灯片，使用 brand-guidelines skill。"
- "把这个文件夹里的转录稿和笔记合并成一份格式化报告。"

#### 提示的结构模式

好的提示包含三个要素：

| 要素 | 说明 | 示例 |
|------|------|------|
| **Input（输入）** | 素材在哪里 | "我的下载文件夹"、"这些会议记录"、"这个文件夹" |
| **Transformation（转换）** | 对它做什么 | "按类型整理"、"做成幻灯片"、"合并成" |
| **Output（输出）** | 产出什么格式 | "带日期的子文件夹"、"带摘要视图的表格"、"格式化报告" |

❌ "整理我的文件" ——没有这三个要素

✅ "将我的下载文件夹按文件类型整理进带日期的子文件夹" ——清晰、完整

### 第8节：大规模研究与分析

> 预计时长：10 分钟

#### Chat vs Cowork 在研究任务上的区别

Chat 在素材能放进一次对话时表现很好：粘贴、讨论、迭代。Cowork 更擅长以下情况：

| 场景 | 说明 |
|------|------|
| **Volume（体量）** | 文件太多无法粘贴，或文件太大无法一次性容纳。Cowork 直接在原地读取，无需上传步骤 |
| **Parallelism（并行）** | "对 N 个条目做同样的分析"——Cowork 可以同时处理，而不是逐个排队 |
| **In-place computation（原地计算）** | 直接在文件所在位置运行代码并写回结果，无需上传再下载 |

#### 典型使用案例

**研究综合**
把笔记、文章、论文、保存的研究内容整合成一份连贯的报告。
> *"读取研究文件夹里的所有内容，写一份综合报告。这些来源在哪里一致？在哪里有分歧？"*

**转录分析**
从会议记录、访谈或录音转录稿集合中提取主题、决策和行动项。
> *"读取这个文件夹里的所有转录稿。大多数人在哪些方面达成了一致？谁有异议，他们有什么共同点？"*

**数据分析**
对数据文件进行统计分析：异常值检测、交叉制表、时间序列。
> *"对这个文件里的每个客户，计算月度环比使用量变化。标记连续三个月下降的账户——这可能是流失风险。"*

**知识综合**
把 Cowork 指向你自己积累的笔记、日志或项目文件，问它发现了什么规律。
> *"读取我过去六个月的所有项目笔记。哪些问题反复出现？我做了哪些决定，现在看来我是否仍然认同？"*

#### 提问框架：找信号，而不是生成摘要

最有用的提示不是"总结一切"，而是你自己想回答的那个问题：

| 弱提示 | 强提示 |
|--------|--------|
| "总结这些转录稿" | "大多数人在哪些方面达成了一致？谁有异议，他们有什么共同点？" |
| "分析这些数据" | "哪些账户有风险？过去三个月的共同规律是什么？" |
| "回顾这些论文" | "这些论文在哪里相互矛盾？哪些说法需要最多注意事项？" |

**越精准的问题，越能得到可行动的答案。**

## 五、负责任地使用

### 第9节：权限、用量与模型选择

> 预计时长：10 分钟

#### 权限与安全边界

Cowork 可以读写真实文件、连接真实系统。以下是规范其运作的边界：

| 边界 | 说明 |
|------|------|
| **隔离执行** | 工作在你电脑上的隔离环境中运行，与操作系统分开。Cowork 无法访问隔离环境之外的系统 |
| **受控文件访问** | 你决定 Cowork 能看到哪些文件夹，不授权就无访问权 |
| **网络策略尊重** | Cowork 遵循你组织的网络规则，受限环境依然受限 |
| **删除有把关** | 永久删除需要你的明确批准，你会先看到提示 |

> ⚠️ **值得注意**：Cowork 对话历史存储在你的本地机器上。检查你的计划文档了解具体细节。

#### 审查 Cowork 做了什么

在将输出发送出去或据此行动之前，请审查它。**输出越精美，越容易跳过这一步，但正是这时最不应该跳过。**

养成习惯：**打开文件，核查一个数字，沿着一条推理线索追下去。**

#### 管理用量

Cowork 比 Chat 消耗更多用量——多步骤、长时间运行的任务更消耗算力。几个省量技巧：

- **批量处理相关任务**：开启一个新会话是有成本的，如果有几个相关任务，在一个会话中完成比分开运行更高效
- **适合 Chat 的就用 Chat**：如果任务不需要你的文件、连接的工具或真实输出文件，Chat 通常更快更省量
- **监控用量**：Cowork 设置中有用量可见性，定期查看，尤其是刚开始建立习惯的阶段

#### 选择合适的模型

使用哪个模型也影响用量消耗。Claude 模型分三个能力层级：

| 层级 | 模型 | 适用场景 |
|------|------|----------|
| 高 | Opus | 复杂推理、高难度任务 |
| 中 | Sonnet | 大多数日常任务 |
| 低 | Haiku | 简单、快速的任务 |

**匹配模型与任务需求**，而不是对所有事情都默认用最高档。

### 第10节：故障排查与下一步

> 预计时长：10 分钟

#### 常见问题与处理方式

**Cowork 正在准备工作区**
Cowork 在启动前需要准备好环境，这比普通的 Chat 回复花时间更长，属于正常现象。

**任务中途停止**
最常见原因：桌面应用在任务运行时被退出了。电脑**睡眠**没问题——会话会恢复。但**退出应用**会中断任务。

**遇到用量限制**
Cowork 比 Chat 消耗更多用量，在更强大模型上运行的长任务消耗最多。把相关任务批量处理，对合适的任务用 Chat，并定期检查剩余用量。

**找不到 Cowork 说它创建的文件**
输出可能落在了与预期不同的文件夹，或者 Cowork 指向的文件夹与你查找的位置不同。回头检查任务结束时 Cowork 显示的保存路径。

#### 推荐的推进路径

目标：**有一个你信任的 skill，在定时任务上运行**。到达那里的步骤：

1. **安装一个插件**：浏览插件库，选一个最匹配你角色的安装。打开插件文件夹，读一个 skill 文件——看看它是什么样的可读文本
2. **运行真实任务**：选一个来自你实际工作的任务——哪怕很小，但要真实。你在寻找的是：*"对，就是这样，这省了我的时间"*
3. **做一个 skill**：如果你产出有品牌规范的内容，先做一个 brand-guidelines skill；否则，下次运行任务时，把你在聊天中给 Claude 的额外指令提炼成一个 skill
4. **定时它**：把 skill 放到定时任务上
5. **分享它**：把 skill 打包给队友，或在 Team/Enterprise 计划上联系管理员让它成为组织级 skill

> 按适合你工作的节奏推进，**顺序比时机更重要。**

## 课程总结

Cowork 是从"对话"到"委托"的转变——你描述结果，Claude 规划、执行、交付。核心能力：

- **Plan → Execute → Connect** 三阶段循环
- **Project + Instructions** 建立跨任务持续生效的上下文
- **Plugins** 封装角色专属专业知识
- **定时任务** 让可靠的工作流自动运行
- **Skills** 是跨平台的核心构建模块

**从小处开始，边界清晰的任务——然后扩大规模。**
