Claude 101 の中心は、Claude を「一問一答のチャット」ではなく、文脈を共有しながら一緒に考える作業相手として扱うことです。ここでは基本能力、良い依頼の作り方、Projects や Artifacts の使いどころを実務目線でまとめます。

## このノートで押さえること

- Claude は文章、分析、推論、コード、学習支援を横断する汎用アシスタントである。
- 良い結果は、背景・目的・制約・期待する形式を渡し、往復しながら改善することで生まれる。
- Projects、Artifacts、Memory、ファイルアップロードを使うと、単発の会話から継続的なワークフローに変えられる。
- モデルの違いは「速さ」「深い推論」「コーディング」「長文処理」の観点で選ぶと分かりやすい。

## Claude をどう捉えるか

Claude は検索エンジンではありません。検索の代わりに使うと、根拠のない断定や古い情報に引っかかることがあります。強みは、与えられた材料を読み、構造化し、選択肢を出し、文章やコードに変換することです。

最初に伝えるべきことは、目的、読者、背景、利用できる資料、避けたいこと、出力形式です。これらが欠けると、Claude は一般論で補おうとします。

Claude は一度で完璧に当てるより、下書き、レビュー、再構成、最終調整のような反復で力を発揮します。

## 代表的な使い方

文章作成では、メール、提案書、ブログ、議事録、仕様書の下書きに使えます。大切なのは、声のトーン、読者、目的を明確にし、最後は自分の言葉に整えることです。

分析では、長い文書の要約、比較表、論点整理、リスクの洗い出しに向いています。ファイルを渡す場合は、どの観点で読むかを指定すると精度が上がります。

コーディングでは、実装方針の相談、エラー調査、テスト設計、コードレビューの補助に使えます。実行結果やエラーログを共有すると、会話が現実のコードに近づきます。

学習では、概念の説明、例題作成、理解確認、復習計画に使えます。答えを受け取るだけでなく、自分の理解をチェックしてもらう使い方が有効です。

## Projects / Artifacts / Memory

**Projects** は、同じ目的の資料、指示、会話をまとめる場所です。チームや長期テーマでは、毎回ゼロから説明しないための文脈置き場になります。

**Artifacts** は、文章、コード、表、HTML などを会話の横で編集するための作業面です。下書きを見ながら修正したいときに向いています。

**Memory** は、継続的に覚えておくべき好みや前提を扱います。便利ですが、機密情報や一時的な情報を入れすぎないことが大切です。

## 良い依頼の型

良い依頼は「背景」「目的」「素材」「制約」「出力形式」「評価基準」を含みます。たとえば、単に「この文章を直して」ではなく、「読者は初学者、目的は不安を減らすこと、専門用語は避ける、見出し付きで 600 字に」と伝えます。

また、最初から完成品を求めるより、「まず構成案」「次に弱点レビュー」「最後に仕上げ」のように分けると、判断を挟みやすくなります。

## 実務で試すワークフロー

1. よく使う仕事を一つ選び、Claude に毎回渡す背景メモを作る。
2. 同じ依頼を「短い依頼」と「文脈つき依頼」で試し、差分を観察する。
3. 良かった出力のプロンプトを Project の指示や自分用テンプレートに残す。

## Prompt pack

- あなたは私の作業パートナーです。次の目的、読者、素材、制約をもとに、まず構成案だけを作ってください。
- この出力をそのまま採用せず、弱い根拠、曖昧な表現、読者に伝わりにくい箇所をレビューしてください。
- 次の会話ログから、今後同じ作業をするときに使える Project instructions を作ってください。

## 自分で確認する

- Claude に任せる前に、目的と読者を一文で書ける。
- 出力をレビューし、採用しない部分を説明できる。
- 単発チャットと Project を使い分けられる。
