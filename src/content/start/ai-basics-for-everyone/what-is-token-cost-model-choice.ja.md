## まず一言で

**Token（トークン）**はモデルがテキストを分割して扱う単位です。文字や単語との固定の換算比率はなく、言語・文字列・トークナイザーによって変わります。見積もりには対象モデルの計数ツールや API の使用量を使います。

## 料金の仕組み

テキスト API では入力・出力を別単価で計算する方式が一般的ですが、キャッシュの読み書き、ツール、画像、音声には別の単位や追加料金がある場合があります。具体的なモデルと利用経路の料金表を確認してください。

単価が「100 万 token あたり」の場合、概算の基本は次の通りです。

> タスク費用 = 各呼び出しの（入力 token × 入力単価 + 出力 token × 出力単価）÷ 1,000,000 の合計 + ツール・実行環境などの費用

キャッシュ分は通常入力と二重に計上せず、対応する単価で分けて計算します。推論 token の扱いなども利用先に従います。リトライとエージェントのループをすべて含め、月額は実測のタスク費用と想定件数から見積もります。これは費用構造の説明で、特定サービスの見積もりではありません。

チャット製品の定額契約と開発者 API は別の契約・課金である場合があります。含まれる機能、使用上限、追加料金を確認し、API 実験では小さな予算上限を設けます。

## Context Window とは

モデルが 1 回で扱える token 数の上限で、「作業机の広さ」に例えられます。入力、会話履歴、ツール定義、出力の枠など、何を含むかは API ごとに確認します。

上限超過時にはエラー、切り詰め、要約などが起こり得ます。古い情報から必ず自動で削除されるわけではありません。軽量モデルか高性能モデルかという分類からウィンドウサイズや料金を推測せず、対象の仕様を確認します。

| 確認項目 | 見るもの |
| --- | --- |
| 入力が収まるか | 実際の token 数と、出力用に残す枠 |
| 長文を正確に使えるか | 必要箇所の引用と照合、情報の欠落 |
| 費用と速度は許容範囲か | 使用量、キャッシュ条件、応答時間の実測 |

長い資料では全文、検索、要約を比較し、正確さ・費用・遅延のバランスを測ります。

## モデルの選び方

タスクの性質に合わせて、コストとパフォーマンスのバランスが良いモデルを選択しましょう。

| タスクの性質 | 適しているモデル |
| --- | --- |
| シンプルな Q&A、日常的な雑談 | 軽量で応答速度の速いモデル |
| 膨大な資料の分析、複雑な論理推論 | 高性能モデル ＋ 大容量のウィンドウ |
| プログラミング、デバッグ | 自分のコードとテストで品質を確認したモデル・ツール |
| 最新の情報に基づいた回答 | ブラウジング（検索）機能付きモデル |
| 大量のデータを安価に処理したい | 軽量モデル ＋ 構造化プロンプト |

## やってみよう

ChatGPT などのツールで、短い質問と、長い資料を添付した質問を交互に送り、応答が始まるまでの時間の違いを体感してみてください。また、「100 文字以内で簡潔に答えてください」といった指示を加えることで、出力トークン数を制御する感覚を掴むことができます。

## 実用的なチェックポイント

新しいツールやモデルを選ぶ際は、以下の 4 点をあらかじめ整理しておくとスムーズです。

1. このタスクを完遂するために、どの程度の情報量（コンテキスト）を読み込ませる必要があるか？
2. 「最強のモデル」が必要な難易度か、それとも「十分な性能」で足りるか？
3. 単発の作業か、それとも繰り返し実行する自動化タスクか？
4. 許容できるコストや予算はどの程度か？
