## まず一言で

**Token（トークン）**は、AI がテキストを処理する際の最小単位です。日本語の場合、漢字 1 文字はおよそ 1〜3 トークン、英単語 1 語は 1〜4 トークン程度として計算されます。AI サービスの利用料金、コンテキストの制限、そして応答速度はすべて、このトークン数に直結しています。

## Token とは

AI はテキストを「文字」や「単語」そのものではなく、トークンという数値化された断片として扱います。

| テキストの例 | おおよそのトークン数 |
| --- | --- |
| 「こんにちは」 | 約 1〜3 トークン |
| "Hello world" | 約 2 トークン |
| 500 文字程度のメール | 約 300〜700 トークン |
| 5,000 文字程度の記事 | 約 3,000〜7,000 トークン |

※使用する AI モデル（言語モデル）によって計算方法は異なります。

## 料金の仕組み

多くの AI API（開発者向けサービス）は、**「入力トークン数 ＋ 出力トークン数」**に基づいた従量課金制を採用しています。一般的に入力は出力よりも安価に設定されており、より高性能なモデルほどトークン単価が高くなる傾向にあります。

一般的なユーザーが利用する ChatGPT Plus や Claude Pro のような月額サブスクリプション制は、このトークン計算を意識せずに利用できるため分かりやすいですが、大量のデータを扱う際や開発を行う際には、トークン単価を意識したコスト最適化が不可欠です。

## Context Window とは

モデルが一度に「認識できる」最大トークン数のことです。これを「机の広さ」に例えると、ウィンドウが広いほど多くの参考資料を一度に広げて作業できますが、上限を超えた情報は古いものから順に「切り捨て」られてしまいます。

| モデルのタイプ | 一般的なウィンドウサイズ |
| --- | --- |
| 軽量・高速モデル | 8K 〜 32K トークン |
| 主流の高性能モデル | 128K 〜 200K トークン |
| 長文特化モデル | 1M（100万）トークン以上 |

## モデルの選び方

タスクの性質に合わせて、コストとパフォーマンスのバランスが良いモデルを選択しましょう。

| タスクの性質 | 適しているモデル |
| --- | --- |
| シンプルな Q&A、日常的な雑談 | 軽量で応答速度の速いモデル |
| 膨大な資料の分析、複雑な論理推論 | 高性能モデル ＋ 大容量のウィンドウ |
| プログラミング、デバッグ | コード生成に特化した専用モデル |
| 最新の情報に基づいた回答 | ブラウジング（検索）機能付きモデル |
| 大量のデータを安価に処理したい | 軽量モデル ＋ 構造化プロンプト |

## やってみよう

ChatGPT などのツールで、短い質問と、長い資料を添付した質問を交互に送り、応答が始まるまでの時間の違いを体感してみてください。また、「100 文字以内で簡潔に答えてください」といった指示を加えることで、出力トークン数を制御する感覚を掴むことができます。

## 実用的なチェックポイント

新しいツールやモデルを選ぶ際は、以下の 4 点をあらかじめ整理しておくとスムーズです。

1. このタスクを完遂するために、どの程度の情報量（コンテキスト）を読み込ませる必要があるか？
2. 「最強のモデル」が必要な難易度か、それとも「十分な性能」で足りるか？
3. 単発の作業か、それとも繰り返し実行する自動化タスクか？
4. 許容できるコストや予算はどの程度か？
