## まず一言で

RAG（Retrieval-Augmented Generation：検索拡張生成）とは、AI が回答を生成する前に、外部の知識ソースから関連する情報を取得（検索）し、それをコンテキスト（背景情報）として活用することで回答の精度を高める技術手法です。

RAG は単なる「検索機能」ではありません。従来の検索が「資料を見つけるだけ」なのに対し、RAG は「資料の適切な分割」「最適な検索」「コンテキストへの注入」「根拠に基づく生成」「回答の評価」という一連のプロセスを含んでいます。

## RAG が解決する課題

大規模言語モデル（LLM）の内部知識には学習時の「締め切り」があり、最新の情報や、非公開の社内文書、個人のメモ、独自のプロジェクト資料などを最初から知っているわけではありません。RAG は、こうした外部資料を「参考書」として一時的に AI の前に置くことで、専門的かつ最新の回答を可能にします。

**主な活用シーン：**
- 社内ナレッジベース（規定・マニュアル等）の Q&A
- 特定のドキュメントの読み込みアシスタント
- 膨大な講座資料や論文の横断検索
- 常に更新されるカスタマーサポート対応
- 出典（リファレンス）付きの調査・リサーチ業務

## RAG システムを構成する要素

| プロセス | 重要な問い |
| --- | --- |
| **資料の準備** | どの資料が信頼できるか、最新の状態に保たれているか |
| **チャンク分割** | どの程度の長さで区切ると、検索で見つけやすくなるか |
| **検索（Retrieval）** | 質問の意味に合致する「本当に必要な断片」を抽出できるか |
| **注入（Injection）** | 抽出した断片を、どのようにモデルに提示するか |
| **生成（Generation）** | 与えられた資料のみに基づき、正確に回答させる（Grounding） |
| **評価（Evaluation）** | 検索の漏れ、誤った引用、AI の「作り話」をどう検知するか |

RAG の難しさは、単にベクトルデータベースを接続することではありません。資料の品質管理、検索精度の設計、そして「正しく回答できているか」を測定する Eval（評価）が極めて重要になります。

## よくある誤解

1. **「RAG を入れれば回答は常に正しくなる」わけではない**：検索ステップで間違った（あるいは無関係な）資料を見つけてしまうと、回答も誤ったものになります。
2. **「すべての文書を一度に読み込ませる」わけではない**：AI のコンテキストウィンドウには限界があるため、必要な情報だけを賢く選別して渡す必要があります。
3. **「技術だけで解決できる」わけではない**：誰がどの情報にアクセスできるかといった、権限管理やガバナンスの設計も不可欠です。

## やってみよう：手動 RAG 体験

自分のメモやドキュメント（200 〜 500 文字程度）を ChatGPT や Claude に貼り付けて、以下のプロンプトを試してみてください。

```text
以下の【参照資料】の内容のみに基づいて、質問に答えてください。
資料に書かれていない情報は、自分の知識で補足せず「資料に記載がありません」と回答してください。

【参照資料】：
[あなたのメモを貼り付け]

質問：[このメモに関する具体的な質問]
```

AI が自分の知識を「封印」し、渡された資料のみに基づいて正確に答えるか観察してください。これが、RAG が目指す「根拠のある生成（Grounding）」の最もシンプルな形です。

## 実用的な見方

「知識連携 AI」を評価する際は、以下の 5 点をチェックしてください。

1. **ソースの透明性**：どの資料を検索対象としているか。
2. **鮮度**：資料はどの程度の頻度で更新・同期されているか。
3. **出典の明記**：回答のどこに、どの資料を引用したかのラベルがあるか。
4. **拒答能力**：情報が見つからないときに、素直に「わかりません」と言えるか。
5. **評価指標**：検索の精度と回答の品質を、開発側がどう定量化しているか。

これらの問いは、どのモデルを採用しているか以上に、システムの信頼性を左右します。
