## 先用一句话理解

**Token（标记）**是模型切分和处理文本的单位。它与字符、单词没有固定换算比例，具体取决于语言、文本与 tokenizer。估算时使用目标模型的计数工具或 API 用量记录。

## 计费模式解析

文本 API 常见做法是输入、输出分别计费，但缓存读写、工具、图像、音频可能使用其他计量单位或另收费用。应查看具体模型和渠道的价格表。

若单价按“每百万 token”给出，基本估算方法是：

> 任务费用 = 所有调用的（输入 token × 输入单价 + 输出 token × 输出单价）÷ 1,000,000 之和 + 工具、运行环境等费用

缓存部分按对应单价分开计算，不与普通输入重复计费；推理 token 等按所用接口规则处理。所有重试与 Agent 轮次都应计入。月费再按实测任务费用和预期任务量估算。这是费用结构说明，不是具体服务的报价。

聊天产品订阅与开发者 API 可能是不同的合同和账单。先确认包含的功能、用量上限和额外费用；API 实验先设置小额预算上限。

## 什么是上下文窗口（Context Window）

它是模型一次能处理的 token 数上限，可以类比为“工作桌面”。输入、历史对话、工具定义和输出预留如何占用窗口，需要查看对应 API 的规则。

超出上限可能报错，也可能由产品截断或摘要，不能假设一定自动删除最早的内容。轻量或旗舰的档位不能直接推导窗口大小与价格，应查看目标模型的规格。

| 检查项 | 看什么 |
| --- | --- |
| 输入是否装得下 | 实际 token 数与输出预留空间 |
| 长文能否正确利用 | 关键段落引用、原文核对和遗漏情况 |
| 费用与速度是否合适 | 实际用量、缓存条件和响应耗时 |

处理长文时比较全文、检索和摘要方案，实测准确性、费用与延迟。

## 如何选择合适的模型

针对不同的任务特点，应选择性价比最高的模型：

| 任务特点 | 推荐模型类型 |
| --- | --- |
| 简单问答、日常对话、翻译 | 轻量、响应极速的模型 |
| 深度文档分析、复杂逻辑推理 | 旗舰强模型 + 大上下文窗口 |
| 辅助编程、代码调试 | 在自己的代码与测试任务中表现合格的模型及工具 |
| 需要获取实时新闻或最新资讯 | 具备联网搜索能力的模型 |
| 高频、成本敏感的批量任务 | 轻量模型 + 结构化 Prompt 优化 |

## 动手实践

建议在 ChatGPT 或 Claude 中尝试以下对比：

1. 发送一个短问题，记录其响应速度。
2. 上传一份数千字的长文档并提问，观察响应延迟的变化。
3. 在 Prompt 中明确要求“请在 100 字内回答”，以此体会如何控制输出 token。

通过这些简单的实验，你能直观建立起对 token、响应速度和预期成本之间的关联感。

## 实用决策建议

在评估 AI 工具或选择模型时，可以参考以下四个维度进行决策：

1. **信息量**：任务执行中需要多少参考资料（上下文）？
2. **能力值**：是需要行业顶尖的推理能力，还是“够用就好”的通用能力？
3. **频率**：是一次性使用的任务，还是需要规模化反复运行的自动化流程？
4. **成本**：该任务对费用消耗是否敏感？

**原则：** 不选“最贵的”，只选“最合适的”。
