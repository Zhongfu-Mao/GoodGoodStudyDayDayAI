## なぜ AI にベクトルが必要か

AI モデルはテキストや画像を直接理解できません。すべてを数値の配列（ベクトル）に変換して処理します。重要なのは、**意味が近いものはベクトル空間で近くに配置される**ことです。

たとえば単語、文、画像、ユーザー行動、商品説明は、人間には別々の種類の情報に見えます。モデルはそれらを同じように「数値の並び」として扱います。ベクトル化できると、検索、推薦、分類、クラスタリングが同じ数学の上で扱えるようになります。

## ベクトル空間の直感

2 次元なら点は `(x, y)`、3 次元なら `(x, y, z)` で表せます。AI で使う embedding は数百から数千次元になることがありますが、考え方は同じです。各次元は人間が簡単に名付けられる軸ではないものの、似た意味のものが近くに来るように学習されています。

大切なのは、次元数が多いほど自動的によいわけではないことです。高次元の embedding は表現力が高い一方で、検索コスト、保存コスト、ノイズも増えます。

## コサイン類似度

$$
\cos(\theta) = \frac{a \cdot b}{\|a\| \|b\|}
$$

| 値 | 意味 |
| --- | --- |
| 1 | 方向が完全に一致（最も類似） |
| 0 | 直交（無関係） |
| -1 | 方向が完全に逆 |

コサイン類似度は長さを無視し、方向だけを見ます。

内積は、対応する要素を掛けて足したものです。コサイン類似度では、それを二つのベクトルの長さで割ります。これにより、「文書が長いから大きく見える」という影響を弱め、方向の近さを見ます。

## なぜコサインか

高次元空間ではユークリッド距離の識別力が低下します（次元の呪い）。コサイン類似度は長さを正規化するため、高次元でも安定します。

ただし、すべての問題にコサインが最適という意味ではありません。絶対的な量が重要な異常検知や物理測定では、ユークリッド距離や別の距離指標が合う場合があります。テキストや semantic search では、方向が意味を持つことが多いためコサインがよく使われます。

## 実用例

- **セマンティック検索**：クエリとドキュメントをベクトル化し、コサイン類似度で最も関連するものを返す（RAG の検索段階）。
- **レコメンド**：ユーザーとアイテムのベクトル類似度で推薦。
- **重複検出**：2 つの記事のベクトル類似度が閾値を超えたら重複候補。
- **クラスタリング**：似た文書やユーザーを近い group にまとめる。

## Python 例

```python
import numpy as np

def cosine_similarity(a, b):
    return np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b))

v1 = np.array([1, 2, 3])
v2 = np.array([2, 4, 6])  # 同じ方向
v3 = np.array([3, -1, 0]) # 異なる方向

print(cosine_similarity(v1, v2))  # 1.0
print(cosine_similarity(v1, v3))  # ≈ 0.08
```

## 実務で見るポイント

- embedding model が変わると、同じ文書でもベクトル空間が変わる。
- 類似度閾値は一律に決めず、実データで分布を見て調整する。
- 短い query は情報量が少ないため、metadata や keyword search と組み合わせる。
- 「似ている」と「答えに必要」は違う。RAG では rerank と grounding が重要になる。
