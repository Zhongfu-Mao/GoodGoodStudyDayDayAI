# 为什么"数据思维"比你以为的重要得多

大多数人把"数据清洗"理解成数据科学家的活：处理缺失值、编码、标准化——跟自己的日常工作没什么关系。

但仔细想想你每天在做什么：

- 写 Prompt 时，你在决定给模型"喂"什么信息
- 搭 RAG 知识库时，你在筛选哪些文档值得被检索
- 做评测时，你在判断什么样的输出算"好"
- 读 AI 雷达时，你在从噪声里提取信号

**这些全部都是数据质量判断。** 数据思维不是写 Python 脚本，而是养成一个习惯：在任何 AI 任务开始前，先审视"我喂进去的东西到底行不行"。

## 三个改变认知的数据原则

### 原则一：清洗不是"做完就完了"，而是"永远在迭代"

很多人以为数据清洗是一次性的——先把数据弄干净，再开始做模型。实际上，你在用 AI 的过程中一直在迭代数据：

- Prompt 不好用 → 你把背景信息写得更清楚了（这是在清洗"指令数据"）
- RAG 检索不准 → 你把知识库里的冗余文档删掉了（这是在清洗"上下文数据"）
- 模型输出不稳定 → 你加了输出格式约束（这是在清洗"输出数据"）

把这些操作识别为"数据工作"，你就知道它们是持续性的，不是一次性的。

### 原则二：数据质量问题的根因通常在"上游"

| 你看到的问题 | 你可能的第一反应 | 真正的根因（数据视角） |
| --- | --- | --- |
| RAG 回答不相关 | 调 Prompt | 检索回来的文档本身和问题就不匹配——向量层的问题 |
| 模型输出格式不一致 | 加更多约束 | 你的示例太少或者示例之间有矛盾 |
| 评测分数很好看但上线效果差 | 怀疑评测方法 | 评测数据太"干净"了，不能代表真实用户输入 |
| Agent 执行到一半就跑偏 | 换更强的模型 | 中间步骤的工具返回数据格式不一致，模型被带歪 |

这个思维切换很关键：**不要只在模型层面找问题，往上追一层，看数据。**

### 原则三：好数据 ≠ 干净的数据，而是"能代表真实场景"的数据

教科书式的数据清洗（去除异常值、填缺失值、标准化）会让你得到一个"漂亮"的数据集。但真实用户不会给你干净的数据。他们会打错字、用缩写、提模糊问题、贴一大段乱七八糟的日志。

如果你的 Prompt 只在"干净"的测试输入上效果好，遇到真实用户就会翻车。**评测数据必须包含噪声、边缘情况和脏输入**——不是因为你懒得清洗，而是因为真实世界就是脏的。

## 认知升级：把数据思维用到日常 AI 使用中

**1. 写 Prompt 之前，先审视"输入数据"**

你准备给模型的文字、文件、对话历史——这些东西有多干净？有没有互相矛盾的信息？有没有模型不需要知道的噪音？用 30 秒做一次"输入审查"，比事后改 Prompt 高效得多。

**2. 搭知识库时，别只堆文档**

知识库的价值不在文档数量，在信息密度。一篇高质量、结构清晰的文档，比十篇互相重复的碎片值得多。建议定期做"知识库健康度检查"：随机抽 20 个查询，看检索结果的相似度分布。大量文档相似度在 0.3 以下？你的知识库缺这块内容。全都挤在 0.9 以上？可能重复太多了。

**3. 把"数据日志"变成习惯**

遇到一次模型表现异常，不要只调完 Prompt 就完了。记录三件事：输入了什么、期望输出什么、实际输出了什么。攒够 20 条，你就有了一份最小可行的评测数据集。这是从"凭感觉用 AI"走向"工程化用 AI"的分水岭。

## 动手实践：给你的一个 AI 任务做一次"数据审查"

挑一个你经常用 AI 做的任务，花 15 分钟做以下检查：

1. **输入审查**：你最近 5 次给模型的输入里，有多少是不必要的信息？有没有互相矛盾的地方？
2. **输出模式分析**：模型输出不好的 3 次里，是输入质量的问题还是模型能力的问题？
3. **做一个"脏输入测试"**：刻意给模型一个包含错别字、缩写、格式混乱的输入，看它的表现下降多少
4. **记录一条数据日志**：按"输入 → 期望输出 → 实际输出 → 数据质量判断"的格式记录下来

做完这 15 分钟，你已经比 90% 的 AI 用户多了一层"数据视角"。

## 数据清洗核心操作速查

如果你确实需要写代码处理数据，以下是最常用的操作（不需要背，用到时回来查即可）：

**缺失值处理**：数值用中位数填充（不改变分布中位数），类别用 `unknown` 标记（保留"未知"这个信息本身），时间序列用前向填充（假设连续性）。

**类别编码**：有序类别（低/中/高）用整数 0/1/2，无序类别（红/蓝/绿）用 One-Hot，高基数类别（几千个值）用 Target Encoding 或 Embedding。

**标准化**：大多数场景用 StandardScaler（使数据均值为 0、方差为 1），有异常值时用 RobustScaler（用中位数和四分位距代替均值和标准差）。

**异常值**：先画箱线图看分布。IQR 法（Q1 - 1.5×IQR / Q3 + 1.5×IQR）适合快速筛选，Z-score |z| > 3 适合正态分布数据。不建议直接删除——先确认这个"异常"是不是你真正关心的信号（如欺诈检测中，异常 = 目标）。
