## なぜデータクリーニングがモデル選択より重要か

ゴミを入れればゴミが出る。実務ではデータクリーニングと特徴量エンジニアリングが全体の 60〜80% の時間を占めます。

モデルを替える前に、まず入力データが何を表しているかを確認します。欠損、重複、外れ値、単位の違い、入力ルールの変更、ラベルの揺れは、モデルから見るとすべて学習対象です。データが壊れていれば、強いモデルほどその壊れ方をうまく覚えてしまいます。

## 欠損値の処理

| 戦略 | 適用場面 | 注意点 |
| --- | --- | --- |
| 行削除 | 欠損率が低い、データ量が十分 | バイアスの可能性 |
| 平均値／中央値で補完 | 数値特徴、正規分布に近い | 分散が低下 |
| 最頻値で補完 | カテゴリ特徴 | 単純だが不正確な場合あり |
| 前方／後方補完 | 時系列データ | 隣接値の相関を仮定 |
| 独立カテゴリとして扱う | 欠損に業務的意味がある | ドメイン知識が必要 |

```python
import pandas as pd

df['price'] = df['price'].fillna(df['price'].median())
df['category'] = df['category'].fillna('unknown')
```

欠損は単なる空欄ではありません。入力されなかったこと自体が意味を持つ場合があります。たとえば「任意項目が空」は、ユーザーの関心や手続きの段階を示す signal かもしれません。

## カテゴリ特徴のエンコーディング

| 手法 | 適用 | 出力 |
| --- | --- | --- |
| Label Encoding | 順序あり（低/中/高） | 整数 |
| One-Hot Encoding | 順序なし、カテゴリ数が少ない | 0/1 ベクトル |
| Target Encoding | 高カーディナリティ | 目的変数の平均 |
| Embedding | 超高カーディナリティ、深層学習 | 低次元稠密ベクトル |

```python
df_encoded = pd.get_dummies(df, columns=['color'], prefix='color')
```

カテゴリが多すぎると one-hot は列数を増やしすぎます。高カーディナリティの特徴では、target encoding や embedding を検討します。ただし target encoding は leakage を起こしやすいので、train/test の分割後に慎重に適用します。

## 標準化

| 手法 | 適用 |
| --- | --- |
| StandardScaler | 大半のケース |
| MinMaxScaler | 0〜1 の範囲が必要な場合 |
| RobustScaler | 外れ値がある場合 |

標準化が必要かどうかは model によって異なります。線形モデル、SVM、k-NN、ニューラルネットは尺度の影響を受けやすい。一方、決定木系の model は比較的影響を受けにくい。前処理は「いつも全部やる」ではなく、model と feature の性質に合わせます。

## 外れ値の扱い

- IQR：Q1 - 1.5×IQR より小さい、または Q3 + 1.5×IQR より大きい値。
- Z-score：平均から大きく離れた値。
- 可視化：box plot、scatter plot、時系列 plot。

外れ値は必ず削除するものではありません。不正検知、障害検知、売上急増のように、外れ値そのものが一番重要な signal になることもあります。

## 特徴量選択

不要な特徴量はノイズ・訓練時間増加・過学習の原因になります。相関分析、分散フィルタ、特徴量重要度、L1 正則化で絞り込みます。

特徴量選択では、削る理由を残すことが大切です。あとからモデルが悪化したとき、「どの特徴量をなぜ捨てたか」が分からないと戻せません。小さな notebook でも、削除候補、理由、判断日をメモしておくと再現性が上がります。

## 実務チェックリスト

- train/test split の前に leakage を起こす処理をしていないか。
- 日付、通貨、単位、timezone が揃っているか。
- 欠損値が「本当に欠損」なのか、業務上の signal なのか。
- 外れ値を削除する前に業務イベントと照合したか。
- 前処理 pipeline が推論時にも同じ順序で再現されるか。
