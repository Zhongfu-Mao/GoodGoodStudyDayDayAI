## なぜデータクリーニングがモデル選択より重要か

業界の格言に「ゴミを入れればゴミが出る」（Garbage In, Garbage Out, GIGO）という言葉があります。実務において、データクリーニングと特徴量エンジニアリングは全工程の 60〜80% を占めると言われています。

モデルを替える前に、まず入力データが何を表しているかを確認することが不可欠です。欠損、重複、外れ値、単位の不一致、入力ルールの変更、表記揺れなどは、モデルから見ればすべて学習対象となります。高性能なモデルほど、そのデータの歪みまで忠実に学習してしまうため、クリーンなデータの提供が最優先されます。

## 欠損値の処理

| 戦略 | 適用場面 | 注意点 |
| --- | --- | --- |
| 行削除 | 欠損率が極めて低く、データ量が十分な場合 | バイアスが生じる可能性 |
| 平均値／中央値補完 | 数値特徴で分布が正規分布に近い場合 | データの分散が低下する |
| 最頻値補完 | カテゴリ特徴の場合 | シンプルだが不正確になるリスクあり |
| 前方／後方補完 | 時系列データの場合 | 隣接値に相関があると仮定 |
| 独立カテゴリ化 | 欠損自体に業務的な意味がある場合 | ドメイン知識による判断が必要 |

```python
import pandas as pd

# 数値列を中央値で補完
df['price'] = df['price'].fillna(df['price'].median())

# カテゴリ列を 'unknown' で補完
df['category'] = df['category'].fillna('unknown')
```

欠損は単なる空欄ではありません。入力されなかったこと自体が重要な信号（signal）である場合があります。例えば「任意項目が空」であることは、ユーザーの関心度や手続きの段階を示唆しているかもしれません。

## カテゴリ特徴のエンコーディング

モデルはテキストを直接処理できないため、適切なエンコーディングが必要です。

| 手法 | 適用対象 | 出力形式 |
| --- | --- | --- |
| Label Encoding | 順序性のあるカテゴリ（例：低/中/高） | 整数 |
| One-Hot Encoding | 順序性のないカテゴリ（種類が少ない場合） | 0/1 ベクトル |
| Target Encoding | 高カーディナリティ（カテゴリ数が多い）な特徴 | 目的変数の平均値 |
| Embedding | 超高カーディナリティ、深層学習 | 低次元の稠密ベクトル |

```python
# One-Hot Encoding の例
df_encoded = pd.get_dummies(df, columns=['color'], prefix='color')
```

カテゴリが多すぎる場合に One-Hot を使うと、列数が膨大になり計算効率が悪化します。その場合は Target Encoding や Embedding を検討しますが、Target Encoding はリーク（leakage）を起こしやすいため、慎重な適用が必要です。

## 標準化

特徴量ごとに尺度が大きく異なる場合、モデルの学習を安定させるために標準化を行います。

| 手法 | 適用シナリオ |
| --- | --- |
| StandardScaler | 大半の一般的なケース（平均0、分散1） |
| MinMaxScaler | 0〜1 の範囲に収めたい場合 |
| RobustScaler | 外れ値の影響を抑えたい場合 |

標準化の必要性はモデルにより異なります。線形モデル、SVM、k-NN、ニューラルネットワークは尺度の影響を強く受けますが、決定木系モデルは比較的影響を受けにくい特性があります。

## 外れ値の扱い

- **IQR法**：第1四分位数（Q1）- 1.5×IQR 以下、または第3四分位数（Q3）+ 1.5×IQR 以上の値を外れ値とみなす。
- **Z-score**：平均から標準偏差の3倍以上離れた値を抽出。
- **可視化**：箱ひげ図（Box plot）や散布図（Scatter plot）での確認が効果的。

外れ値は必ずしも削除すべきものではありません。不正検知や故障予兆検知のように、外れ値そのものが最も重要な信号となるケースも存在します。

## 特徴量選択

不要な特徴量はノイズとなり、訓練時間の増加や過学習（Overfitting）の原因となります。

1. **相関分析**：目的変数との相関が極めて低い特徴量を削除。
2. **分散フィルタ**：値がほとんど変化しない（分散がゼロに近い）特徴量を削除。
3. **特徴量重要度**：Random Forest や XGBoost 等のモデルが出力する重要度に基づいて選別。
4. **正則化**：L1正則化（Lasso）を用いて、不要な特徴量の重みをゼロにする。

## 実務チェックリスト

- Train/Test 分割の前にリーク（leakage）を起こす処理を行っていないか。
- 日付、通貨、単位、タイムゾーンは統一されているか。
- 欠損値は「入力漏れ」か、それとも「意味のある欠損」か。
- 外れ値を削除する前に、その背景にある業務イベントを確認したか。
- 前処理パイプラインが、推論時にも同一の順序で再現可能か。
