# Good Good Study, Day Day AI

以 Astro 构建的个人 AI 学习与研究博客。  
Astro で構築した、個人の AI 学習・研究ブログです。

站点地址 / サイト:
<https://zhongfu-mao.github.io/GoodGoodStudyDayDayAI/>

## 项目简介 / プロジェクト概要

**中文**

这个项目面向两个核心目标：

- 持续记录 AI 领域的重要变化
- 系统沉淀学习笔记、工程实践与基础知识

整体采用 Markdown First 的方式写作，文章是核心资产，页面、标签、归档、音频和其他衍生内容都围绕 Markdown 组织。

**日本語**

このプロジェクトの目的は次の二つです。

- AI 分野の重要な変化を継続的に記録すること
- 学習ノート、実装メモ、基礎知識を体系的に蓄積すること

全体は Markdown First で運用しており、記事そのものを中心資産として、ページ、タグ、アーカイブ、音声などの派生物を組み立てています。

## 内容结构 / コンテンツ構成

所有内容位于 `src/content/` 下的四个主目录。  
すべてのコンテンツは `src/content/` 以下の 4 つの主要ディレクトリに配置しています。

### 1. `radar/`

**中文**

用于记录 AI 资讯、工具更新、研究动态和行业信号，是站点更新最频繁的部分。

- `日报`：聚焦最近 24 到 72 小时内值得记录的信号，强调快速扫描与短周期整理
- `周报`：把一周内的重要信息重新归纳成更稳定的主题，强调关联、筛选与总结
- `月报`：从更长时间尺度回看当月趋势，强调主线判断、结构变化与阶段性结论

可以把三者理解为：

- 日报负责“记录发生了什么”
- 周报负责“整理哪些变化值得持续关注”
- 月报负责“判断这个月真正形成了什么趋势”

**日本語**

AI ニュース、ツール更新、研究動向、業界シグナルを記録する領域で、サイトの中でもっとも更新頻度が高い部分です。

- `日報`：直近 24〜72 時間の重要シグナルを素早く記録する
- `週報`：1 週間分の動きをまとめ直し、重要テーマを再整理する
- `月報`：1 か月単位で流れを振り返り、主要トレンドと構造変化を判断する

役割を簡単に言えば、

- 日報は「何が起きたか」を記録する
- 週報は「何を追い続けるべきか」を整理する
- 月報は「どんな流れが本当に立ち上がったか」を判断する

### 2. `academy/`

**中文**

用于沉淀系统化学习笔记。这里更强调“课程式”或“主题式”的结构，不追求资讯速度，而追求可复读、可回顾、可串联。

**日本語**

体系的な学習ノートを蓄積する領域です。速報性よりも、再読しやすさ、振り返りやすさ、学習経路としてのつながりを重視しています。

### 3. `engineering/`

**中文**

用于记录开发实践、工具使用、基础设施和工作流相关内容，更偏向“怎么做”。

**日本語**

開発実践、ツール活用、インフラ、ワークフローに関する内容をまとめる領域で、「どう実装するか」を中心に扱います。

### 4. `foundations/`

**中文**

用于整理数学、数据、模型结构等基础主题，更偏向“为什么会这样”。

**日本語**

数学、データ、モデル構造などの基礎テーマを整理する領域で、「なぜそうなるのか」を重視します。

## 内容组织与生成逻辑 / コンテンツの編成と生成ロジック

**中文**

当前的组织逻辑大致是：

1. 先用 Markdown 写出原始内容
2. 通过 frontmatter 为文章补充日期、分类、标签、语言、封面、音频等元数据
3. 前端根据这些元数据生成文章页、分类页、标签页、归档与语言切换
4. 对 Radar 内容，再按“日报 -> 周报 -> 月报”的节奏逐步聚合

其中 `Radar` 的生成逻辑可以理解为：

- `日报` 是最小记录单元，先把当天或最近两三天内值得留档的信号写下来
- `周报` 不是简单拼接日报，而是重新提炼一周的主题、线索和代表性案例
- `月报` 则进一步拉开时间尺度，对一个月内的主线变化做二次判断

也就是说，这个项目不是把同样的内容重复写三遍，而是在不同时间粒度下，对信息做不同层次的组织。

**日本語**

現在の編成ロジックはおおむね次の通りです。

1. まず Markdown で原稿を書く
2. frontmatter で日付、分類、タグ、言語、カバー画像、音声などのメタデータを付与する
3. フロントエンド側で記事ページ、分類ページ、タグページ、アーカイブ、言語切替を生成する
4. Radar 系コンテンツは「日報 -> 週報 -> 月報」の粒度で再編成する

`Radar` の流れをもう少し具体的に言うと、

- `日報` は最小の記録単位
- `週報` は日報の単純結合ではなく、1 週間のテーマと流れを再整理したもの
- `月報` はさらに長い時間軸から、その月に何が主要トレンドだったかを判断したもの

つまり、同じ情報を重複して並べるのではなく、時間粒度ごとに役割を変えて再構成しています。

## 浏览统计 / Analytics

站点支持静态部署下的隐私友好浏览统计。默认没有配置时不会注入任何第三方脚本；需要统计时，在 GitHub 仓库的 Actions variables 中配置以下变量后重新部署。

このサイトは静的デプロイ向けの軽量 analytics に対応しています。未設定の場合、第三者の計測スクリプトは出力されません。利用する場合は GitHub の Actions variables に次の値を設定して再デプロイします。

推荐优先使用 Cloudflare Web Analytics：

```text
PUBLIC_ANALYTICS_PROVIDER=cloudflare
PUBLIC_CLOUDFLARE_WEB_ANALYTICS_TOKEN=你的 Cloudflare Web Analytics token
```

也可以切换到 Plausible：

```text
PUBLIC_ANALYTICS_PROVIDER=plausible
PUBLIC_PLAUSIBLE_DOMAIN=zhongfu-mao.github.io
PUBLIC_PLAUSIBLE_SCRIPT_SRC=https://plausible.io/js/script.js
```

或 Umami：

```text
PUBLIC_ANALYTICS_PROVIDER=umami
PUBLIC_UMAMI_WEBSITE_ID=你的 Umami website id
PUBLIC_UMAMI_SCRIPT_SRC=https://cloud.umami.is/script.js
```
