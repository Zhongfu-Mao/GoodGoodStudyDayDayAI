# 日报正文配图

正文配图与顶部信息图分别承担局部解释和全篇总览的作用。2026-10-09 的中日试排已获用户认可：具体条目旁放原始图片，并附读图讲解。常规日报以 **3–5 张条目配图**为编辑目标，分布在不同栏目；顶部信息图和开头代表图不计入这个数量。不能用重复封面、logo、宣传海报或与条目无关的图片凑数。

## 采编与选图

1. 读原文时同时记录候选图片、出处、所在条目和能帮助读者理解的关系。选题冻结时一并形成配图计划。
2. 优先原文的流程图、架构图、实验图表、产品实拍或实际界面。摘要中的数字、箭头、界面状态必须与图片对应；图表保留坐标、图例、测试条件和限定语。
3. 抓取 HTML 仍用 `scripts/radar/fetch-url.mjs` 并复用缓存。页面里的第一张图或 `og:image` 只是候选，不自动成为条目配图。抓取失败按主工作流的浏览器复核规则处理。
4. 历史回补不得把当前产品界面当成旧版本，也不得以仓库今天的 README 为当时的能力证明。优先对应日期的文章原图、可确认版本的素材；无法核实则换条目或制作明确标注的解释图。新增事实需要单独核实，不能通过图注悄悄改写原新闻。
5. 原始图不适合时，可按文章配图 skill 制作解释图，注明为示意图；生成、事实核对、视觉验收缺一不可。不得伪造产品截图或官方图表。

## 图注与双语

- 每张图必须有描述性 alt、原文来源链接和一至两句讲解：告诉读者看哪里、如何理解组件/步骤/对比，必要时说明局限。只写“某某配图”不算讲解。
- 中日版配同一条目、同一原图及同一解释语义。原图的英文标签可保留；alt 与讲解须本地化。生成式带文字图按语言分别制作和验收。
- 图放在对应条目摘要之后；允许点击查看原尺寸。复杂原图在手机上以图注承载关键关系，不把缩小后的细字当成可读内容。
- 外链图片在下载、验收后压缩为本地 WebP，保留出处和校验和。动画可选取能说明机制的静帧并明确标注；不能把文件变小等同于画面可用。
- 新图片交付及历史图片迁移遵守 [R2 约束](../r2-cost-guardrails.md)。本地验收不等于公开 URL 已可用。

## 可续跑清单与检查

每期采用 `scripts/radar/visuals/YYYY-MM-DD.json` 清单（version 1），列出每张图的 `id`、`sourceUrl`、`originalImageUrl`、`asset`、`sha256`、`credit`、`review`，以及 `zh` / `ja` 的精确 `heading`、`alt`、`caption`。`review: accepted` 只能在事实与实际图像检查通过后写入，模型建议或下载成功不能直接升级为验收通过。内部抓取日志、拒绝原因和生成草稿存入忽略的 `tmp/` / `.cache/`。

```sh
node scripts/radar/inline-visuals.mjs --date YYYY-MM-DD
node scripts/radar/inline-visuals.mjs --date YYYY-MM-DD --apply
npm run check:radar-visuals
```

默认 dry-run。应用前检查两种语言全部定位和图片校验和；任一失败则整批不写。已管理图块可幂等更新；遇到条目已有未管理图片，先人工检查，不覆盖。少于三张时必须记录具体的编辑例外；例外不是批量跳过验收的通道。每期完成状态以正文实际包含清单中的图块为准。

发布前还须按根目录要求执行 GitHub Pages base path 的构建和相关 UI 检查，目视查看桌面和手机效果，核实图像加载、链接、双语对应和无图片溢出。流程/脚本修改与历史回补的推送不自动适用本期日报发布例外。
